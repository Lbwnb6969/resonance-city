## 0. 这份规格要解决的一个矛盾

旧稿把三件事混写成一件，导致玩家听到的和系统算的对不上：

| 层 | 是什么 | 谁在用 |
|---|---|---|
| **规则耦合层** | `c(i,j)`：两个建筑"算不算有关系"、关系多强 | R/V、生长、命名形态、地标觉醒 |
| **声学传播层** | 声音在两点之间如何被地形衰减 / 滤波 / 延迟 | 环境层、对唱、湖面、林地 |
| **实际混音层** | PCM 里真正能被听到的拍频、掩蔽、响度 | 玩家耳朵、混音验收 |

**裁定：`c = 0` 只表示"不参与规则结算"，不表示"听不见"。**

隔着河的 C3 与 C♯3 建筑，规则上不产生耦合边（不进入 R），但若两者都在全城混音里以 drone 持续发声，
PCM 里仍然有 7.8 Hz 的拍频——这是物理事实，删一条规则边不能消除它。

因此：**任何"听感"的断言必须以混音层为准，不能以规则层为准。**
AUDIO-009 定义两者如何拉平（区域监听 / 编曲隔离），这是本规格与 spec.audio 的共同责任。

## 表 SP2 · 耦合系数（取代旧权重 w）

```
c(i,j) = A(d) × O(i,j) × T(i,j) × I(i,j) × M(i,j)        c ≥ 0
```

**乘算顺序是规格的一部分**（不是实现细节）：先算 `A`（A 自身封顶 2.0），再依次乘 `O`、`T`、`I`、`M`。

| 项 | 定义 |
|---|---|
| `d` | 中心距离 − `r_i` − `r_j`（间隙距离，可为负） |
| **A(d)** 距离衰减 | `d ≤ 0` → **2.0**；`0 < d ≤ 4` → `2.0 × exp(−(d/σ)²)`；`d > 4` → **0** |
| **σ** | 基础 1.8；地形倍率见下 |
| `O` 遮挡 | 无阻挡 1.0；部分（林地 / 矮墙）0.7；完全（山脊 / 成路街道）**0** |
| `T` 地形调制 | 平原 1.0；跨水面 **1.15**；跨林地 **0.85**；同地形按表 SP7 |
| `I` 工业系数 | 任一方为工业 → **1.3**，否则 1.0 |
| `M` 音乐性 | 表 SP4；默认 1.0 |

**σ 的地形倍率必须对称**：取两端传播 σ 的**最大值**：

```
σ(i,j) = σ_base × max( f(i), f(j) )
  f = 1 + h/8     山上传声远（h 为建筑海拔，单位地块）
  f = 0.85        河谷聚声
  f = 1.15        海岸开阔
```

max 而非平均，保证 `c(i,j) = c(j,i)`；**任一端放宽即整条边放宽**（山上的钟声真的传得远），这是设计意图。

### 2.1 数值范围（修正旧稿的封顶声明）

**`c` 没有统一上限。** 旧稿写 `c ∈ [0, 2.0]`，与同段的"平原工业最大 2.6"自相矛盾，两者都不完整：

| 情形 | c 的最大值 |
|---|---|
| 平原，非工业 | **2.00** |
| 平原，任一端工业 | **2.60** |
| 跨水面（有桥）+ 工业 | **2.99** |
| 跨水面 + 工业 + 山上传声 | **2.99**（`A` 已封顶；σ 只改变"多远算近"，不改变贴合的峰值） |

规格口径：**`A ≤ 2.0` 单独成立；`c` 的上界为 2.99，不另设封顶。**
任何测试、配置文件或文档不得写"c 封顶 2.0 / 2.6"。

### 2.2 A(d) 参考表

`σ = 1.8`。**这些值由公式派生**（`2.0×exp(−(d/1.8)²)`），不是独立常数；公式与表不符时以公式为准并改表。

| d（间隙，地块） | A |
|---|---|
| ≤ 0 | 2.000000000000 |
| 0.5 | 1.851482531849 |
| 1.0 | 1.468887343859 |
| 1.5 | 0.998703577199 |
| 2.0 | 0.581920917729 |
| 2.5 | 0.290583251091 |
| 3.0 | 0.124353048044 |
| 3.5 | 0.045605953263 |
| 4.0 | 0.014333950075（**保留**；只有 d > 4 才截断） |
| > 4.0 | 0 |

### 2.3 截断处的连续性（回答"连续变化 vs 硬截断"）

旧稿同时宣称"c 是连续函数"和"d > 4 硬截断"，没有说明这对矛盾如何共存。裁定：

- **距离核本身连续**：`d` 从 0 增到 4，`A` 从 2.0 平滑降到 0.0143。玩家挪动建筑 0.3 地块，R 连续变化——"柔和直觉"的数学基础**成立**。
- **截断点有 0.72% 的不连续**：`A(4.0) = 0.0143` 占峰值 `A(0) = 2.0` 的 0.72%。下述构造在R上影响约0.71个百分点，**不是普遍上界**（构造：一对紧贴同音 `c=2.0, s=1.0`，加上一对边界三全音 `c=0.0143, s=0.0` → R = 99.288；该对越界后 R = 100）。
- **保留硬截断**（这是 SPACE-001 反例的基础，但单条孤立失谐边消失可使R由0跳到无边默认100，不能把该构造推广为全部布局的感知保证）。**但不得再宣称"c 处处连续"**——正确表述是"**c 在 `0 < d < 4` 上连续，在 `d = 4` 处幅值已衰减到峰值的 0.72%，截断仍不连续，界面可平滑展示但结算不改值**"。
- **截断对称**：截断基于 `d`（间隙距离），`d` 对称，故 `c(i,j) = c(j,i)` 天然成立，不需要额外规则。

## 表 SP3 · 谐振度 R（形状不变，权重分层）

```
R = 100 × Σ_k ( W_k × ( Σ_{i,j∈k} c_ij·s_ij ) / ( Σ_{i,j∈k} c_ij ) )
其中 W_k = ( Σ_{i,j∈k} c_ij ) / ( Σ_all c_ij )        Σ_k W_k = 1
```

即：**先按社区算加权平均，再按社区耦合总量加权。**

| 项 | 规则 |
|---|---|
| `s_ij` | 取自 spec.harmony.md 表 B（**不变**） |
| 结算频率 | 每乐句边界（16 秒）重算一次，纯函数，不保留历史 |
| 无配对 | `R = 100`（保留旧裁定） |
| 浮点容差 | **1e-6** |
| 无向对计数 | 每条无向对只计一次 |
| 退化情形 | 全城只有一个社区 → 退化为全城加权平均（与旧公式一致） |
| 跨社区对 | c为对称边权，两端无大小之分；跨社区边按稳定社区ID字典序归桶，每条无向边恰好一次 |

**分层用途**：社区桶用于输出局部R与定位，但W取耦合总量时，上式代数上严格等于全城加权平均，不能宣称它消除了局部问题稀释。局部锈蚀由独立社区指标处理，不暗改全城R公式。

**R 的职责边界**：R 是**布局的和谐度指标**，不是"好不好听"的指标。好听由编曲（spec.audio 表 A20–A22）负责。
除崩盘阈值外，**没有任何跨章条件、缺口、奖励以 R 为唯一判据**——这是"提高 R 不是唯一策略"的制度保证（见 spec.run 表 R7）。

**V 活力公式不变**（见 spec.harmony.md 表 H1），但增加音乐性上限修正（表 SP4）。

## 表 SP4 · 音乐性权重 M

**问题**：同度最优（`s = 1.00`，`ΔV = +8`）使"全城调成 C"成为数值最优。旧稿用"全城同音会触发缺应答缺口"来反对它，
但那是**间接**的，且可被其他缺口收益抵消。

**裁定：给多样性一个直接、可计算、不惩罚的方式。**

对任一建筑 `i`，令 `k = i 的 current_midi`，定义**音级占据率**

```
c0 = A × O × T × I
occ(i) = Σ_{j ∈ N₁₂(i), midi_j = k} c0_ij / Σ_{j ∈ N₁₂(i)} c0_ij
无邻居时occ = 0；M(i,j) = min(M(i), M(j))；c = c0 × M(i,j)
```

| occ(i) | M(i) | 对 i 的联动效果 |
|---|---|---|
| ≤ 0.40 | 1.0 | — |
| > 0.40 | **0.7** | 任一端超阈值时该边c乘0.7，仅乘一次；i自身每条ΔV_pair（含负数）乘0.5并按0.5取整，基础生长/衰减/动作成本不减半 |

**性质（这是它成立的原因）**：

- **按邻近度计算，不是全城统计**。全城有 5 个 C 社区但各自都与其他音级混居时，`occ` 都低，无影响。
- **是乘法而非减法**：混入不同音级使 `occ` 回落；仅当 `occ ≤0.40` 时，`M` 回到 1.0，**立即恢复**，不累积、不停留、不需补救动作。
- **不封顶城市规模**：一个纯 C 的小镇可以照常长大，只是同音新建筑的和声收益减半——这就是"同音最优"被拆掉的机制。
- **对R的实际作用**：混合音级图中改变相对边权；全同音时所有边等比缩放，R仍为100，不能宣称M直接奖励全城R多样性。同音收益减半与配器目标共同承担多样性激励，是否好玩需试玩。

**上限**：`occ` 阈值 0.40、`M` 值 0.7、`ΔV` 减半系数 0.5 —— 这三个数是设计值，**需实测调参**（P1 音频切片），不得由执行 AI 私自改动。

**与缺口的分工**：M 是**布局层的连续性激励**（随时生效、无 UI、无提示）；
缺口系统是**音乐层的创作机会**（乐句边界结算、有听觉先行提示）。两者不可互相替代，
M 不得做成"缺口提示"，缺口不得做成"惩罚"。

## 表 SP5 · 两个邻居集合（更正旧的"4–9 邻居"）

旧稿写"典型邻居数 4–9"，同时又写"密集方阵可有 68 个邻居"，两句都低估了。

**平地、无遮挡、M=1 的几何计数**（`r = 0.45`，`d ≤ 4.0` 判定，Python 精确计算；实际地形与遮挡会减少有效边）：

| 排布 | 间距 | `c > 0` 的邻居数 | `c ≥ 0.10`（d ≤ 3.115） |
|---|---|---|---|
| 六方最密堆积 | 0.90 | **108** | **72** |
| 六方堆积 | 1.00 | 84 | 60 |
| 六方堆积 | 1.20 | 60 | 36 |
| 方格 | 1.00 | 68 | 48 |
| 方格 | 1.20 | 48 | 36 |

**因此把邻居分成两个集合，各有各的用途：**

| 集合 | 定义 | 用途 | 规模 |
|---|---|---|---|
| **全对集合** `E` | 所有 `c > 0` 的无向对 | R 的分子分母、V 的 ΔV 求和 | 密集区每栋可达 108 |
| **近邻集合** `N₁₂(i)` | 按未乘M的基础边权 `c0` 降序取 `i` 的**前12个**邻居（同权按稳定实体ID排序）（不足则全部） | 生长判据、阶段升级、碴冻结、`occ` 计算、M | ≤ 12 |

**为什么必须分开**：若阶段升级与碴冻结用全对集合，密集区每栋建筑会有 70+ 个邻居，
"≥2 邻居 s ≥ 0.85"和"任一邻居 s ≤ 0.05"两边都极易命中——
**结果是密集区所有建筑同时冻结、同时不再升级，城市在密集处停止生长**。这是旧稿里一个隐藏的致命问题。

**裁定**：

- 表 E-grow 的全部阶段与生长判据 → 一律用 `N₁₂(i)`
- 碴冻结 → 只在 `N₁₂(i)` 内判定；`N₁₂` 之外的三全音邻居**不冻结**（远景，听不清）
- `occ`（表 SP4）→ 用基础边权c0选出的 `N₁₂(i)`
- R 与 V 的 ΔV → 用 `E`（全对，保留旧语义，不因密度改变定义）

**性能**：空间索引必须支持"取前 12 个最强邻居"的查询（四叉树 + 有界堆，或按距离分环取）。
**禁止**每次生长全城两两重算（19 §4 已禁止）。

## 表 SP6 · 社区：稳定规划社区（取代"同家族声学连通群"）

旧稿在三处给了三种定义，必须收敛。**以 19 §2③ 的稳定规划社区为唯一定义。**

| 概念 | 定义 | 稳定性 | 数量级 |
|---|---|---|---|
| **源点家族** `Family` | 一个共鸣点源出的全部建筑 | 随生长变化；只用于溯源与显示 | 12–20 |
| **规划社区** `Community` | 从锚点沿**可建邻接图**加权扩张得到的发展区域 | **稳定 ID**，不随音级 / 成熟 / 调音变化 | 36–48 |
| **音乐连通簇** `Cluster` | 每乐句按**声学耦合图** `c > 0` 重算的连通分量 | **每乐句重算**，编曲的临时输入 | 每乐句不同 |
| **功能区** `District` | ≥2 个规划社区 + 用途构成 | 由章程/锚点、公共设施、成员用途和线路派生、自动更新 | 8–14 |

**规划社区规则**：

| 项 | 规则 |
|---|---|
| 扩张种子 | 城市中心 / 地标 / 玩家播种点 |
| 扩张代价 | 道路穿越 + 坡度 + 岸线 + 边界（**不用欧氏 Voronoi**——会把隔河两岸划成同一片） |
| 边界 | 主路 / 河岸 / 山脊（可见边界，玩家看得见） |
| 最小 | **4 栋**（少于 4 栋为"萌芽区域"，**规划 ID 仍存在**，只是不参与社区级音乐） |
| 最大 | **40 栋**，超出先分裂 |
| 分裂 | 沿可建邻接图的支中心扩张分区；各区连通且成员互斥；**保留父 ID** |
| 禁止 | 裸 k-means、割点块、声学删边、按音级重编号 |

**三条硬规则**：

1. **一座建筑恰好属于 1 个规划社区**（不是"可能属于多个"）。家族与音乐簇是另两套标注，不改变归属。
2. **改音级不改变规划社区 ID**。玩家调音不会把房子"调出社区"。
3. **原 P0 九栋 fixture 的 3 个区域 ≠ 3 个成熟社区**。按最小 4 栋规则，该 fixture 至多 2 个区域达数量门槛；这不限制当前 E7 十八栋制作开局。任何开局的成熟与主题资格均按实际成员和 FB3/主题条件判断。

**为什么音乐簇每乐句重算**：建筑/道路/桥/遮挡变化会改变 `c>0` 图；调音只改变边的协和分与 M 权重，M>0 本身不会删除连通边。编曲仍须跟随协和变化，
而这正是编曲要跟随的东西。规划社区稳定（给玩家归属感），音乐簇流动（给编曲依据），两者服务不同目的。

## 表 SP7 · 地形参数（供表 SP2 引用）

| 地形 | O | T | σ 倍率 | 备注 |
|---|---|---|---|---|
| 平原 | 1.0 | 1.0 | 1.00 | 默认 |
| 滩涂 / 海岸 | 1.0 | 1.0 | 1.15 | 开阔；**σ 倍率不是 T**（旧稿把它写进 T 列） |
| 林 | 0.7 | 0.85 | 1.00 | 吸高频 |
| 山（缓坡） | 0.7 | 1.0 | 1 + h/8 | 高程越高传越远 |
| 山（陡坡 / 山脊线） | **0** | — | — | 完全遮挡 |
| 河 | **0** | — | — | 见下 |
| 湖 | **0** | — | — | 见下 |
| 海 | **0** | — | — | 地图外缘 |

**水体的完整规则（修正旧稿把湖写成 T = 1.0 的笔误）**：

- **规则层**：河 / 湖 / 海一律 `O = 0` → 不产生耦合边，不参与 R。
- **声学层**：不阻断一切声音。水面是**声学镜面**：
  - **湖** → 极轻延迟副本（约 0.15 s，−12 dB），湖边可闻
  - **河** → 两岸可形成**对唱**（表 T3），是**有来源的事件应答**，不是规则耦合
  - **海** → 开放空间，低频回荡（环境层）
- **一句话**：**水体在规则层是墙，在声学层是镜子。** 任何文档、UI、提示不得把两者写成同一件事。

**桥**：建桥把该处 `O` 由 0 恢复为 1.0，并允许两岸进入规则耦合。
桥是**真实的几何边**（两岸落脚点存在、跨度合理、桥头能接路），不是"划过河就成桥"。
