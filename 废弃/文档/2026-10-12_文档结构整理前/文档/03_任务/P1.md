# P1 · 地形、社区、声音规模与极简界面

> 2026-10-09 重构版。按P0的可交付切片推进；空间基础接入后可同步制作必要的画面/供音，不用“全部规格完成”阻挡河谷试玩。完整P0进度见PROJECT；数值样例改见SP9。
> P1 的目标是让**新世界模型第一次产生新体验**：地形提供空间机会，玩家通过声部、音级、位置和规划表达；城市按声部组发声，界面保持克制。

2026-10-11 当前执行优先级：1b 的20–30栋新开局、三种真实表达、主题作者因果和1c最低视觉地基已在第180–182轮接入同一河湾试玩；当前转入真人表达/作者感/差异听测与最小反馈收集。冻结公交及公共空间功能扩展，保留既有能力作为一个规划锚点；时代、地标、三模式、祝福与大城后续推进。技术证据不能替代下列三项真人验收。

## P1 达成的体验

- 在河谷/海岸/山地上开局，**地形改变城市空间机会，玩家的布局与表达产生可听后果**
- 城市长到 **80–150 栋（中型验证阶段）**时，**听起来是一支乐队**，
  不是音轨堆。**400–600 栋是阶段大城目标**，之后继续推进 3,000–5,000 栋；200–400 栋只作途中观测点（见 `18_城市规模.md` §5.1）
- 界面默认只有城市 + 一条节拍条；信息在悬停时出现
- 玩家能一次操作**整个社区**，不必逐栋
- **听见自己做的动机**：≥6 栋的成熟社区生成社区主题，改其中任何一栋的音级，主题就变

3. **最后检验期待是否兑现**：同种子、相近介入额度分别走深流、织机及搭配留地的计划，记录“第一次选择→实际成长→空间或音乐关系出现→下一次自选行动”。第149轮已提供可执行的下一行动入口；跨越条件与形态仍按现行规格，玩家能说出当前收益、取舍和下一步理由，并从录音/城貌认出结果，才证明这条循环成立。

实现证据、同一试玩的前后片段与玩家原话归入项目根 `验证记录/` 对应切片目录，正文只更新状态与链接。不会自动产生兑现的规划、尚未实装的新能力和没有真人证据的乐趣均保持待验证；独立规模/性能工程继续。

## 城市生成与美术协作

当前是已有河湾的精修，最终美术风格仍待选。涉及美术方向时先按 [17 §2.3](../17_美术规格.md#23-风格探索与本机-blender) 做同街坊 2–3 组候选对照，记录用户选择后再批量加工；本机 Blender 可直接通过 Python/CLI 使用，MCP 用于打开场景的检查与小步迭代，不作为离线批处理前置。Agent 先读 PROJECT，按 P1 的未验证目标选一项工作。每次任务明确**输入场景/存档、改动对象、可见结果、验证方法和当前不确定性**，交付实际游戏画面；“开发完整程序化城市系统”不能作为一次无边界任务。

### 给 AI Agent 的 Blender 风格与建模工作流

1. **固定基线**：复制 `.blend` 为工作副本，记录种子、镜头、投影、昼夜时点、街坊布局和导出目标；先用 `get_addon_status`、`get_scene_info` 检查连接与场景。
2. **确定风格**：在同一小街坊中只改一组变量，制作 2–3 个候选（轮廓/屋顶比例、材质平滑度、植被、色彩、阴影）；每个候选都用 `look` 输出同镜头对照，先看整体构图和可读性，再看细节。用户选定前不批量制作。
3. **修改建模**：一次只处理一个建筑家族或公共空间；先读对象、材质、节点和尺寸，再用 `execute_blender_code` 修改，保持项目的地面锚点、朝向、色板、阴影和模块命名合同。改完立即 `look` 检查正面、侧面、俯视和线框/材质结果。
4. **导入 Godot 验证**：导出 GLB/贴图到工作目录，在当前固定河湾中检查接地、遮挡排序、2.5D 朝向、街道连续性、留白和分区性格；不要只凭 Blender 视图通过。
5. **确认与回退**：记录用户接受、拒绝或修改意见；接受后保存版本并进入下一家族，拒绝则回到工作副本或候选分支。不要覆盖原始资产，不要用整城重生成掩盖局部问题。

MCP 操作适合“读场景 → 小改动 → 多角度看 → Godot 对照”的循环；批量变体、固定种子和最终导出仍优先使用可复现的 Blender Python/CLI 脚本。

| 顺序 | 交给 Agent 的具体工作 | 可评审交付与完成条件 |
|---|---|---|
| 1 · 固定基线 | 使用当前 24 栋新河湾和已有章程/声音流程，记录种子、镜头、可听帧与版本；定位最影响自然布局的一处问题 | 整城/社区对应截图、真实道路与占地说明；先保留已成立的核心链路，不重写占位生成器 |
| 2 · 轮廓与公共空间 | 沿已有资产家族精修屋顶/立面/共墙，检查商业街、公建焦点、庭院和河岸留白 | 在相同布局与灯光下对照前后图；统一锚点/色板/阴影，资产工具可用现有脚本或可选 Blender，朝向按 S8a |
| 3 · 分区与选择因果 | 复用 CityProfile、章程、用途和 public_sites，改善商业—居住—文化—公园的自然衔接；对照深流/织机 | 同种子、相近介入次数的城貌与实际录音；说明真实用途、密度或成长差异；未成熟/未排程声部不在预览中冒充演奏 |
| 4 · 连续性 | 涉及布局演化时只更新受影响范围，保留已形成建筑、稳定 ID、玩家音级、留地与历史来源 | 一次局部变化和保存恢复对照；与对应最小合约一起验证，不通过删除整座城制造新布局 |

这四项是当前验收反馈驱动的工作顺序，不新增每项必须从零开发的系统。广泛的文化建筑、学校、诊所与地形族扩充沿后续任务推进，不能为了“分区齐全”塞满核心河湾。每次只跑能证明本次改动的合约；固定画面对照按 [17 §10.1](../17_美术规格.md#101-固定城市美术对照)。布局算法变化再增加少量代表种子，素材变化复用固定布局。技术 PASS、多种子观感与真人作者感分别记录；结果归验证记录，进度只在 PROJECT 更新。

每个切片只跑：
1. 该切片的合约 case

3. 音频相关切片加一次真峰值与 skips 检查

## 风险

| 风险 | 应对 |
|---|---|
| 声部组在 70 时下溢 | 小步 40→55→70；参考旧 64 实体下溢教训 |
| 地形生成产生不可玩布局 | 可建面积 ≥45%；R≥65 保护；最多重采样 8 次 |
| 资产朝向不匹配连续街道 | **先只选资产支持的朝向**；需要自由方向时先补资产（见 `19_城市生成管线.md` §2⑤） |
| 编曲槽让玩家失去控制感 | 槽位竞争规则对玩家可见（悬停时显示谁在唱）；聚焦可覆盖 |

这些切片服务极致心流方向，优先级低于当前核心试玩稳定性，且都需要真人反馈后再升格为规格：

1. 即时手感脚手架：预影、撤回、连片关系线、张力波纹和 ≤0.5s 声音反馈，验证不写入正式世界。
2. 有机聚落对照：同一河湾比较台地、屋脊起伏、庭院微动效和留白，验证可读性、遮挡和帧率。
3. 批量播种候选：沿真实道路拖拽的预览与撤回等价性，暂不扩大正式额度。
4. 音乐涌现候选：只做离线空间卡农或稀疏高潮对照，不接入正式保存和跨局规则。
