## 一、2个必须先修的错误（硬事实层）

（作者本人插话：我觉得其实应该是2.5D，然后做好了，加上少量的3D素材，比如粒子，光源，天空等 然后shader可以做云，后处理，天空，雾等等）
连带后果：
- **渲染路线的结论可以留（2D 矢量 + 2.5D 分层仍然是对的），但论证必须换掉。** 理由要改成"扁平矢量最适合'换色板即换氛围'的联觉一致需求 + YSort 伪立体成本可控"，
- 最对口的是 **Kenney City Kit 系列**（Roads / Commercial / Industrial / Suburban，2025 年 4 月整包重做，40+ 栋、模块化、CC0，`kenney.nl/assets/city-kit-suburban`）——它的"道路为底、建筑件往上叠"的结构，比那批 EPS 更贴你们"20% 模板 + 80% 模块组合"的组装方式。

### 1. "城市即乐器"这个空格已经不空了

策划案第 0 节写"市场空位：没有人做过'城市本身是一件乐器'的游戏"。这句到 2026 年初已经不成立：

- **Circuit City**（Steam，2022-02-01）——"建造城市，你的数据代理和电子元件边工作边为你唱一首独特的程序生成芯片音乐"。这几乎就是你们的支柱 A+B。
- **Music Puzzle: City Builder**（2019 上线）——踩拍堆楼生成城市。
- **Beat Street**（Ludum Dare 41）——每栋建筑在节奏条上占一个音符。
- **Harmoni-us**——等距城市建造，市民碰面产生协和/冲突音景。
- DavidZhang14/**Sound of Cities**（GitHub）——"每栋建筑一种音色，每栋建筑一个发声体"。

**这不是坏消息，是定位的救命信息。** 注意这批作品全部是**加法 / 创作向**：你放一个东西 → 它响一个声 → 城市唱起来。你们文档里最好的一句话其实是第 58 行：

> 失谐不是坏，未解决的失谐才是。

**这句话才是没人做过的方向。** 我建议把定位显式改成：

> 别人做的是"你建的城市会唱歌"（建造→音乐，加法，创作向）。
> **本作是"城市先响着，你负责听出哪里不对，然后只说一个字"（聆听→诊断→处方，减法，诊断向）。**

这个定位会立刻改掉一批设计：如果核心动词是"诊断"，那么玩家的时间应该花在听和判断上，而不是在工具栏里挑房子。目前六份文档没有一处机制在保护这个定位——P0 的任务全是生成方块和调颜色。

### 2. P0 的验收标准不可执行，且管线缺一个硬依赖

- **"测试者闭眼听 30 秒能指出哪边出问题了"不是验收，是愿望。** 它无法自动化、无法回归、AI 无法自检。而你们手上恰好有正确范式：`audio-contract.gd` 里那套"合约测试"（小节边界、未来量化、和声保护、PCM 逐采样比对）。回写策划案时它丢了。
- **Inkscape 转 EPS 需要 Ghostscript，交接单漏了。** Inkscape 自身不解析 PostScript，EPS 导入走 `ps_input.py` → 调 `ps2pdf` / `gswin64c`，缺了会直接报 `No GhostScript executable was found`。所以 A2"用 Inkscape CLI 把 744 个 EPS 批量转 SVG"**第一行就会失败**，而执行 AI 大概率会卡在这里自己发明绕路方案。环境缺口表要加 Ghostscript，并去掉整条 A 线的必要性（因为素材本来就不能用）。
- 顺带三个小的但会咬人的：素材实际在 `资产\2.5D素材\` 而交接单写的是项目根的 `2.5D素材\`；`共鸣之城` 目录**不是 git 仓库**（"先复制再改"的规约没有版本控制兜底）；`资产/` 在 `res://` 里放 3.0 GB / 750 张 JPG，Godot 首次打开会全量导入——需要 `资产/.gdignore`。

## 二、设计层：四处必须修正的实质矛盾

### 1. 律动型声部永远产生不了拍频——这是声学事实，不是调参问题

策划案 §4.6 说：

> 失谐的可闻性不依赖额外音效——两声部真实波形在混音中自然产生拍频，声学天然成立。

但同一张表把声部定义成**律动**："工业 = 锯齿脉冲 + 不规则切分"、"商业 = 十六分律动"。**律动之间产生的是节奏对比，不是拍频。** 拍频需要两条**同时持续振荡**的波形，频率差落在几 Hz 到十几 Hz。P0 的验收对象（"能听出哪边有问题"）恰好依赖这个声学机制——如果声部是断奏的，它就不成立。

而且你们选的两个"失谐"音程，声学行为完全不同：

| 音程 | 低频区（C2 附近） | 中高频区（C4 以上） |
|---|---|---|
| 小二度 C–C♯ | Δf ≈ 4–8 Hz → **清晰慢拍频**，能听出"波动" | C4–C♯4 Δf ≈ 15.6 Hz → 转为**粗糙感** |
| 三全音 C–F♯ | **不产生慢拍频** → 一直是**粗糙度（roughness）** | 同左 |

**所以"工业 = F♯（三全音）"从设计上就不该被听成"抖动"，而是被听成"发毛"。** 两个失谐源要用两种不同的听觉语汇，而文档把它们混成了一类。这直接影响 P0 怎么培训测试者、听诊视图怎么画、以及验收怎么写。

**修正方案：声部拆三层。**

```
每个街区 = drone 层  （持续 pad/持续音，承载音级 → 产生拍频/粗糙）
          + 律动层   （承载节奏签名 → 产生节奏对比）
          + 装饰层   （偶发音，彩蛋/生命感）
```

- **drone 层是失谐的唯一载体**，必须全程持续、不可静音、音域固定。这是"闭眼能听出问题"的物理基础。
- **律动层负责声部身份**（工业切分、商业十六分）。它失谐时表现为"咔咔"的粗糙，而不是波动。
- 这样顺带解释了为什么"公园 = 无固定音级 + 正弦 pad（长音留白）"是对的——它天然是 drone 层，是**解音声部**。但这也暴露一个 P0 缺口：**公园要到 P1 才加入，而 P0 里唯一的解音工具就是它。** 结果是 P0 版工业在城里**永远无法被解决**（C–F♯ 三全音，P0 无转位工具）。
- **附带必修：声部表必须补"音域（八度）"列。** 现在只给了音级（pitch class）。没有八度，整个可闻性设计就是未定义的——C3 和 C5 上的同一个音程效果差一个量级。

### 2. 单局 2–4h × 只有 3 次三选一，和"再来一局是第二引擎"自我矛盾

支柱 D 说 Roguelite 的意义是"让再来一局成为第二引擎"，§6 却给了 **2–4 小时**的单局、4 个乐章、**3 次祝福选择**。Hades 的构筑手感需要 10+ 次决策；3 次三选一构不成构筑，只构成"抽了三次"。而且对一款听觉游戏，2–4 小时连续程序化音乐是**疲劳区间**，不是沉浸区间。

建议：**单局压到 25–40 分钟，乐章拆 6–8 段，祝福 5–7 次。** 短局才是"再来一局"的前提。

### 3. 所有介入都是纯增益——没有代价就没有 Roguelite 张力

现在的提案（增建住宅区）只让事情变好。但和声的本质是**取舍**：把住宅加到 C 音上，就与旁边商业的 E 形成了大二度（轻度不协）。**每次介入都应该在和声地图上留下一个新张力**，"每乐句只能介入一次"是注意力预算。这样"规划"才真的是作曲，而不是修 bug。

### 4. 数值表不够钉死，执行 AI 一定会自创

§4.6 的音程表本身是全文最好的一条（直接可用），但缺一半：

| 缺失项 | 后果 |
|---|---|
| "每乐句"多长 | 结算频率未知，AI 自选 |
| R 的"加权平均"权重怎么算 | 公式不存在，AI 自创 |
| R 的**初始值**是多少 | 随机开局可能一上来就 R<40 触发灰噪化 |
| 活力 V 的上限/是否复利 | "+8%/乐句"复利几回合就爆表 |
| "终止式达成"的定义 | 乐章如何推进？完全未定义 |

这几条不钉死，策划案与实现会**永久不一致**——这是这类项目的标准死法。

## 三、五个我认为真正有价值的创新补丁

按性价比排序。前三条约等于重做核心动词。

### ★ 1. 张力债务 / 延迟解决（Deferred Resolution）——把"修 bug"变成"作曲"

现在玩家看到的失谐全是待清理的故障。但在调性音乐里，**最爽的瞬间是延迟解决**：张力挂了很久，最后落回主音。

> 允许城里有 N 处**故意保留**的未解决失谐，每处按持续时间累积"期待值"。你在一个卡准的和声落点上把它一次性解决——爆发加成 = 期待值 × 解决精度。

这一条同时干了三件事：给"什么都不做"一个策略价值（现在完全没有）；让时间本身成为资源；让 §7 的"留白计分"从事后评分变成**时刻决策**。这是我认为最该进 P1 的一条，也是唯一一条能让"诊断向"定位长出深度而不只是氛围的机制。

### ★ 2. 推子（Solo / Mute）——支柱 A 的听觉版听诊

文档有"听诊**视图**"（视觉），但没有"听诊**动作**"。真正的创新在这里：

> 玩家可以对任意街区做 solo / mute——把可疑声部单独抽出来听，或者把整片城区静音只听一处。

这是混音师的本能，零学习成本，实现成本极低（改 bus 音量而已），而且它是**唯一一个把"城市是乐器"从隐喻变成操作**的动词——比"抚琴"更贴支柱 A，因为它是**诊断**而不是表演。我认为 A1 抚琴的热度应该让位给这一条。

### ★ 3. 介入的落点从"拍子"改为"音级"（双轨奖励）

现在"卡拍落定"给出"切分共鸣"加成。问题是：**卡拍是节奏反应，与和声核心无关，而且对新手是精准度门槛**——这跟"耳朵优先、耳朵是工具"的支柱是拧的。

> 介入可以发生在任何时刻。**落点音级决定效果**：落在当前和弦音上 = 协和解决；落在和弦外音 = 引入新张力（可能是你想要的）；同时命中拍点 = 额外节奏奖励。

于是技巧分两条轨：和声判断（核心，人人可学可深）+ 节奏精准（可选，给老手的糖）。试听未来机制天然承担教学——长按预览时你听到的是"解决"还是"更糟"，玩家三分钟内自己就懂了。

### 4. 每次介入的副作用显式化

接上面第 3 条：每个提案在 UI 上除了显示"这里会变好"，还要显示**"代价：与 X 处形成大二度"**。这不是惩罚，是把权衡放到台面上。Roguelite 的构筑感来自"我选择了这个张力而不是那个"。

### 5. 无音频可玩模式升级为一等公民

支柱 A 把所有信息押在听觉上，那**静音玩家和听障玩家就完全不可玩**。Steam Deck、公共场所、直播场景全都要静音。文档只在听诊视图提了一句"兜底"。

这不是可访问性的施舍，是商业必需：**做一个"视觉优先"模式——音程关系、失谐、张力债务全部有等价的视觉语言（波形、色温偏移、微动效熄灭），信息完整度与听觉模式等价。** 你们的美学规格 §2.5 已经写了失谐的潜意识视觉信号（色温偏移、对比拉高、阴影边缘变硬、微动效逐一熄灭）——那套东西离"完整信息通道"只差一层组织。把它做成一等模式，而不是兜底。

**另外两条便宜且值：** 市民来信（B1）我建议**从 P2 提到 P1**——它是全文唯一的情感锚点，成本是文本模板，收益是"城市记得"。每日一城建议**用 UTC 日期哈希派生种子，不做后端**——同种子竞技不需要服务器，省一个系统。

## 四、文档重构：这是让执行 AI 做对的关键

核心诊断一句话：**这六份文档是设计师的思考日志，不是执行规格。**

执行 AI 失败的方式从来不是"不懂设计"，而是这四种：

1. **读错版本**——`游戏策划案v3` 与 `v3.1` 并存，交接单让 AI"冲突时以高优先级为准"，AI 会把两版混起来。
2. **数值自创**——规格没给的地方它不会停下来问，它编一个，然后这个数会留在代码里直到项目结束。
3. **用错手段达成目标**——用额外音效"伪造"拍频（直接破坏支柱 A），用普通 Tween 假造"生长精确等于 1 拍"（破坏视听同步这个核心爽点），用逐帧扫描图片代替读 manifest。
4. **交付一个无法验收的东西**——"闭眼听能指出问题"没法自动化，于是没有任何东西能证明 P0 成功了。

### 新文档树

```
文档/
├── 00_设计意图.md          ← 给人读。1 页。定位声明 + 竞品差异 + 支柱 + 反支柱
├── 01_执行规格/            ← 给 AI 读。机读优先。唯一权威。
│   ├── spec.city.md        街区/声部三层/音级/音域 schema
│   ├── spec.harmony.md     音程表 + R/V 完整公式 + 初始值 + 结算频率
│   ├── spec.audio.md       bus 表、音频时钟、拍频与粗糙度的可闻性要求
│   ├── spec.asset.md       资产来源白名单 + 授权状态 + 加工管线（含 Ghostscript）
│   ├── spec.proposal.md    提案生成、试听、双轨落点、代价显示
│   ├── spec.run.md         乐章/祝福 schema、种子派生、City DNA
│   └── spec.ui.md          HUD、推子、听诊视图
├── 02_验收/DOD.md          ← 每条机制配一条可运行测试 + 反例
├── 03_任务/P0.md …         ← 每条任务带 DoD 与产出路径
└── 90_存档/                ← 所有被取代版本，执行 AI 不读
```

**铁律：只有 `01_执行规格` + `02_验收` 产生实现细节。`00_设计意图` 只解释为什么。`90_存档` 任何人都不得作为实现依据。**

### 每条规格的格式（这是最关键的部分）

```
[HARM-004] 失谐的可闻性
意图：读者能在混音里听出小二度相邻的两个街区存在张力
规则：drone 层两音频率差 Δf
      Δf ∈ [3,16] Hz  → 必须可闻为「慢拍频」（波动感）
      Δf > 16 Hz 且音程 ≤ 3 半音 → 可闻为「粗糙感」
      三全音           → 只产生粗糙感，不产生慢拍频
数据：spec.harmony.md 表 2（含每个声部的音域）
验收：headless 脚本合成 C3+C#3 两条 drone，对输出做包络 FFT，
      检测到 7.7±0.4 Hz 周期分量 → PASS
反例：不得用独立音效伪造拍频（查代码：该效果只能来自 _mix_frame 的波形叠加）
```

**验收 + 反例这一对，是这份规格的价值所在。** 交接单里"明确不做"那一节（祝福/昼夜/行人一律不进 P0，谁提都不做）写得非常好——那种句式要推广到每一条规格。

### 给执行 AI 的元规则（写进 `00`，开头就放）

1. 数值只能来自 `01_执行规格` 的表格，**不得在代码中硬编码**；规格没有的值 → 停下来问，不要自创。
2. 每个任务必须附一条**可运行的验收命令**，否则该任务视为未定义。
3. **不得引入规格未列出的新机制**，即使它看起来显然更好。
4. 任何文档的大改：先复制为带日期的新工作稿，原件只读（这条已有，保留）。
5. `manifest.json` 是程序选件的唯一事实源（已有，保留，全项目推广）。
6. **一次只实现一个规格 ID**，日志记录"规格 ID + 验收命令 + 输出"。

### 还要补三件工程小事

- `git init`。现在的"先复制再改"规约没有版本控制兜底，是裸奔。
- `资产/.gdignore`。否则首次打开 Godot 会导入 3.0 GB / 750 张 JPG。
- 渲染器从 Forward Plus 换成 **Compatibility**——纯 2D 项目用不上 Forward+，而遗产项目正是在 `gl_compatibility` 上验证过的；顺带把窗口尺寸写上（现在没设）。
- 顺便关注 `美学规格v1` 的"单屏 Sprite ≤ 800"：模块化建筑每栋 6 层 sprite → 只够 130 栋。这对城市建造游戏是紧预算，应该在 P0 就实测，而不是留到 P2。

## 五、修订后的 P0（3 周，可验收）

原 P0 的目标是对的，但缺一个动词、缺一个解音工具、缺自动化验收。我的版本：

**目标：证明"失谐可以被耳朵定位"这件事，本身不靠任何视觉、不靠任何音效特效。**

| # | 任务 | 验收 |
|---|---|---|
| 0 | git init；`.gdignore`；切 Compatibility | 仓库可提交 |
| 1 | 音频时钟 autoload（移植 `sound_engine.gd`） | `audio_contract` 风格测试 PASS：小节边界、未来量化 |
| 2 | **声部三层**：住宅 C3 drone、商业 E3 drone + 十六分律动、工业 F♯3 drone + 切分 | **拍频测试**：C3+F♯3 输出包络无慢周期；C3+C♯3 输出包络有 7.7 Hz 周期 |
| 3 | 16×16 地图、3 类街区生成、邻接结算 | R 与 V 的**数值断言测试**（给定布局 → 期望 R） |
| 4 | 黑屏模式：只出声、无任何画面 | **闭眼定位测试**：3 名测试者，10 次随机布局，正确指向失谐源的 ≥ 7 次 |
| 5 | **一个提案，其动词是"改变音级/位置"**（例如把工业从 F♯ 移到 G），长按试听 3 秒 | 试听版与落定版混音的差异可被自动比对；落定只在边界生效 |
| 6 | **一个推子**：solo / mute 任意街区 | mute 后该 bus 输出能量 ≈ 0，且不影响其他 bus |

注意第 5 条我改了动词。**原来写"增建住宅区"——那教出来的是"多盖房子"，不是"作曲"。** P0 唯一的手必须落在和声变化上，玩家才会在第一天就学到这个游戏在说什么。

第 6 条是新加的，成本半天，但它让 P0 第一次拥有"诊断"这个动词——目前 P0 全部是"建造"。

## 2. 声学规格：必须新增的一整节（这是当前最大技术风险）

> 症状：`游戏策划案v3.1` §4.6 断言"失谐的可闻性不依赖额外音效——两声部真实波形在混音中自然产生拍频，声学天然成立"。
> **这个断言在它自己选定的两个失谐音程上都不完全成立。** 下面给出正确的模型，请**新增为策划案 §4.7**，并**修改 §4.6 的表**。

### 2.1 拍频只在窄音程上成立——三全音不产生拍频

以 C 为基准的实际频率差（A4 = 440 Hz，十二平均律）：

| 关系 | 上音 | 频率 | **Δf** | 主导听觉机制 | 听感词汇 |
|---|---|---|---|---|---|
| 纯五 C–G（C3–G3） | G3 | 196.00 Hz | **65.2 Hz** | 谐波重合 3:2 | 空、开、稳 |
| 大三 C–E（C3–E3） | E3 | 164.82 Hz | **34.0 Hz** | 谐波重合 5:4 | 亮、暖、满 |
| 大二 C–D（C3–D3） | D3 | 146.83 Hz | **16.0 Hz** | 边界区（拍频↔粗糙） | 发痒、不稳 |
| 大二 C–D（C2–D2） | D2 | 73.42 Hz | **8.0 Hz** | **包络拍频** | 缓慢摆动 |
| 小二 C–C♯（C3–C♯3） | C♯3 | 138.59 Hz | **7.8 Hz** | **包络拍频** | 颤抖、发抖 |
| 小二 C–C♯（C2–C♯2） | C♯2 | 69.30 Hz | **3.9 Hz** | 包络拍频 | 极缓的晃 |
| **三全音 C–F♯（C3–F♯3）** | F♯3 | 185.00 Hz | **54.2 Hz** | **谐波失配（无重合），不生拍频** | **刺、沙、脏** |

**三条必须写进文档的结论**：

1. **"难听"不来自 Δf 的大小。** C–G 的 Δf（65 Hz）比 C–F♯（54 Hz）还大，却是最协和的音程。协和度来自**谐波序列的重合度**，不来自频率距离。
2. **拍频机制只在 ≤2 半音时才是主导。** 三全音（6 半音）在任何可听音域都**不产生慢拍频**。
3. **因此失谐必须分成两类，用两套听觉语汇和两套修复手段**：

   | 类型 | 声学来源 | 听感 | 修复手段 |
   |---|---|---|---|
   | **「抖」（Wobble）** | 小二/大二，低音区，Δf 3–16 Hz | 包络脉动、有节奏感的颤抖 | **移开** / **插入解音声部** |
   | **「刺」（Grate）** | 三全音，谐波失配 | 静止的、无起伏的沙糙感 | **必须重排邻接**（不能靠改音级，因 F♯ 在调外） |

### 2.2 五声音阶里产生不了小二度——请修正 §4.6

`游戏策划案v3.1` §4.6 定 P0 骨架为 **C D E G A**（C 大调五声）。在这个音级集合内：

- **可达的窄音程**：大二（C–D、D–E、G–A，各 2 半音）、小三（E–G，3 半音）
- **不可达**：**小二度（需 1 半音，五声音阶按构造排除）**、纯四（C–F 但 F 不在集合内）、三全音（C–F♯，F♯ 不在集合内）

**因此 §4.6 音程表中的"小二/三全音 = 失谐"这一行是有问题的**：小二度在 P0 不可能出现，三全音只能通过**调外音**出现。

**修正动作**：

1. §4.6 表**新增一列**并补一行，改为下 §2.3 的表。
2. **新增一段设计说明**（原文照抄）：

   > **工业区的 F♯ 是刻意引入的调外音（chromatic）。** 在 C 大调五声的城市里，工业是唯一一个"天生不属于任何邻居"的声部——这正是它的设计身份，也是它的玩法身份：它必须被**重排邻接**才能融入，而不能通过改变自身音级来融入（F♯ 改到任何五声音级都会失去工业身份）。这使工业成为全城唯一的"结构性难题"，而不是"数值低的街区"。
   >
   > 小二度（「抖」）在本作中不由街区类型固有产生，而是**由「声部叛离」状态产生**：一个长期未解决的街区音高偏移 +1 半音，同时脱离节拍网格（见《设计增补v1》C2 的规格化）。这样「抖」的语义 = **离调（可修复，会晃）**，「刺」的语义 = **对冲（需重排，会刮）**。两个诊断类别由此区分。

3. §4.6 音程表**删除"R −3"**。理由见 §2.4。

### 2.4 新增公式（原样复制进策划案 §4.7）

```
【R · 谐振度】  纯函数，每个乐句边界重算一次，不保留历史
  R = 100 × Σ(w_i · s_i) / Σ(w_i)          i 遍历全城所有邻接对
  s_i = 该邻接对音程的协和分（表 B）
  w_i = 1 + 0.15 × (n_i − 1)               n_i = 两街区共享边界格数
      w_i = min(w_i, 2.0)
      若任一方为工业，则 w_i × 1.3          （工业天生需要被安排）
  初始值：由开局布局计算；生成器必须保证 R_initial ≥ 65（见 §2.5）

【V · 活力】  每街区独立，每乐句更新
  V_next = clamp( V + Σ_neighbors(ΔV_pair) + base_growth − decay , 0 , 100 )
  base_growth = +1.0 / 乐句
  decay       = 0.5 / 乐句  当 R < 60，否则 0
  单乐句净变化上限 = ±12      （防复利爆表）
  初始值 V_0 = 50

【灰噪化】  可逆，带迟滞
  进入：R < 40    退出：R > 48

【崩盘】  R < 40 连续 3 个乐句 → 本局结束（仍有保底采样，见策划案 §5.5）
```

**关键裁定**：原文"双方活力 +8%"这类**百分比表述全部改为绝对点数**。百分比会复利，几回合内爆表且不可复现。

### 2.5 生成器与运行时的四条硬约束

1. **开局 R 下限**：地形+初始布局生成后立即计算 R；若 `R_initial < 65`，对种子做局部扰动重新采样，**最多 8 次**；仍不达标则换种子。此约束必须写进文档，否则随机开局可能一进场就触发灰噪化。
2. **RNG 子流隔离**：City DNA = `{ seed: uint64, mode: string, charter_id: string, decisions: [{bar:int, proposal_id, target, choice}] }`。所有随机必须来自 `hash(seed, 子流名)`，**子流固定为**：`terrain` / `mode` / `boons` / `form` / `events`。文档中显式禁止无子流来源的 `randi()` 调用。这样才能保证"种子+抉择序列可完整复现一局"。
3. **建筑 sprite 合并**：`执行方案v1` §7 的"单屏 Sprite ≤ 800"与"模块化建筑 6 层 sprite"直接冲突（800 ÷ 7 ≈ 114 栋，对城市建造游戏过少）。
   **修正**：每栋建筑在**导入期烘焙为 1 张整图**（各层在离线阶段合成），运行时不叠 6 个节点；换色由**全局色板 LUT shader** 承担，不靠分层遮罩；全城窗户统一进**一层全屏 additive 层**。结果 ≈ 1.05 sprite/栋 → 约 760 栋，预算达标。
   **生长动画的 mask 揭示改在 shader 内按参数完成**，不再依赖独立节点。
4. **色板两轴分离**（原文档把两件事混为一谈，会导致"16 × N 张色板"的组合爆炸）：
   - **轴一 · 色板表**：4 时段 × 4 季节 = **16 张**，离散切换，只在小节边界过渡。
   - **轴二 · 谐振度调制**：一个**连续全局调节器**（饱和度 −15%…+10%、色温 ±300 K），叠加在轴一之上。
   **文档必须明确：谐振度不新增色板表。**"谐振度驱动饱和度由同一套色板系统实现"这句话请改为"谐振度作为轴二叠加在轴一的输出上"。

## 3. 音频工程规格：三处必须修改

### 3.1 Sidechain ducking 不能压低 drone 层（原规格会导致核心信号消失）

`美学规格v1` §5.3 写"提案试听、定音、形态演出时，音乐 bus 自动 −6dB"。

**这会让玩家在"比较两个方案"的瞬间失去判断依据**——因为协和/失谐的差异全在 drone 层，而 drone 被压了。

**替换为**：

> - **Sidechain ducking 的目标 bus 白名单**：律动层 bus / 环境 bus / UI bus。
> - **drone bus 永不参与 ducking**（唯一例外：形态演出时全城淡出）。
> - 提案试听期间：被改动声部 **+3 dB**，其余非 drone 声部 −6 dB，**drone 层保持不变**。
> - 试听时长 3 秒，必须包含至少**一个完整的 3–16 Hz 拍频周期**（即 ≥ 300 ms）才能让人听出差异。

### 3.2 新增：小扬声器（beat_assist）

**问题**：3–16 Hz 的拍频来自低音区的两条相邻频率（如 C3 130.81 与 C♯3 138.59）。笔记本/手机扬声器在 200 Hz 以下大幅衰减，**拍频在窄带设备上完全消失**——玩家会得出"这游戏听不出区别"的结论。

**新增规格**：

> - **beat_assist 开关**（默认开）：对参与失谐的两条 drone，在**上方一个八度**复制一对伴音（C4 261.63 / C♯4 277.18），并对伴音施加与被压制的原拍频**同频的振幅调制**。
> - 伴音电平原值为 drone 层的 −12 dB，仅当播放设备被判定为窄带时提升至 −6 dB（提供手动开关即可，不做自动探测）。
> - 此机制**只在设备无法重现原拍频时启用**，默认路径仍是真实的声学拍频（支柱 A 的优雅性优先）。
> - 验收：**新增"狼牙音箱测试"**——用笔记本内置扬声器播放黑屏模式，测试者仍能定位失谐源。

### 3.3 响度与混音目标（替换 `美学规格v1` §5.3 最后一行）

> - 整体 **−16 LUFS**，真峰值余量 **3 dB**。
> - **drone 层在该响度下的技术下限**：任何时刻 drone 层的 RMS 不得低于总混音 RMS 的 **25%**；低于此值时触发自动补偿（防止环境声床掩蔽失谐信号）。
> - 所有 drone 必须**持续发声、不可静音**（这是"闭眼能听出问题"的物理基础）。只有玩家的推子操作可以临时静音它。

## 4. 玩法机制：五处修改

### 4.1 支柱零：定位声明（新增到 `游戏策划案v3.1` §0 与 §1 之间）

> **§0.5 定位：诊断向，不是创作向**
>
> 原文 §0 写"市场空位：没有人做过'城市本身是一件乐器'的游戏"。**此判断已过时。** 已存在同方向作品：
>
> | 作品 | 年份 | 关系 |
> |---|---|---|
> | Circuit City | 2022（Steam） | 城市建造，元件与代理"边工作边唱出一首独特的程序生成芯片音乐" |
> | Music Puzzle: City Builder | 2019 | 踩拍堆楼生成城市 |
> | Beat Street | Ludum Dare 41 | 每栋建筑在节奏条上占一个音符 |
> | Harmoni-us | — | 等距城市建造，市民碰面产生协和/冲突音景 |
> | Sound of Cities | — | "每栋建筑一种音色，每栋建筑一个发声体" |
>
> **这批作品全部是加法 / 创作向：你放一个东西 → 它响一个声 → 城市唱起来。**
>
> **本作的差异必须写成一句话**：
>
> > 别人做的是"你建造的城市会唱歌"。
> > **本作是"城市先响着，你负责听出哪里不对，然后只说一个字"。**
>
> 据此确定两个反支柱（Anti-pillars），写入 §2：
> - **反支柱 A：玩家不直接作曲。** 玩家不能说"在这个街区加一个 E 音"。玩家只能诊断与介入。
> - **反支柱 B：核心动词是"听"和"判断"，不是"挑选"。** 任何让玩家大部分时间花在工具栏里浏览选项的设计，都违反定位。
>
> 原文 §4 那句"失谐不是坏，未解决的失谐才是"是本文档最好的一句话，**提升为支柱 B 的表述**，并在 §1 一句话概念中复现。

### 4.2 声部三层（新增，接 §2.3 表 A）

见上文 §2.3 表 A 的层结构说明。**必须写明**：drone 层是失谐的唯一载体；律动层之间产生的是节奏对比，**不产生拍频**。这决定了 P0 的验收只能在 drone 层上做。

### 4.3 介入落点：从"卡拍"改为"音级"双轨（替换 §4"和声提案"条目）

原文把"卡拍落定触发切分共鸣加成"作为核心。问题：卡拍是节奏反应，与和声核心无关，且对新手是精准度门槛——与"耳朵优先"的支柱相拧。

**替换为**：

> - **介入可发生在任何时刻**，落定只在乐句边界生效。
> - **主轨 · 音级命中**（核心技巧）：
>   | 落点与目标音级的关系 | 效果倍数 |
>   |---|---|
>   | 命中提案允许的和声音级 | **×1.0** |
>   | 偏差 1 半音 | **×0.7** |
>   | 偏差 ≥2 半音 | **×0.4**，且引入一次新张力 |
> - **副轨 · 卡拍**（可选技巧，给老手的糖）：落点距乐句边界 **≤ ±80 ms**（沿用 `audio-game/scripts/sound_engine.gd` 的 `0.080` 秒常数）→ 附加「切分共鸣」泛音层 + 该街区 **+5 活力**。
> - 试听未来机制天然承担教学：长按预览时听到的是"解决"还是"更糟"，玩家在三分钟内自己会懂。

### 4.4 每次介入必须显示副作用（新增）

> 提案 UI 除显示预期收益，**必须同时显示代价**。例：
> `「把工业区移到此处」预期：R +8 ／ 代价：与北侧住宅形成大二度（−3 活力）`
>
> **理由**：和声的本质是取舍。没有代价的介入不是作曲，是修 bug；有代价的介入才让 Roguelite 的构筑感成立（"我选择了这个张力而不是那个"）。

**P0 的三个介入动词（替换 `执行交接-P0.md` §5 B6 的"增建住宅区"）**：

| 动词 | 内容 | 代价 |
|---|---|---|
| `retune` | 把一个街区的音级改到相邻协和音级（例：工业 F♯3 → G3，与 C 成纯五） | 该街区 −10 活力（改造成本）；与**新**邻居的关系可能不协，必须预览 |
| `relocate` | 把一个街区移到另一格，改变邻接关系 | 移动期间该声部静音 1 乐句；原邻居失去加成 |
| `infill`（P1） | 在两街区之间插入解音声部（公园），取共同协和音 | 占地，降低该处密度上限 |

**注意**：原 P0 动词"增建住宅区"教出来的是"多盖房子"，不是"作曲"。**P0 的唯一介入手必须落在和声变化上。**

### 4.5 Roguelite 张力：三条修改

1. **单局时长压缩**（替换 §6 局内循环）：
   | 单位 | 长度 |
   |---|---|
   | 小节 | 2 s |
   | 乐句 | 8 小节 = **16 s** |
   | 乐章 | 12 乐句 ≈ **3.2 min** |
   | 一局 | **7 乐章 ≈ 22 min**（含祝福与结算停顿，实际 25–35 min） |
   | 祝福选择 | **每乐章边界 1 次 → 一局 7 次** |

   原稿"2–4 小时单局 + 3 次祝福"构不成构筑感，且与听觉疲劳区间冲突。**"再来一局是第二引擎"要求短局。**

2. **终止式定义**（原文完全未定义，必须补）：
   > 乐章完成条件 = 该乐章内达成 **3 次「协和解决」**（把一处大二/小三提升到协和）**且**末乐句 R ≥ 70。
   > 达成即进入祝福三选一。

3. **祝福软保底数值**（替换 §5.6 第 2 条）：
   > 稀有度基础权重：普通 **70** / 稀有 **22** / 史诗 **7** / 传说 **1**。
   > 每连续出一个普通：稀有 **+3**、史诗 **+1**。
   > 出稀有或以上后权重重置。
   > **硬保底：连续 5 次普通后，下一次必定稀有或以上。**

4. **每日一城实现**（替换 §5.5 最后一条）：
   > `seed = hash("daily:" + UTC日期 + 版本号)`。**不使用任何后端服务。**

### 4.6 张力债务（新增机制，接 §4.4）

> **§5.7 张力债务 / 延迟解决**
>
> 在调性音乐里，最有力的瞬间不是消除不协和，而是**延迟解决**。据此：
> - 允许城内保留 **N 处故意未解决**的失谐（N = 1 + 已获祝福数 ÷ 2，上限 4）。
> - 每处按持续时间累积 **期待值 E**（每乐句 +1，上限 6）。
> - 玩家在一个**卡准的和声落点**上把它一次性解决 → **爆发加成 = E × 落点精度**，并把 E 转化为**城市图鉴**条目。
>
> 此机制同时完成三件事：给"什么都不做"一个策略价值（当前完全没有）；让时间成为资源；把 §7 的"留白计分"从事后评分变成**时刻决策**。
>
> **建议 P1 实现。**

## 7. 无音频可玩模式（新增整节）

> 支柱 A 把所有信息押在听觉上，则**静音玩家、听障玩家、公共场所与直播场景全部不可玩**。原文档只在听诊视图提了一句"兜底"。
>
> **这不是可访问性的施舍，是商业必需。**
>
> **新增规格：视觉优先模式**（一等公民，非兜底）
> - 失谐类型有等价视觉语言：
>   | 听觉 | 视觉 |
>   |---|---|
>   | 「抖」（包络脉动） | 该邻接边界出现**脉动的发光带**，脉动频率 = 实际拍频（缩放自 3–16 Hz） |
>   | 「刺」（谐波失配） | 该邻接边界出现**静止的高频毛刺纹理**，无脉动 |
>   | 张力债务期待值 E | 边界发光带的**色温偏移量**，随 E 累积 |
> - 信息完整度必须与听觉模式**等价**（验收：视觉优先模式下完成闭眼测试的对应版本——"遮挡听觉，仅凭视觉指出失谐方位与类型"，正确率 ≥70%）。
>
> 这直接复用 `美学规格v1` §2.5 已写的失谐视觉信号（色温偏移、对比拉高、阴影边缘变硬、微动效逐一熄灭），只是从"潜意识级"提升为"完整信息通道"。

### 每条规格的格式（强制模板）

```
[域-编号] 标题
意图：一句话，说明这条规格保护什么玩家体验
规则：精确到可判定（数值、公式、阈值）
数据：指向 spec.*.md 的表号
验收：可运行的判定命令或可数的判定标准
反例：这条规格最容易被违反的方式，以及如何检出
```

**示例（可直接作为 `spec.audio.md` 的第 1 条）**：

```
[AUDIO-001] 失谐的可闻性
意图：读者能在混音里听出相邻两个街区之间存在张力，且能区分张力的性质
规则：drone 层两音频率差 Δf
      Δf ∈ [3,16] Hz → 必须可闻为「慢拍频」（包络脉动）
      Δf > 16 Hz 且音程 ≤3 半音 → 可闻为「粗糙感」
      三全音 → 只产生粗糙感，不产生慢拍频
数据：spec.harmony.md 表 A（含每个声部的音域）与表 B
验收：headless 合成 C3+C♯3，对输出包络做 FFT，检出 7.78±0.5 Hz 显著峰 → PASS
反例：不得用独立音效伪造拍频。
      查代码路径：该脉动只能来自 _mix_frame() 的真实波形叠加。
```

### 给执行 AI 的元规则（放进 `00_设计意图.md` 开头）

1. 数值只能来自 `01_执行规格` 的表格，**不得在代码中硬编码**；规格没有的值 → 停下提问，**不要自创**。
2. 每个任务必须附**一条可运行的验收命令**；没有验收的任务视为未定义，不得开工。
3. **不得引入规格未列出的新机制**，即使它看起来显然更好。
4. 任何文档的大改：先复制为带日期的新工作稿，原件只读（既有规则，保留）。
5. `manifest.json` 是程序选件的唯一事实源（既有规则，保留，全项目推广）。
6. **一次只实现一个规格 ID**；执行日志记录"规格 ID + 验收命令 + 输出路径"。
