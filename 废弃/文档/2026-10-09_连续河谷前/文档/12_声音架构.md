# 03 · 声音架构：声部、编曲与规模

> 2026-10-09 重构版。本文回答旧问题单 Q03/Q04/Q05/Q11/Q12/Q21——即"大城市怎么听起来是一支乐队"。
> 数值权威在 `01_执行规格/spec.audio.md`。

---

## 1. 三层声部（保留）

每个建筑 = **drone 层**（持续音，承载音级 → 唯一产生拍频/粗糙的层）+ **律动层**（节奏签名）+ **装饰层**（偶发音）。

**保留旧实现的全部技术参数**：
- drone 谐波权重：住宅 `1.0/0.08/0.03`、商业 `1.0/0.12/0.06`、工业 `1.0/0.20/0.10`
- 律动音高 = drone 上方 12 半音
- 律动包络：起振 0.005 s、尾音 0.25 s、衰减 0.075 s
- 工业律动 300 Hz 高通（drone 保留基音）
- 波表 4096 点，22050 Hz

## 2. 规模问题的本质（回答 Q03）

**旧限制的根源是"一栋建筑 = 一个独立合成声部"。27 栋到顶。**

但仔细看：如果 20 栋住宅都在 C3，它们的 drone 是**同一个频率、同一相位、同一音色**——它们在数学上是**同一个信号**。合成 20 份再相加，得到的不是 20 倍音量（那是 20 倍功率），而是**每个频率上相干叠加**。

旧设计已经意识到这点：`voice_group_budget.gd` 是"分组供音"候选，`spec.audio` 表 A15 定义了合并条件（家族、音高、相位、电平、锚点、阶段曲线、轮唱拍号、滤波、控制签名全部一致）。但旧设计把它当**优化**，且因为"a·√k 只在不相关信号假设下成立"而不敢用。

**重构的转变：把合并从"优化"升格为"编曲的正当手段"。**

---

## 3. 声部合并规则（新的规模地基）

### 3.1 合并是设计决策，不是妥协

**同一社区内、同一音级、同一成熟阶段的建筑，合并为一个"声部组"。**

```
声部组 = { 社区, 音级, 成熟阶段 }
```

一个声部组的合成信号 = 该组所有建筑的**单个** drone 采样 × `k^(1/2)`（保持功率），相位统一。

**这不是近似**：同音同相位的相干信号相加，功率 ∝ k²。若要保持总功率不变（避免爆音），振幅应 ∝ √k。旧规格说"√k 只在不相关信号假设下成立"——**对同频同相信号，√k 恰好保持功率**（正确）；对同频**不同相**信号，相加结果介于 √k 与 k 之间。所以：

- **合并前必须归一化相位**（同社区的同类建筑统一起始相位）→ 使 √k 严格成立
- **合并后实测**（旧 A6 协议），不以推断通过

### 3.2 合并的取舍（诚实说明）

| 项 | 合并前 | 合并后 |
|---|---|---|
| 每栋独立 Solo/Mute | ✅ | ❌ **改为按声部组** |
| 单栋调音 | ✅ | ✅ **改音级即拆出该栋，重新成组** |
| 每栋独立相位/装饰 | ✅ | 装饰层保留逐栋（装饰是偶发事件，可逐栋排程） |
| 合成成本 | O(栋数) | O(声部组数) |

**为什么可以接受 Solo/Mute 粒度变化**：玩家实际上从不需要"只静音这一栋"——他需要的是"只听这个和声部分"或"只听这个社区"。按声部组 Solo 反而**更有音乐意义**。

**旧问题 Q23（地标吸收抹掉玩家的作品）的解法**：吸收时**不销毁音高信息**，被吸收建筑的音级进入地标动机的数据源（保留），所以玩家调出来的旋律**活着**，只是由地标演奏。

### 3.3 规模的量化

| 规模 | 建筑数 | 社区数 | 不同音级数 | **声部组数** | 同时发声的实际声部 |
|---|---|---|---|---|---|
| 古典小镇 | 30 | 3–4 | 5 | 8–12 | **10–14** |
| 中城 | 120 | 8–12 | 7 | 20–30 | **20–30** |
| 大城 | 400 | 24–36 | 10 | 60–90 | **30–60** |
| 终局大城 | 600 | 36–48 | 12 | 90–140 | **40–70** |

**关键**：建筑数可以到 600，但**同时发声的声部数被编曲规则限制在 40–70**（见 §4）。这是"乐队"而非"600 条音轨"。

**CPU 预算**：现行实现 27 实体在 22050 Hz 单线程下 16 秒 0 skips。声部组合成后**每组合成 1 次、共享输出**，成本降到 O(声部组)。40–70 声部组在可接受范围；**必须先做压力测试确定真实上限**（见 `03_任务/`）。

## 4. 编曲规则：城市如何成为一支乐队（回答 Q04/Q12）

### 4.1 声部角色

城市演奏时，声部被分配到**固定数量的角色槽**：

| 角色 | 槽数 | 音域 | 来源 | 可否被 ducking |
|---|---|---|---|---|
| **低音（Bass）** | 1–2 | C2–C3 | 低八度社区 | 否 |
| **和声垫（Pad）** | 2–4 | C3–E3 | 各社区 drone | 否（drone 不进 ducking） |
| **旋律（Lead）** | 1 | C4–C6 | 环形合唱 / 歌剧院 / 社区主题 | 是 |
| **节奏（Rhythm）** | 2–3 | 打击 + 低音律动 | 商业社区 | 是 |
| **装饰（Ornament）** | 不限（稀疏） | 高音 | 央/腔建筑 | 是 |
| **环境（Bed）** | 1 | 全频段 | 地形声床 | 是 |

**槽位是稀缺的**：全城同时只有 **1 个旋律槽**、**1–2 个低音槽**。

### 4.2 谁拿到槽位（这是玩法，不是自动）

**旋律槽与低音槽由"城市状态"竞争产生**：

- **旋律槽**优先给：已命名的旋律结构（环形合唱 > 歌剧院 > 社区主题 > 手动 Solo 的社区）
- **低音槽**优先给：音域最低的成熟社区；洼地/河谷社区加成
- **节奏槽**优先给：商业建筑密度最高、且与旋律槽有协和关系的商业区

**玩家能通过建城影响谁拿到槽**——这就是"用城市布局决定编曲"。

### 4.3 同时发声与进退场

- **同一时刻最多 1 个旋律声部**。多个候选旋律结构存在时，**轮流**（每 4 乐句轮换，或由玩家的引力/聚焦指向决定）。
- **低音/垫永不间断**（drone 持续是旧硬规则，保留）。
- **节奏与装饰可进退**：进 = 2–4 拍 equal-power 交叉；退 = 同。
- **留白是强制的**：每乐章至少有 1 个乐句，旋律槽**空着**（只有垫与节奏）。这来自旧美学"留白 ≥25%"，在音乐上是"让城市呼吸"。

### 4.4 层次化聆听尺度（回答 Q21）

三个尺度，用同一个键循环切换：

| 尺度 | 听到什么 | 用途 |
|---|---|---|
| **全城** | 上述编曲，40–70 声部 | 听整体作品 |
| **社区** | 该社区的全部建筑 + 它的有效邻居（跨社区） | 听局部和声，判断缺口 |
| **单栋** | 该建筑三层的完整频谱 + 它的直接邻居 | 诊断具体音程 |

**切换方式**：镜头缩放自动联动（拉远 = 全城，拉近到某社区 = 社区尺度，选中一栋 = 单栋），**不需要菜单**。这满足"极简 UI + 直觉"。

**声像**：连续声像（不是三档）。`pan = clamp((x−y) / 12, −0.8, 0.8)`，等功率映射。这取代旧的三段量化（旧 A5/A16），并解决了"跨阈值整声部跳一边"的问题。

## 5. 响度与密度预算（回答 Q05）

### 5.1 增长规则

**响度不随规模增长。** 这是硬规则（旧 ERA-08 硬约束③保留）：

- 初始完整混音校准到 **−16 LUFS**，固定公共增益
- 真峰值余量 **3 dB**
- drone RMS ≥ 总混音 RMS 的 **25%**（保护器保留）

**城市变大时，靠织体变丰富（更多声部角色、更宽的频率覆盖），不靠音量变大。**

### 5.2 混音预算分配

| 层 | 目标占比（大城） | 说明 |
|---|---|---|
| drone（垫 + 低音） | 35–45% | 地基，恒定 |
| 节奏 | 15–25% | 推进力 |
| 旋律 | 10–20% | 主角，但占比小 |
| 装饰 | 5–10% | 稀疏点缀 |
| 环境 | 10–20% | 地形声床 |

**当声部组数量上升时**：新增声部组的**单组振幅下降**（统一 `1/√(组数)` 归一或按角色分配），使总能量恒定。

### 5.3 密度限制

**同时活跃的声部组上限**（防"墙"）：

- 每社区最多 **3 个声部组**同时**以完整振幅**发声；其余降到 40% 音量（"背景层"）
- 全城最多 **70 个声部组**；超出者只保留 drone，律动与装饰自动简化

**旧约束修订**：旧"长音持续/不自动补偿"需要修订为——**drone 持续但背景声部可以降级**。修订记入 `spec.audio`。

### 5.4 ducking

保留旧规则：Rhythm / Environment / UI 可触发 ducking（−6 dB，300 ms 回弹）；**drone 永不参与**。

## 6. 音色与声学（保留旧协议）

- **协和分表 B** 原样保留
- **声学测量协议**原样保留：小二 7.78±0.5 Hz 峰 ≥6 dB；三全音 3–16 Hz 无慢峰；协和包络波动 <1.5 dB
- **时代音色**必须通过 A6 协议（谐波更丰富会在三全音上产生慢差频）
- **形状恒定，音色换代**：连续/分段/锯齿/包络拍频四种形状是游戏语言；**锯齿类只给工业**
- **节拍辅助**：保留（默认开，手动窄带，−6 dB）

## 7. 音乐素材的来源

| 层 | 由谁提供 |
|---|---|
| **音阶与调式** | 设计者（五声 → 十二音，随时代） |
| **和声规则** | 设计者（表 B） |
| **编曲语法** | 设计者（每时代的规则：单旋律 → 奥尔加农 → 复调 → 管弦 → 电子） |
| **具体音高分配** | **玩家**（播种与调音决定谁唱什么） |
| **旋律内容** | **城市状态**（环形合唱读玩家调出的 8 音；地标动机读落成时的音级） |
| **节奏型** | 设计者（商业十六分、工业切分等） |
| **谁是旋律谁是伴奏** | **玩家**（通过城市布局与引力决定） |

**这条表就是"声音与城市深度结合"的可执行定义**：设计者给语法，玩家给内容。

## 8. 音频实现建议

- **合并必须发生在合成前**：先算声部组，再逐组合成，最后混音。
- **装饰层保持逐栋排程**（事件是稀疏的，成本低，且保留"每栋有个性"）。
- **相位归一化**是 √k 成立的前提，必须显式做。
- **压力测试**是规模开放的前置条件：测 40/70/100 声部组在目标硬件上的 skips 与真峰值。
- **保留旧 A15 的分组边界合约**（26 项生产合约 + 4 项边界），扩展到新结构。
