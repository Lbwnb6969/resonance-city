# Sandbanker stage 2：coverage 与成对顶点平滑的确定规则

本段已确定：先对 `coverage` 做 **3 轮**半差传播，再按有向岸边积累水平法向、偏移 **偶数**顶点，随后做 **6 轮**偶数顶点半差平滑；奇数顶点在这一段只接受固定向上位移。两种传播都没有邻居数量分母。把它写成“奇数顶点六轮平滑”或“按邻居度数求平均”会改变原程序。

证据来自已有 Ghidra 导出 [815c40.c](native_application/815c40.c) 与安装包中 `GameAssembly.dll` 的原始 x86 字节。新的逐指令证据、字节哈希、常量与数值检查见 [townscaper_sandbank_smoothing_raw.json](townscaper_sandbank_smoothing_raw.json)，复核脚本为 [verify_sandbank_smoothing.py](../work/verify_sandbank_smoothing.py)。这是独立本地 PE / Capstone 核验，**没有新增 REA Evidence ID**，也不把静态结果称作运行时观察。

## 索引与临时表

令 `V=verts.Count`，`N=V/2`，`T=tris.Count`。除法是 C# 整数除法；原始指令在 RVA `0x8170c9` 使用 `cdq/sub/sar` 实现向零截断。有效构造路径的 `V` 为偶数：stage 1 每生成一个端点就连续添加两份相同 `Vector3`，并添加一个 coverage 值，源码第 1334–1396 行和 1429–1492 行分别给出两端点路径。

每个逻辑岸边顶点 `i` 对应：

- `P_i = verts[2*i]`：本段法向偏移和六轮平滑修改的点。
- `Q_i = verts[2*i+1]`：本段六轮中保持不变，之后加垂直位移的配对点。
- `c_i = coverage[i]`：一对点共用一个浮点 coverage。

每个岸边条带由六个三角索引表示。stage 1 在第 1501–1565 行按原顺序写入：

```text
[a, b, b+1, b+1, a+1, a]
```

`a,b` 是端点第一次加入 `verts` 时的当前列表长度，或从字典取回的同一个索引，因而是偶数。其对应两三角形为 `(a,b,b+1)` 和 `(b+1,a+1,a)`。本段的边扫描每次 `k += 6`，**只取** `a=tris[k]`、`b=tris[k+1]`；它不把两个三角形的六条边逐一送入平滑，也不读取 `tris[k+2..k+5]` 来产生额外邻接。逻辑边端点为 `i=a/2,j=b/2`。

两个池化 scratch 列表分别记为 `A` 和 `B`，元素真实布局是三个连续 float32。池的申请容量参数为 **V**，之后仅追加 **N** 个 `Vector3.zero`，两个列表的实际 Count 为 N。Ghidra 将 `B` 错标成 Dictionary，并把浮点数据混进 `OrientedModule` / obfuscated int 字段；原始程序实际用 List 的 `_items`（+8）、`_size`（+12）、Vector3 步长 12 字节。RVA `0x8170a2..0x8171a8` 记录了整个初始化过程。

## 三轮 coverage 传播

对轮次 `r=0,1,2`，先遍历全部条带，以该轮尚未改写的 `c` 计算：

```text
for k = 0; k < T; k += 6:
    i = tris[k] / 2
    j = tris[k+1] / 2
    d = (c[j] - c[i]) * 0.5
    A[i].x += d
    A[j].x -= d

for i = 0; i < N; i += 1:
    c[i] += A[i].x
    A[i] = Vector3.zero
```

`A.y,z` 同时沿着加减零的 Vector3 通路保留，但 coverage 只使用 `A.x`。第一轮开始时 A 全零，每轮应用后对 **每个**元素重新写入完整 `Vector3.zero`。不是一边遍历边就立刻修改 coverage；全部边贡献积累完之后才应用，所以是同步迭代。字节 `0x81724a` 的 `fmul [0x111d3834]` 使用常量 `0x3f000000=0.5`；`0x81747f` 比较 3，`0x817482` 返回该轮开始。源码第 1681–1786 行给出边贡献，第 1792–1835 行给出应用、清零和轮次。

用实数代数写成：

\[
c_i^{r+1}=c_i^r+\frac12\sum_{j\in E(i)}(c_j^r-c_i^r).
\]

`E(i)` 在这里是六索引记录产生的邻接**多重集合**，重复边贡献按原列表次序重复累积；程序没有去重。唯一的分母是常量 **2**。没有除以 `degree(i)`，没有 clamp，也没有保留初始 coverage 作为固定端点。矩阵表示为 `(I-0.5L)^3 c_initial`，L 是这张多重边图的拉普拉斯矩阵；这个表示是从已经确定的循环推导出的数学表达，不是发现了原作者源码中的矩阵实现。

当且仅当一个顶点在该多重集合里的度数是 2，这一步在实数运算下等于两个邻居值的平均。程序没有在本段验证度数 2。不能把这个特殊情况推广为通用“邻居平均”。

## 水平法向积累与偶数点偏移

coverage 三轮结束后，B 仍然是初始化的全零表。每个条带按 `a -> b` 的方向读取顶点位置并计算：

```text
edge = verts[b] - verts[a]
n = Vector3(-edge.z, 0, edge.x)
B[a/2] += n
B[b/2] += n
```

两个端点收到的是**同向** n，第二个端点也用加法；不使用相反法向。只取 x/z，edge.y 被忽略。第 1910–1987 行有这个累积；原始 RVA `0x8175c0` 一带的减法与 sign-bit XOR 确认 x 分量为 `-dz`，z 分量为 `dx`。n 在逐边积累之前没有归一化，也没有除以边长或端点度数。

接着逐顶点执行：

```text
w = Mathf.Lerp(0.8f, 0.2f, c[i])
verts[2*i] += B[i] * w
B[i] = B[i].normalized
```

这是**先用未归一化的 B 偏移，再把 B 原位置归一化**，不能交换顺序。偏移结果为：

\[
P_i'=P_i+B_i\,[0.8+(0.2-0.8)\,\operatorname{Clamp01}(c_i)].
\]

第 2066–2096 行给出 Lerp、偏移和 normalized 的顺序；原始调用在 `0x817889`，even 索引步长在 `0x817952` 是 `add edx,2`。B 归一化结果留给后续 stage 2 使用，六轮位置平滑使用的是 A，不是 B。

实际 `Mathf.Lerp` 函数 RVA `0xa43e90` 已核验，参数 t 的有限值先限制到 `[0,1]`；这不是 `LerpUnclamped`。因此 coverage 传播本身虽不 clamp，**本次偏移权重**仍限于 `[0.2,0.8]`。0.8 与 0.2 的实际 float32 位型分别是 `0x3f4ccccd`、`0x3e4ccccd`。

normalized 实际进入 RVA `0x673cc0`：用 float32 乘加求 `x*x+y*y+z*z`，转 double 求平方根，再转 float32；只有长度严格大于 float32 `0x3727c5ac`（`9.999999747378752e-6`）才对各分量除以长度，否则返回零向量。这里是**归一化**的分母，不能误写成前面 coverage 或后面邻接传播的分母。

“水平法向”是数学意义的观察结论；它相对于整条海岸是向内还是向外，取决于 stage 1 生成的有向条带顺序。不能仅凭这几行把方向固定叫作外侧。

## 六轮偶数顶点位置平滑

法向偏移结束后，对轮次 `r=0..5`：

```text
for k = 0; k < T; k += 6:
    a = tris[k]
    b = tris[k+1]
    d = (verts[b] - verts[a]) * 0.5f
    A[a/2] += d
    A[b/2] -= d

for i = 0; i < N; i += 1:
    verts[2*i] += A[i]
    A[i] = Vector3.zero
```

A 已在三轮 coverage 的最后一次应用中逐项清零；没有把 coverage 的临时数值带入位置平滑。每轮同样是积累全部边后再更新所有点，并清零完整 Vector3。位置差取 **x、y、z 三分量**，不是仅平滑水平 x/z。第 2173–2245 行给出半差和两端点加减，第 2262–2322 行给出偶数点更新和六轮计数。原始 `0x817a52..0x817ab1` 对三个分量分别 `subss/mulss`；`0x817cdb` 是偶数索引 `+2`；`0x817cf4` 比较 6 并跳回六轮起点。

写成实数代数，每个分量分别满足：

\[
P_i^{r+1}=P_i^r+\frac12\sum_{j\in E(i)}(P_j^r-P_i^r),\quad r=0,\ldots,5.
\]

起点 `P^0` 是刚完成未归一化法向偏移的偶数点，所以等价矩阵表达为 `(I-0.5L)^6 P_displaced`。没有 coverage 权重、法向投影、长度归一化、degree 分母或单独固定的端点守卫。

六轮循环虽然用 `verts[tris[k]]` 读点，但在前述构造不变量下 `tris[k],tris[k+1]` 都为偶数，所以奇数配对点不进入这个平滑邻接。

## 奇数点的固定抬高

六轮之后开始 `index=1`、每次 `index+=2`，执行：

```text
verts[index] += Vector3.up * float32_bits(0x3e3e76c9)
```

这个常量真实值是 `0.1860000044107437`。源码第 2323–2380 行以及 RVA `0x817cfd..0x817e2a` 绑定了起点 1、Vector3.up、常量位置 `0x111f1650` 与步长 2。因此本段处理的配对关系是“偶数点法向偏移并平滑；奇数点单独抬高”。把 Q 称为某种“岸内固定点”属于对用途的解释，不是本段运行时观测。

## 数值与异常边界

Ghidra 伪码中的 `(int)((float)...` 是局部槽位错误类型传播。原始 stage 2 字节完全没有 `cvtt*`、`cvtss2si` 或 `fist*` 浮点转整数指令；偏移与累积以 float32 数据位直接传进 List<Vector3>，不会先截断到整数。

coverage 边半差使用 x87 `fsub/fmul` 并在 d 处 `fstp float32`，所以该处是 `float32((float64(c_j)-float64(c_i))*0.5)` 的有限输入参考式；A 的加减与 coverage 应用使用 SSE float32。位置半差则三个分量分别先 `subss` 舍入，再 `mulss` 乘 0.5，随后用 Vector3 float32 加减。重建若要求逐位一致，需要保持边序、加减序以及原程序的 x87/SSE 舍入路径，不能全部换成无中间舍入的 double 公式。

本段保留 IL2CPP List 的空引用与越界异常：scratch、verts、coverage、tris 为空触发原异常路径，访问越界触发 `ThrowArgumentOutOfRangeException`。没有“异常索引略过”的正常分支。`V=0` 或 `T=0` 会跳过对应内层循环，轮数仍执行；合法生成路径的 T 是 6 的倍数。函数不会在此主动检查 T 是否可被 6 整除，也不会检查 a/b 为偶数；不满足这些构造不变量时，按原索引访问规则执行或抛异常，不能额外发明容错行为。

原字节核验覆盖本段完整 `0x8170a2..0x817e2a`，确认没有 arithmetic divide 指令，只有索引 `/2` 的位移实现。normalization 的除法位于调用函数内部，已经单独记录。
