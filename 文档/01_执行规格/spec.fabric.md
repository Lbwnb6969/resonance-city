# 有机连片与落点分层执行规格

> 2026-10-10 新增。本文定义**三件事**，它们是同一条因果链的三个环节：
> ① 玩家能在哪里落下（落点分层）；② 相邻建筑如何视觉拼合成连片街墙与围合庭院（有机拼合）；③ 连片如何成为可辨认的社区（社区成形）。
>
> 它回答的是"房子长到一起变成一个社区"这件事，并补上现行规格的空白：
> `spec.space` 只定义**声学耦合**（看不见的关系），本文定义**建筑形态关系**（看得见的关系）。
> **两者必须分开存储**：形态关系不参与 R/V，声学关系不决定外观。混用会让"长得像"和"听起来有关"互相污染。

> 当前落地范围：连续河谷已接入 L1/L2/L3 合法落点预览、L3 生长后果、派生共享山墙/连排缓存；第73轮加入按社区筛选的真实庭院多边形、净空直径和画面覆盖；第74轮让庭院中心成为可播种、可生长的内地 L2 落点。真人可辨验收仍待实施。

## 0. 与现行规格的边界（先读这一段）

| 层 | 管辖 | 权威 |
|---|---|---|
| 声学耦合 `c`、R/V、E/N₁₂、规划社区 | 不可见的规则关系 | [spec.space](spec.space.md) |
| **形态关系**（连片、围合、街墙） | **可见的建筑形态** | **本文** |
| 生长候选评分与乐句边界提交 | 何时长、长在哪 | [spec.city](spec.city.md)、[14_城市生长](../14_城市生长.md) |
| 声部组、编曲槽 | 听起来是什么 | [spec.audio](spec.audio.md) |

**三条不可越界的规则**：

1. **形态关系不进 R/V**。两个共享山墙的建筑，其 `c` 仍由 spec.space 表 SP2 的距离核算出——共享山墙**不额外加成**。
   （理由：形态是表现层。若形态给规则加成，玩家会为了数值刷连片，连片就从"好看"退化成"刷分"。）
2. **声学耦合不决定外观**。隔着 1.2 地块、`c = 0.9` 的两栋建筑，若中间有院子，就是**不连片**的。
3. **合并只发生在视觉层**。每一栋建筑的**身份、音级、阶段、活力、ID 全部独立**，永远不因为连片而合并。
   音频侧的声部组合并（spec.audio 表 A15）是另一件事，条件不同——**不得用 A15 的分组结果驱动连片外观**。

## 表 FB1 · 落点分层（任意合法陆地都能点，位置决定未来）

**裁定：玩家可以在任意合法陆地落点。系统不拒绝落点，而是让位置决定这栋建筑会长成什么。**

合法性（全部满足才可落）：

| 条件 | 值 |
|---|---|
| 在地图可建区内 | spec.terrain 可建性判定 |
| 不落水 / 不落陡坡 / 不落保留地 | spec.terrain；玩家主动留地的占地排除见 [spec.proposal P10](spec.proposal.md#表-p10--留地与后续兑现)（待实施），覆盖 L1/L2/L3，包括庭院内地 |
| 不与已有建筑占地重叠 | `D ≥ r_i + r_j`（D 为中心距；FB2 的 d 为占地净间隙）（spec.space 表 SP1） |
| 不在成路街道上 | spec.city 道路层 |

合法落点再按**临街面数量**分三层。**临街面方向必须来自实际可达道路，不能把空地上未受阻的方向算成临街。** 原 1.2 地块/8 向描述未定义道路接入；当前代码用 1.35 地块搜路，并包含“已有地块且至少一向临街即 L1”的切片例外。正式接入距离与该例外须在 GAP-FRONTAGE 闭合，不能直接据切片改阈值。庭院内地 L2 是 FB2 已批准的独立例外。

| 层 | 条件 | 名字 | 生长上限 | 可升级到 | 声学后果 | 界面文案 |
|---|---|---|---|---|---|---|
| **L1** | 临街面 ≥ 2 个不同方向 | **临街地块** | 正常（每乐句 1 栋） | 群 / 央 / 腔 / 地标 | 按常规耦合 | "沿街 · 可成长" |
| **L2** | 临街面 = 1 个方向 | **街尾 / 侧街** | 正常，但**首栋需 2 乐句**（先建立进入） | 群 / 央 / 腔 | 按常规耦合 | "临街一侧 · 稍慢" |
| **L3** | 临街面 = 0 个方向 | **空地** | **减半**（每 2 乐句 1 栋） | **只能到群**（冻结在群） | `σ × 0.9`（孤屋耦合略弱） | "孤屋 · 慢生长，阶段停在群" |

**分层只看临街面数量，不看邻居**。理由是**可预判**：
玩家必须能在点下去之前，**只凭看一眼地形**就知道这块地属于哪一层。
若层判定还依赖"附近有没有别的房子"，玩家就要数房子——那就不再是直觉（与支柱 E 冲突）。
"周围有没有邻居"的正确归属是 §2.2 的形态关系（连排需要邻），不是落点分层。

### 1.1 为什么是"后果"而不是"拒绝"

- **拒绝**会在玩家最想试的瞬间关掉输入（"点哪都不行"是手感杀手，也是 Townscaper / Dorfromantik / ISLANDERS 一致避免的做法）。
- **后果**让玩家每一次点击都有回应，且**可学习**：他点三次空地，看到三次"孤屋"，自己就懂了。
- **不设失败**：空地不是错误，是一种合法的表达（"我想让这里有一个孤独的东西"）。

### 1.2 落点预览必须回答的一句话

悬停任意合法落点时，预览卡**必须**显示它属于哪一层，以及**会长成什么**：

```
"沿街地块 · 预计与东侧形成 C–E 大三度 · 可达群/央"
"空地 · 无临街 · 每 2 乐句最多出生 1 栋，阶段停在群"
```

**这行字是本节的全部意义**：玩家在**点下去之前**就知道自己在做什么选择。
不得只显示"合法/不合法"——那是二值判断，不构成设计选择。

### 1.3 三层必须都有真实用途（禁止把 L3 做成废物）

| 层 | 玩家会为了什么选它 |
|---|---|
| L1 | 城墙面的推进、参与命名形态（回声街需沿路 ≥4 栋） |
| L2 | 在已有街区内部加深肌理、形成庭院、控制密度 |
| **L3** | **孤立的独奏岛 / 瞭望点 / 故意留白前的地标前兆**；为了一件"孤零零的东西"的音乐效果 |

**验收**：若实测中玩家从不主动选 L3，则 L3 的声学收益不足，**改 L3 的收益，不是删 L3**。
（候选收益方向：孤屋 `σ` 略强而非略弱、或孤屋自动获得一个装饰层音型。取哪一项需实测算。）

## 表 FB2 · 有机拼合（共享院墙 / 屋顶连片 / 围合庭院）

### 2.1 形态关系三种，逐条独立判定

对任意两栋建筑 i、j，中心距 D，占地净间隙 `d = max(0, D−r_i−r_j)`；以下阈值均指净间隙：

| 关系 | 判定 | 视觉结果 |
|---|---|---|
| **共享山墙** | `d ≤ 0.10` 地块（几乎贴合） | 两者之间**不画间隙贴图**；两侧外墙融合为一道山墙；两栋屋顶**朝向一致对齐**，檐口连成一条线 |
| **连排** | 一组建筑沿排的相邻成员 `d ≤ 0.25` 且**共用同一条街面**（临街方向夹角 ≤ 30°） | 屋顶脊线连成一片；沿线出现统一的檐口与排水 |
| **围合庭院** | 见 §2.3 | 中央出现**庭院地面**（非建筑），带共享通道 |

**阈值来源（换算说明，供执行方核对）**：一栋民居 `r = 0.45`，中心距 0.90 为贴合。
现实联排的共享山墙是**零间隙**，而本作连续空间里两个独立命中点几乎不可能正好 0.90，
所以取 `d ≤ 0.10` 为"贴合容差"（相当于现实中 ~1 m 的施工缝）。**这不是数值游戏，是一个几何容差**，当前阈值保持；若实测需调整，先记录 GAP-FABRIC 裁定再更新唯一规格，执行方不得自行调换。

### 2.2 连排的长度上限（防止"一条街一栋楼"）

| 参数 | 值 | 理由 |
|---|---|---|
| 单条连排最多 **6 栋** | 6 栋 × 0.9 = 5.4 地块 | 现实联排 4–6 户一段（温哥华 4–6 units / 里士满最多 6 units） |
| 超过 6 栋 | **强制断为两段**，断点处留 **0.3 地块**间隙（视觉上是巷道口） | 保持"街墙有节奏"而不是无限长条 |

**断点必须是可见的**（巷道口/门洞），不得只是"算法上分了两段而画面上无缝"。

### 2.3 庭院成形条件

一个庭院被**确认**，当且仅当同时满足：

| 条件 | 值 |
|---|---|
| 围合边数 | 至少 **3 条边**（4 边最好；3 边时开口必须 < 1.5 地块宽） |
| 内部净空直径 | `≥ 0.8` 地块（现实换算 ≈ 8 m；温哥华花园庭院最小 7.3 m、入口庭院最小 8 m；UNEP 庭院住宅同量级） |
| 内部无建筑 | 是 |
| 内部不是路 / 水 / 陡坡 | 是 |

满足后：

- 中央渲染为**庭院地面**（"共享通道色"，与 `18_城市规模.md` §2.2 的社区地面纹理同源），不生成建筑
- 庭院**计入留白**（`17_美术规格` §6 的社区尺度留白）
- 庭院是**内地的 L2 地块合法来源**：不再需要临街面

**为什么最小 0.8 地块而不是更小**：这是现实尺度的直接换算，且与本作相机缩放有关——
小于 0.8 的庭院在社区尺度（0.8 < zoom < 1.8）下读不出来，等于没做。**视觉上读不出的规则不要写进规格。**

### 2.4 屋顶连片的具体做法（2.5D 硬约束）

**硬约束（来自 19 §2⑤，必须正视）**：固定视角 2.5D 贴图**不能通过旋转变成正确的另一侧**。

因此屋顶连片**不做几何变形**，只做**三种合规做法**，任选其一或组合：

| 做法 | 说明 | 成本 |
|---|---|---|
| **A · 檐口线融合**（推荐首选） | 两栋贴合时，中间不画檐口阴影线，屋檐描边连成一条连续线 | 低，仅改绘制顺序与描边层 |
| **B · 山墙贴片替换** | 贴合侧改用"山墙贴片"资产（无窗、无门、无檐口），替代默认朝向面 | 中，需新增少量资产 |
| **C · 顶面合并贴图** | 连排 ≥3 栋时，整条连排的屋顶烘焙为一张合并贴图 | 中高，但 `17_美术规格` §9 的大城合并贴图已有同款机制可复用 |

**不得做**：把建筑贴图旋转到"另一侧"当成共享墙；把两栋在几何上切成一个连续体（那是 Townscaper 路线，2.5D 固定贴图不支持，且会动摇"一栋一发声体"）。

### 2.5 拼合不能破坏的东西

| 必须保持 | 原因 |
|---|---|
| 每栋的建筑 ID / 音级 / 阶段 / 活力独立 | 玩家调一栋的音，**只有这一栋变**；共享山墙不传递音高 |
| 每栋仍可被单独悬停、选中、Solo | 交互命中以建筑自身占地为准，**不以连片为单位** |
| 连片不改变 R / V | 见 §0 |
| 连片不改变规划社区 ID | 见 §3 |

## 表 FB3 · 社区成形（连片如何成为"一个社区"）

社区定义（稳定规划社区）**仍以 spec.space 表 SP6 为准**，本文不重定义。本文只定义**可见的成形读法**。

### 3.1 街墙连续度（新指标）

```
街墙连续度 S_wall = 该社区沿街立面的"被建筑占据长度" / "可建临街总长度"
```

| 值 | 读作 | 视觉 |
|---|---|---|
| `S_wall < 0.35` | 散落 | 房子各自孤立，读作"村" |
| `0.35 ≤ S_wall < 0.70` | 成街 | 出现连续街墙，读作"镇" |
| `S_wall ≥ 0.70` | 街区 | 读作"城"，可取社区级命名 |

**必须可辨**：这个指标**不上界面数字**，只通过外观（屋顶是否连片）表现。它是给生成器的目标，不是给玩家的仪表。

### 3.2 社区成形的三档可辨（取代"靠色相族辨认"的弱表达）

| 档 | 条件 | 视觉（必须可辨） | 听觉 |
|---|---|---|---|
| **萌芽** | < 4 栋 | 无社区级完整轮廓；成对共享山墙仍按 FB2 几何条件判定 | 各自发声，无社区主题 |
| **成熟** | ≥ 4 栋，且 `S_wall ≥ 0.35`，且至少 1 个庭院成形 | **出现连片街墙**；悬停任一栋，整片轮廓光连成一圈 | 获得社区身份；主题须另满足 ≥6 栋成熟建筑（见 `11 §11.2`），不能因本档 ≥4 栋就提前触发 |
| **完整** | ≥ 8 栋，且 `S_wall ≥ 0.70`，且 ≥2 庭院 | 屋顶连成一片，有明显的公共内院 | 声部组完整、可竞争角色槽 |

**三档是达到条件后的成形标签**；尚未满足成熟/完整条件的社区仍保留规划 ID，不据总栋数强行判为成熟。

**关键改变**：现行 `18_城市规模.md` §2.2 用**色相族 + 地面纹理 + 微动效同步**辨认社区。
这三条都成立、都保留，但它们**与建筑形态无关**——所以一座"房子散落但色调一致"的城，
现在也会被读作一个社区。**新增"连片"作为主要视觉线索后，散落与成街能被区分开。**

## 表 FB4 · 性能与数据

| 项 | 规则 |
|---|---|
| 连片检测触发 | **仅脏区域**（新增/移除/迁移一栋时，只重算它 4 地块内的对） |
| 禁止 | 每次新增一栋就全城两两重算（沿用 19 §4 的禁令） |
| 存储 | 形态关系存**派生缓存**，可由建筑位置重算；**不进 City DNA 的必需字段**（DNA 的完整世界/声音字段仍沿 R2b；位置+ID+音级只足以重算部分形态，不能替代完整快照） |
| 庭院 | 庭院是派生结果，不存为实体；需要有稳定 ID 时（如命名）按"最小建筑 ID 序"生成 |
| 渲染 | 檐口融合与合并贴图各算一次，随建筑增删失效 |

**必须实测的数字**（与 19 §4 的五个数并列，**不合并**）：

1. 有共享山墙的建筑占比
2. 每栋平均连片邻居数
3. 庭院数 / 社区数
4. 檐口融合层的绘制开销（新增）

## 反例（明确不做）

1. 不得为了连片把建筑 ID 合并。
2. 不得让共享山墙给 R/V 加成。
3. 不得用旋转贴图假装"另一侧建筑"。
4. 不得让空地（L3）被系统拒绝或弹提示。
5. 不得把街墙连续度做成界面数字仪表。
6. 不得让庭院小于 0.8 净空（读不出来）。
7. 不得让连排超过 6 栋而画面无缝。
