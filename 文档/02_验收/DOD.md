# 验收 · 最低充分证据

设计已定、实现完成、技术通过和真人好玩四种结论分别记录。下面是新切片验收目标；不存在的测试脚本不写成可执行命令。

## 核心验收

| ID | 操作 | 通过条件 |
|---|---|---|
| SPACE-DUAL | 点平墙/角/上层，退出后拉路 | 墙格只在房屋焦点出现，城市曲线不被量化 |
| GROW-CLICK | 单次、笔画、停手、删块 | 新增来自明确操作；停手后不增殖，邻接局部重组 |
| JOIN-ART | 同层、高差、屋顶、路接门、坡地 | 不穿模/悬空/大斜棚，庭院与入口保持可读 |
| CITY-TOOLS | 画区域、放特殊建筑、刷植被 | 连续范围正确，影响真实占地，区域不自动刷房 |
| UNDO-SAVE | 全部工具撤销/重做、存档恢复 | 几何、ID、种子、成员、时代和音乐连接恢复一致 |
| AUDIO-VIEW | 推移镜头、远端回应、特殊合奏 | 来源真实、平滑进退、全城参与而音量不随栋数累加 |
| AUDIO-OPTION | 静音建造、选风格/连接/断开 | 静音可完成全部动作，连接不改空间规则 |
| UI-INPUT | 小窗口、输入名字、Esc/右键、键盘 | 候选不被面板遮住，按键不泄漏，取消不撤其他已提交动作 |
| PROGRESSION | 启用强力建筑、换代/历史保留 | 能力真实可用，作品来源和玩家修改保留 |
| PERF-SLICE | 固定场景连续编辑、镜头移动、有声 | 记录帧时/延迟/内存/欠载，无持续卡顿，目标 60 FPS |

## 检查命令

在项目根执行文档检查：

```powershell
python tools/check_doc_links.py
python tools/merge_docs_compact.py --check
python tools/build_spec_data.py --check
```

已有模块的测试入口按 PROJECT 和下列代码目录选择：[tests](../../tests)、[tools](../../tools)。先运行能覆盖本次变化的单个合约，再对未解决风险增加实窗/声音检查。旧 `space_contract`/`audio_contract`/存档测试的 PASS 只证明旧对应路径；新工具需要其新行为证据，不能用旧自动生长测试作为通过条件。

## 文档与数据完整性

源稿归档与备份逐文件 SHA-256 对照；本地链接/锚点有效；生成阅读稿与源文档一致。兼容参数更动时检查 `world_v2.json` 除来源哈希外的数据和 `spec_values.json` 是否保持原样。更新实际参数是另一项明确记录的代码工作。

## 体验检查

第一次使用者能找到房屋扩展、道路、区域/植被、撤销和保存；同一片城市可形成至少两种有辨识度布局。分别评价美术吸引力、手感、连接可读性、听感和继续建设意愿。截图和声学测试不代替这些评价。
