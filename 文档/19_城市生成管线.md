# 19 · 城市生成管线：六层结构

> 2026-10-09 新增。本文回答 `技术调研-地形道路与多功能城市生成_2026-10-09.md` 提出的缺口：
> "环带撒点解决不了街坊与临街面；河道缺排水拓扑；桥需要真正几何；家族≠社区"。
> 本文给出**从地形到建筑**的完整六层管线，取代"只在锚点周围撒点"的单一生成方式。

---

## 1. 为什么需要分层

`14_城市生长.md` 描述的"环带采样 + 评分"只能回答"下一栋房子放哪"，回答不了：

- 房子朝哪？（临街面）
- 这一片是住宅还是商业？谁决定？
- 为什么这里有一条主街，那里没有？
- 河上那座桥怎么来的？

**只撒点长不出城市，只会长出一团房子。**

正确的顺序是（来自调研的核心结论）：

```
① 地形      → 高程、坡度、水系、可建性
② 骨架      → 城市中心、主路网、连接意图
③ 社区/功能区 → 区域划分、用途配额、区位偏好
④ 街坊      → 道路闭环围出的街区
⑤ 地块      → 街坊内切分，临街面、朝向、容量
⑥ 建筑 + 生长事件 → 在地块上出现，接入音乐
```

**每一层都向下一层提供约束，向下不越级。**

---

## 2. 分层详解

### ① 地形层

见 `13_地形与自然.md` 与 `spec.terrain.md`。

**关键修正（来自调研）**：河道不能只"从最高点按梯度流向海"——会在局部低洼或平地停住。需要**排水拓扑**：

| 步 | 规则 |
|---|---|
| 1 | 填洼（priority-flood）：把无出口的洼地填平，记录哪些洼地变成**湖** |
| 2 | 保留priority-flood无环父图；有下降取D8最陡邻居，填平区沿父图指向出口，不能在平台重新选出环 |
| 3 | 累积流量；流量 > 阈值的水道 → 河；宽度 ∝ `sqrt(流量)` |
| 4 | 河流终止于海或湖；**不允许终止于平地** |
| 5 | 河两岸留缓冲带（宽度 ∝ 河宽），缓冲带内不可建 |
| 6 | **第一切片可用明确控制的河谷模板**，先解决城水配合，不追求通用水文 |

**内部采样栅格**：空间对玩家是连续的，但地形查询可以缓存在栅格上（如 4×4 子格）。**采样在栅格、放置是连续**——两者不矛盾。

### ② 骨架层

**先定中心与连接，再长房子。**

| 步 | 规则 |
|---|---|
| 1 | 在可建区选 **1–3 个城市中心**（大型城市多中心，不都朝一个种子收缩） |
| 2 | 计算**可达性场**（从中心沿可建区扩散，代价 = 距离 + 坡度 + 绕行） |
| 3 | 用**方向场**（tensor field）生成主路候选：平地用规则网格场，坡地用等高线方向，中心附近混合径向场 |
| 4 | 主路经**局部约束**修正：越界/水域/坡度上限 → 拒绝或转向；与已有路接合 → 吸附为共享节点；过短/急转/重复 → 拒绝 |
| 5 | 交点必须是**共享节点**（"画面交叉"不算连通） |
| 6 | 主路整形后**重新检查**水域/占地/交点；曲线渲染从路网图派生，保留拓扑↔几何对应 |

**桥**：河是"带跨越属性的特殊边"。桥必须同时满足：两岸落脚点存在、跨度合理、桥头能接路。**玩家划过一条河不自动成桥**——它只是提出桥的候选，仍需几何成立。

### ③ 社区与功能区层

**这一层是调研指出的最大缺口：家族 ≠ 社区。**

| 概念 | 定义 | 稳定性 |
|---|---|---|
| **家族**（Family） | 一个共鸣点源出的全部建筑 | 随生长变化 |
| **社区**（Community） | 沿可建邻接图发展的规划区域，允许混合用途 | **稳定 ID，不随音级/成熟变化重算** |
| **功能区**（District） | ≥2 个社区 + 用途构成的分区 | 自动涌现 |

**社区划分算法**：
1. 从**锚点**（中心/地标/玩家播种点）沿**可建邻接图**加权扩张
2. 扩张代价 = 道路穿越 + 坡度 + 岸线 + 边界
3. **不用欧氏距离 Voronoi**（会把隔河两岸划成同一片）
4. 小区合并，大区按支中心分裂
5. 用主路/河岸/山脊作为**可见边界**

**用途分配**（来自 Watabou 区位评分 + Citybound 用地模型）：

| 用途 | 区位偏好 | 内部形态 | 需要保留的关系 |
|---|---|---|---|
| 住宅 | 稳定可达、靠绿地、避强干扰 | 小地块、院落、短巷 | 能到商业/公共中心 |
| 商业 | 主街、广场、多社区连接点 | 连续临街面、较密 | 服务多个社区 |
| 工业/工坊 | 足够大平地、骨干连接、边缘 | 较大地块、疏密分明、缓冲带 | 与住宅有取舍 |
| 公共/文化 | 中心、重要节点、景观焦点 | 大地块、显著留白 | 有服务范围 |
| 绿地/自然 | 岸线、山脊、碎角、生态走廊 | 连续留白 | 参与区划边界 |

**混合用途**：同一个住宅社区可以有一条商业街或一座公共建筑。**用途不应把所有房屋锁成永久同音**——用途决定建筑"长什么样"，音级仍由玩家与和声决定。

### ④ 街坊层

- 从平面道路图提取**闭合街坊**（按转角遍历闭环）
- 扣除路宽、岸线、公共保留区
- **没有闭环的边缘街道**：沿道路布置带状地块（不能因为没闭环就永远不长房子）

### ⑤ 地块层

每个地块记录：用途、容量、**临街边**、入口、占地多边形、坡地基础、社区 ID。

- 沿最长边递归切分，控制最小面积、角度扰动、尺寸变化、留空概率
- **临街面必须真实可得**：找不到真正街面时不能"退回最长边"当成临街
- 建筑朝向以**街面为基准**，同一区域只做小幅变化

**资产限制（必须正视）**：固定视角的 2.5D 贴图**不能通过任意旋转变成正确的另一侧建筑**。
→ 连续布局**先只选资产支持的朝向**，并让街面与朝向模板配合；需要自由街道方向时，**必须补对应视角的资产**或改用可投影几何。这是本层的硬约束，不能靠旋转贴图绕过。

### ⑥ 建筑与生长事件层

见 `14_城市生长.md`。与音乐结合的关键：

```
on_city_tick(player_intent):
    update_local_planning_fields(player_intent)   # 引力带/播种/踩路改变局部目标
    enqueue_connection_and_land_use_goals()
    while planning_budget_left and queue_not_empty:
        proposal = pop_next_goal()
        feasible = apply_terrain_geometry_and_access_constraints(proposal)
        if feasible:
            commit_local_plan(feasible)            # 提交的是"空地 + 连接意图"，不是立即造楼
    lots = eligible_lots_in_active_growth_regions()
    choices = score(lots, 城市用途缺口, 玩家意图, 音乐角色缺口)
    if choices.has_viable_option:
        schedule_birth_at_phrase_boundary(choose_deterministically(choices))
    else:
        expose_reason_and_other_growth_options()   # 说清"缺临街面/坡太陡/用途不足"
```

**关键**：
- 生长是**在合法地块上出现**，不是在空地上撒点
- **几何不合法必须拒绝**；但**音乐规则不应提前消掉所有张力**——不能自动把所有"音乐不理想"的候选都剔掉
- 生成器要能**说清为什么没长**（比无声停止有用）

## 3. 四张关系图必须分开（调研的核心洞见）

**不能用一个邻接表回答全部问题。**

| 图 | 回答什么 | 用于 |
|---|---|---|
| **物理连通图** | 能否到达（道路、桥、坡道） | 交通、服务覆盖、可达性 |
| **地块边界图** | 属于哪里（行政/用途） | 社区 ID、功能区、统计 |
| **声学耦合图** | 彼此如何影响（距离核 + 遮挡 + 地形） | R/V、音频、诊断 |
| **编曲图** | 这一乐句谁演奏（角色槽） | 声部调度 |

| 空间层 | 音乐接口 | 不能混为一谈 |
|---|---|---|
| 建筑/地块 | 音级、音色、成熟、调音事件、占地 ID | 建筑数 ≠ 同时发声数 |
| 社区 | 主题、声部组、成熟轮廓、内部密度 | 用途不应锁死同音 |
| 多社区连接 | 主题呼应、对唱、交接 | **道路连通 ≠ 声学连通** |
| 全城 | 配器角色、进出场、动态留白 | 合成优化 ≠ 编曲好听 |
| 地形 | 反射/吸收/遮挡/环境声床 | **河流阻断交通，不自动证明阻断声音**（反之亦然） |

**社区 ID 稳定性**：社区 ID 不随音级或成熟变化重算。社区主题、声部组、建筑 ID 分别保存。地标吸收时保留来源地块与玩家音级历史。

## 4. 性能与数据结构

| 需求 | 方案 |
|---|---|
| 近邻查询 | 均匀桶或四叉树（不是全城两两） |
| 道路求交 | 局部脏区域更新 |
| 局部耦合 | 脏区域更新（新增一栋不重算全城） |
| 地块/街坊 | 空间索引 |
| 建筑身份 | 稳定 ID（不随音级变化） |

**禁止**：每次新增一栋就全城两两重算；通过听觉合并悄悄丢掉建筑身份。

**必须分别定义的数字**（调研要求）：
- 渲染建筑数
- 空间查询对象数
- 声学邻居数
- 声部组数
- 同时演奏数

这五个数**不是同一个**，见 `18_城市规模.md` §1。

## 5. 迁移影响（诚实评估）

**迁移不是把 `Vector2i` 换成 `Vector2` 就完成。**

| 现行位置 | 现状 | 需要新增/替换 |
|---|---|---|
| `city_growth.gd::advance` | 从锚点四邻格挑位置 | 从合法**地块**挑候选；用途/占地/可达/音乐分开处理；拆开社区 ID 与建筑 ID |
| `city_growth.gd::connected / conditions` | 共享格边连通与成熟判断 | **物理连通与声学关系分开**；连续空间索引与真实占地 |
| `city_roads.gd` | 道路主要阻断既有相邻关系 | 完整道路图、交点、路宽、桥、临街面、正面发展作用 |
| `city_generator.gd` | P0 固定规模布局 | 地形输入、中心与起始区域、生成版本与稳定 ID |
| `city_era.gd` | 地图范围扩张与来客 | 扩张边界连接、区域潜力、保护既有城市与遗产 |
| `city_demo_view.gd` | 固定等距画面与网格资产布局 | 连续世界位置、高差/基础、道路曲线、资产支持的朝向与遮挡排序 |

**受影响的下游**：存档、选择命中、迁移预览、道路操作、成形识别、声学、资产朝向、镜头——**都要接同一个世界坐标与对象身份模型**。

## 6. 推荐实施切片（来自调研）

**不引入完整第三方引擎，分层移植到 Godot。**

| 切片 | 内容 | 证明什么 |
|---|---|---|
| **1 · 河谷切片** | 一条河、一个缓坡、两岸可建地；主街 + 一处合法桥；几个用途不同的社区、商业节点、公共留白 | 看到"沿街建、沿岸留、沿坡转"；体验一次同时改变城貌与声音的操作 |
| **2 · 局部生长切片** | 玩家移动播种点或改变引力带 → 后续道路/地块/用途局部变化，已形成社区保留 | 至少两条选择同时造成可辨城貌与听感差异 |
| **3 · 几十社区规模切片** | 多中心、不同区形态、分尺度编曲 | 实测帧耗、空间查询、音频下溢，**决定预算** |

**只保留三项检查**（调研建议）：
1. 生成后完整占地不落水、不重叠
2. 主要功能区有正确道路可达
3. 同一操作确实带来预期城貌与声音变化

**城市感对照**：平原 / 河谷 / 坡地三个地形例子，同样的用途目标应形成不同道路与布局。
