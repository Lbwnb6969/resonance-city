# 19 · 城市生成管线：六层结构

> 2026-10-09 新增。本文回答 `技术调研-地形道路与多功能城市生成_2026-10-09.md` 提出的缺口：
> "环带撒点解决不了街坊与临街面；河道缺排水拓扑；桥需要真正几何；家族≠社区"。
> 本文给出**从地形到建筑**的完整六层管线，取代"只在锚点周围撒点"的单一生成方式。

---

## 1. 为什么需要分层

`14_城市生长.md` 描述的"环带采样 + 评分"只能回答"下一栋房子放哪"，回答不了：

- 房子朝哪？（临街面）
- 这一片是住宅还是商业？谁决定？
- 为什么这里有一条主街，那里没有？
- 河上那座桥怎么来的？

**只撒点长不出城市，只会长出一团房子。**

正确的顺序是（来自调研的核心结论）：

```
① 地形      → 高程、坡度、水系、可建性
② 骨架      → 城市中心、主路网、连接意图
③ 社区/功能区 → 区域划分、用途配额、区位偏好
④ 街坊      → 道路闭环围出的街区
⑤ 地块      → 街坊内切分，临街面、朝向、容量
⑥ 建筑 + 生长事件 → 在地块上出现，接入音乐
```

**每一层都向下一层提供约束，向下不越级。**

---

## 2. 分层详解

### ① 地形层

见 `13_地形与自然.md` 与 `spec.terrain.md`。

**关键修正（来自调研）**：河道不能只"从最高点按梯度流向海"——会在局部低洼或平地停住。需要**排水拓扑**：

| 步 | 规则 |
|---|---|
| 1 | 填洼（priority-flood）：把无出口的洼地填平，记录哪些洼地变成**湖** |
| 2 | 保留priority-flood无环父图；有下降取D8最陡邻居，填平区沿父图指向出口，不能在平台重新选出环 |
| 3 | 累积流量；流量 > 阈值的水道 → 河；宽度 ∝ `sqrt(流量)` |
| 4 | 河流终止于海或湖；**不允许终止于平地** |
| 5 | 河两岸留缓冲带（宽度 ∝ 河宽），缓冲带内不可建 |
| 6 | **第一切片可用明确控制的河谷模板**，先解决城水配合，不追求通用水文 |

**内部采样栅格**：空间对玩家是连续的，但地形查询可以缓存在栅格上（如 4×4 子格）。**采样在栅格、放置是连续**——两者不矛盾。

### ② 骨架层

**先定中心与连接，再长房子。**

| 步 | 规则 |
|---|---|
| 1 | 在可建区选 **1–3 个城市中心**（大型城市多中心，不都朝一个种子收缩） |
| 2 | 计算**可达性场**（从中心沿可建区扩散，代价 = 距离 + 坡度 + 绕行） |
| 3 | 用**方向场**（tensor field）生成主路候选：平地用规则网格场，坡地用等高线方向，中心附近混合径向场 |
| 4 | 主路经**局部约束**修正：越界/水域/坡度上限 → 拒绝或转向；与已有路接合 → 吸附为共享节点；过短/急转/重复 → 拒绝 |
| 5 | 交点必须是**共享节点**（"画面交叉"不算连通） |
| 6 | 主路整形后**重新检查**水域/占地/交点；曲线渲染从路网图派生，保留拓扑↔几何对应 |

**桥**：河是"带跨越属性的特殊边"。桥必须同时满足：两岸落脚点存在、跨度合理、桥头能接路。**玩家划过一条河不自动成桥**——它只是提出桥的候选，仍需几何成立。

### ③ 社区与功能区层

**这一层是调研指出的最大缺口：家族 ≠ 社区。**

| 概念 | 定义 | 稳定性 |
|---|---|---|
| **家族**（Family） | 一个共鸣点源出的全部建筑 | 随生长变化 |
| **社区**（Community） | 沿可建邻接图发展的规划区域，允许混合用途 | **稳定 ID，不随音级/成熟变化重算** |
| **功能区**（District） | ≥2 个活跃社区 + 用途/公共设施/线路构成的分区 | 自动涌现，稳定 `zone-*` ID |

Demo 第104轮已落地第一层派生实现：居住带、商贸核心、公共绿地带、混合中心和换乘节点从活跃社区、建筑用途、绿廊、公共站点与交通线路自动更新；功能区不重写建筑或社区身份，只为 UI、统计和编曲提供稳定角色。第106轮进一步让扩展城的部分内台/台地地块实际使用 `industrial`，由多个工业建筑派生稳定 `zone-industrial-core` 工坊带；活跃文化公共站点派生 `zone-cultural-core` 文化声场。两者分别映射 `workshop` 与 `choir` 音乐角色，并允许汽车将其作为有意图旅程目的地；完整用途配额仍属于后续施工。

**社区划分算法**：
1. 从**锚点**（中心/地标/玩家播种点）沿**可建邻接图**加权扩张
2. 扩张代价 = 道路穿越 + 坡度 + 岸线 + 边界
3. **不用欧氏距离 Voronoi**（会把隔河两岸划成同一片）
4. 小区合并，大区按支中心分裂
5. 用主路/河岸/山脊作为**可见边界**

**用途分配**（来自 Watabou 区位评分 + Citybound 用地模型）：

| 用途 | 区位偏好 | 内部形态 | 需要保留的关系 |
|---|---|---|---|
| 住宅 | 稳定可达、靠绿地、避强干扰 | 小地块、院落、短巷 | 能到商业/公共中心 |
| 商业 | 主街、广场、多社区连接点 | 连续临街面、较密 | 服务多个社区 |
| 工业/工坊 | 足够大平地、骨干连接、边缘 | 较大地块、疏密分明、缓冲带 | 与住宅有取舍 |
| 公共/文化 | 中心、重要节点、景观焦点 | 大地块、显著留白 | 有服务范围 |
| 绿地/自然 | 岸线、山脊、碎角、生态走廊 | 连续留白 | 参与区划边界 |

**混合用途**：同一个住宅社区可以有一条商业街或一座公共建筑。**用途不应把所有房屋锁成永久同音**——用途决定建筑"长什么样"，音级仍由玩家与和声决定。

### ④ 街坊层

- 从平面道路图提取**闭合街坊**（按转角遍历闭环）
- 扣除路宽、岸线、公共保留区
- **没有闭环的边缘街道**：沿道路布置带状地块（不能因为没闭环就永远不长房子）

### ⑤ 地块层

每个地块记录：用途、容量、**临街边**、入口、占地多边形、坡地基础、社区 ID。

- 沿最长边递归切分，控制最小面积、角度扰动、尺寸变化、留空概率
- **临街面必须真实可得**：找不到真正街面时不能"退回最长边"当成临街
- 建筑朝向以**街面为基准**，同一区域只做小幅变化

**地块分三层落点**（2026-10-10 新增，见 `01_执行规格/spec.fabric.md` 表 FB1）：

| 层 | 来源 | 说明 |
|---|---|---|
| **L1 临街地块** | 本层产出，临街边 ≥2 个方向 | 主力生长位 |
| **L2 内地块** | 本层产出，临街边 =1 且有邻 | 内部加深肌理、生成庭院 |
| **L3 空地** | **不在本层**——由 `14_城市生长.md` 的环带采样产生 | 任意合法陆地，速率减半、冻结在群 |

**为什么 L3 不在本层**：地块层是"有路才切地"的管线，
而玩家**可以在任何合法陆地上播种**（这是支柱 E 的要求）。
两条路都必须存在：**地块管线产生城市肌理，环带采样保证落点自由**。

**资产限制（必须正视）**：固定视角的 2.5D 贴图**不能通过任意旋转变成正确的另一侧建筑**。
→ 连续布局**先只选资产支持的朝向**，并让街面与朝向模板配合；需要自由街道方向时，**必须补对应视角的资产**或改用可投影几何。这是本层的硬约束，不能靠旋转贴图绕过。

**连片资产需求**（2026-10-10 新增）：连片需要三类新资产或新绘制层——
**山墙贴片**（无窗无门）、**檐口融合的描边层**、**连排顶面合并贴图**。
它们**属于 P1 资产范围**，且必须过 §质量红线 的三格测试。
**在连片资产到位之前，不得声称"城市读作一片"已达成。**

### ⑥ 建筑与生长事件层

见 `14_城市生长.md`。与音乐结合的关键：

```
on_city_tick(player_intent):
    update_local_planning_fields(player_intent)   # 引力带/播种/踩路改变局部目标
    enqueue_connection_and_land_use_goals()
    while planning_budget_left and queue_not_empty:
        proposal = pop_next_goal()
        feasible = apply_terrain_geometry_and_access_constraints(proposal)
        if feasible:
            commit_local_plan(feasible)            # 提交的是"空地 + 连接意图"，不是立即造楼
    lots = eligible_lots_in_active_growth_regions()
    choices = score(lots, 城市用途缺口, 玩家意图, 音乐角色缺口)
    if choices.has_viable_option:
        schedule_birth_at_phrase_boundary(choose_deterministically(choices))
    else:
        expose_reason_and_other_growth_options()   # 说清"缺临街面/坡太陡/用途不足"
```

**关键**：
- 生长是**在合法地块上出现**，不是在空地上撒点
- **几何不合法必须拒绝**；但**音乐规则不应提前消掉所有张力**——不能自动把所有"音乐不理想"的候选都剔掉
- 生成器要能**说清为什么没长**（比无声停止有用）

## 3. 四张关系图必须分开（调研的核心洞见）

**不能用一个邻接表回答全部问题。**

| 图 | 回答什么 | 用于 |
|---|---|---|
| **物理连通图** | 能否到达（道路、桥、坡道） | 交通、服务覆盖、可达性 |
| **地块边界图** | 属于哪里（行政/用途） | 社区 ID、功能区、统计 |
| **声学耦合图** | 彼此如何影响（距离核 + 遮挡 + 地形） | R/V、音频、诊断 |
| **编曲图** | 这一乐句谁演奏（角色槽） | 声部调度 |

| 空间层 | 音乐接口 | 不能混为一谈 |
|---|---|---|
| 建筑/地块 | 音级、音色、成熟、调音事件、占地 ID | 建筑数 ≠ 同时发声数 |
| 社区 | 主题、声部组、成熟轮廓、内部密度 | 用途不应锁死同音 |
| 多社区连接 | 主题呼应、对唱、交接 | **道路连通 ≠ 声学连通** |
| 全城 | 配器角色、进出场、动态留白 | 合成优化 ≠ 编曲好听 |
| 地形 | 反射/吸收/遮挡/环境声床 | **河流阻断交通，不自动证明阻断声音**（反之亦然） |

**社区 ID 稳定性**：社区 ID 不随音级或成熟变化重算。社区主题、声部组、建筑 ID 分别保存。地标吸收时保留来源地块与玩家音级历史。

## 4. 性能与数据结构

| 需求 | 方案 |
|---|---|
| 近邻查询 | 均匀桶或四叉树（不是全城两两） |
| 道路求交 | 局部脏区域更新 |
| 局部耦合 | 脏区域更新（新增一栋不重算全城） |
| 地块/街坊 | 空间索引 |
| 建筑身份 | 稳定 ID（不随音级变化） |

**禁止**：每次新增一栋就全城两两重算；通过听觉合并悄悄丢掉建筑身份。

**必须分别定义的数字**（调研要求）：
- 渲染建筑数
- 空间查询对象数
- 声学邻居数
- 声部组数
- 同时演奏数

这五个数**不是同一个**，见 `18_城市规模.md` §1。

## 5. 迁移影响（诚实评估）

**迁移不是把 `Vector2i` 换成 `Vector2` 就完成。**

| 现行位置 | 现状 | 需要新增/替换 |
|---|---|---|
| `city_growth.gd::advance` | 从锚点四邻格挑位置 | 从合法**地块**挑候选；用途/占地/可达/音乐分开处理；拆开社区 ID 与建筑 ID |
| `city_growth.gd::connected / conditions` | 共享格边连通与成熟判断 | **物理连通与声学关系分开**；连续空间索引与真实占地 |
| `city_roads.gd` | 道路主要阻断既有相邻关系 | 完整道路图、交点、路宽、桥、临街面、正面发展作用 |
| `city_generator.gd` | P0 固定规模布局 | 地形输入、中心与起始区域、生成版本与稳定 ID |
| `city_era.gd` | 地图范围扩张与来客 | 扩张边界连接、区域潜力、保护既有城市与遗产 |
| `city_demo_view.gd` | 固定等距画面与网格资产布局 | 连续世界位置、高差/基础、道路曲线、资产支持的朝向与遮挡排序 |

**受影响的下游**：存档、选择命中、迁移预览、道路操作、成形识别、声学、资产朝向、镜头——**都要接同一个世界坐标与对象身份模型**。

## 6. 推荐实施切片（来自调研）

**不引入完整第三方引擎，分层移植到 Godot。**

| 切片 | 内容 | 证明什么 |
|---|---|---|
| **1 · 河谷切片** | 一条河、一个缓坡、两岸可建地；主街 + 一处合法桥；几个用途不同的社区、商业节点、公共留白 | 看到"沿街建、沿岸留、沿坡转"；体验一次同时改变城貌与声音的操作 |
| **2 · 局部生长切片** | 玩家移动播种点或改变引力带 → 后续道路/地块/用途局部变化，已形成社区保留 | 至少两条选择同时造成可辨城貌与听感差异 |
| **3 · 几十社区规模切片** | 多中心、不同区形态、分尺度编曲 | 实测帧耗、空间查询、音频下溢，**决定预算** |

**只保留三项检查**（调研建议）：
1. 生成后完整占地不落水、不重叠
2. 主要功能区有正确道路可达
3. 同一操作确实带来预期城貌与声音变化

**城市感对照**：平原 / 河谷 / 坡地三个地形例子，同样的用途目标应形成不同道路与布局。

## 8. 当前技术合同：规划、事务与存档共用一个世界

本节是施工 AI 的唯一技术落点。研究稿、第三方源码和历史报告不能另写一套字段或提交顺序。

### 8.1 城市画像只提供结构倾向

每座城保存一个 `CityProfile`。它影响规划候选和形态统计，不直接指定某栋建筑，也不改变玩家音级规则。

状态：字段合同已定；第67轮通过 `TerraceNeighborhood` 接入可选 26 社区/104 地块/56 道路的规模切片，第68轮让湖盆/林岭/海湾平原改变台地退让与路段曲线，第69轮增加 8 个地形主题公共站点并接入入口步行覆盖，第71轮增加两岸蓝绿廊道并写入扩展快照，第72轮接入主/次/台地中心层级并参与主题排序，第73轮将庭院多边形作为派生形态缓存并显示，第74轮接入庭院内地 L2 落点和生长候选；完整画像接入、五种通用地形族独立规划仍为后续实现，不把当前河谷模板当作完整 `CityProfile`。

| 字段 | 作用 |
|---|---|
| `terrain_family` | 平原、河谷、坡地、港湾等地形族 |
| `center_count` / `center_levels` | 中心数量与主/次中心层级 |
| `street_pattern` / `block_scale` | 街道形态、街坊宽深分布 |
| `road_cross_section` | 路宽、人行道、绿化带和桥/坡道偏好 |
| `density_gradient` | 中心到边缘的密度和轮廓变化 |
| `mixed_use_ratio` | 住宅、商业、工业、公共用途配额倾向 |
| `green_network` | 岸线、山脊、公园和口袋绿地组织 |
| `transit_form` | 步行、车马、有轨车、公交的时代交通形态 |
| `architecture_style` | 建筑组件、朝向和轮廓套件 |
| `heritage_bias` | 历史保留、地标和遗产连接倾向 |

庭院、园林、港城、工业等形态预设必须同时改变路网、街坊、绿地、密度和建筑语法；不能只换色板。细节由固定子流派生，新增树、路灯或装饰不能重排既有建筑。

### 8.2 世界数据边界

| 对象 | 必须保存的最小字段 | 身份规则 |
|---|---|---|
| `WorldSnapshot` | schema/generator/spec/asset 版本、根种子、五子流计数器、地形、道路、地块、建筑、社区、待提交动作、音频帧与城市锚点 | 版本化；旧 schema 显式迁移或拒绝 |
| `TerrainField` | 原始高程、坡度、排水面、流量、水体/林地多边形 | 查询可栅格缓存，放置仍用连续几何 |
| `RoadGraph` | 稳定节点/边、中心线、宽度、共享交点、高程层、桥跨度和桥头 | 画面曲线从图派生 |
| `Lot` | 外环/孔洞、真实临街边、入口、用途、社区 ID、朝向和占地 | 预留地也有稳定 ID |
| `Building` | `building_id`、`lot_id`、`family_id`、`community_id`、位置/海拔/占地、音级、阶段、音色时代、历史来源 | 建筑身份不随音级、声部合并或视觉连片改变 |
| `Community` / `District` | 稳定规划社区、父子分裂关系、用途构成和派生标签 | 家族、社区、功能区分开 |
| `VoiceGroup` / `RenderVoice` | 前者保存成员和编曲信息；后者保存实际波形、增益、声像、滤波和排程签名 | 逻辑组不等于实际 PCM 节点 |

### 8.3 规划、事务和音频的提交顺序

一次玩家操作必须沿同一条纯计算路径走完预览和落定：

```text
玩家意图
→ 合法几何候选
→ 预测 WorldDelta
→ 等待对应音频/乐句提交帧
→ 局部道路与地块计划
→ 建筑/公共设施事件
→ 声学边变化
→ AudioPlan
→ 视觉揭示
```

`WorldDelta` 至少包含 `delta_id`、来源操作、请求帧、提交帧、几何变化、身份变化、声音变化、视觉变化和失败原因。额度动作、地形动作、桥、公共设施和生长都必须通过同一 `WorldDelta`；失败只回滚预测，不删除已有建筑或静默迁移。

### 8.4 交通对象不得混成一条数据

路线、站点、步行接驳和换乘分别保存：

- 路线引用有序道路边和方向；
- 站点拥有道路入口、停靠表现和时代类型；
- 步行接驳只沿真实可走边，不能跨无桥水面吸附；
- 换乘是独立代价和事件；
- 车辆沿路线弧长移动，改线时完成当前边或在站点接入，不能瞬移。

扩展台地道路还要求每条支路的首尾点与其 `from`/`to` 节点坐标一致；移动体按活动线路稳定轮询，弯道横向偏移保持在车道宽度内。该合同由 `tests/expanded_routes_contract.gd` 以 6 辆车连续模拟 60 秒验证。

第75轮补上运行时交通层：移动体把上一帧的道路、方向、优先级和位置交给同一批代理；同向跟车保持车辆/行人安全距，近距离会车按稳定优先级短暂停让，避免交点穿模和瞬移。公交在每条腿的起点记录稳定站点 ID，根据确定性载荷计算停站时间，并把载荷写入快照；视觉层用车窗灯和停站环揭示上下客。该层不改变路线拓扑，也不为交通对象新增常驻声部。

第76轮把扩展规划入口扩到两岸各 13 个台地社区，社区、地块、支路节点、中心、公共站点和绿廊继续由同一次规划生成并写入快照；公共空间新增口袋公园与远台公共节点，使 36 个社区仍有真实设施锚点。交通线路按连续台地节点动态收集，不再依赖固定 8 站上限。

第77轮在两岸台地外侧再生成 6 个内台社区，形成 48 社区、126 地块、124 道路和 16 公共站点的有纵深扩展。每个内台节点以最近台地节点为道路锚点，内台道路按稳定顺序串联；公共设施保留地随社区一起生成。交通层在台地回声线后动态收集内台节点，生成 `inland-line`，路线仍只引用真实路网边，不创建脱离道路的视觉捷径。

第78轮成长搜索改为按家族保留最近四个生长点作为局部前沿；空地、庭院和 L3 候选先按前沿半径裁剪，再执行原有道路连通、协和和形态条件。这样 48 社区在长时生长中不重复扫描全城历史候选，24 个乐句探针达到 333 栋；该裁剪只影响搜索顺序和计算量，不改变建筑身份、道路拓扑或声音公式。公共设施音乐入口由 `ContinuousSynth` 保留一个节奏槽，形成“先有公共空间、后长满房屋”的可听反馈。

第80轮把长时规模探针延长到36个乐句：48社区由95栋增长到400栋，庭院缓存保持85个，仍由合法候选和运行时资源决定边界。现代交通同时加入独立汽车代理；时代Ⅰ—Ⅳ只生成马车/有轨车，时代Ⅴ才揭示汽车，汽车与公交共享道路安全距、会车让行和线路拓扑，汽车不占用公交停站驻留规则。

第81轮继续跑72个乐句，48社区由95栋增长到531栋，庭院缓存保持84个，进入500–600栋目标区间。五类地形的基础公园、台地公园、口袋园和公共设施使用不同的稳定命名组合，高地峡谷的设施明确表达峡谷、关隘与风口；这些对象仍沿同一公共保留地、入口步行覆盖和节奏槽合同生成。

第82轮把 `terrain_family` 传入主题与公共设施节奏元数据。河谷保持原节奏作为基线，湖盆采用回声间隔，林岭采用疏朗起拍，海湾采用切分起拍，高地采用阶梯起拍；五类主题在一个完整乐句内产生不同起拍签名，仍共享同一渲染声部预算和淡入淡出合同。

第83轮将现代交通加入扩展路线回归：6辆公交与3辆汽车共用四条真实线路连续模拟60秒，汽车速度提高后仍保持有界单步移动和道路偏离；公交站点驻留与汽车巡航分开，时代门槛由世界状态控制。

第84轮加入 `City DNA v1` 可读导出。导出从同一个 `capture_city()` 快照提取种子、地形、建筑、规划道路/地块/社区、绿廊、中心、公共设施、公交线路和 `ContinuousSynth` 的主题/应答/节奏；Vector2 与 PackedVector2Array 统一转成 JSON 数组，导出文件通过临时文件写完后再改名发布，不影响可恢复的二进制作品存档。

第85轮把可读导出补成 `resonance_audio_plan_v1`：沿用同一份世界快照，写出 `phrase_frames`/`sample_rate` 时间基准、世界事件、作者决策、待播 `sound_events` 与已应用 `sound_trace`。音频模型快照同时保存 `sound_trace`，旧版本缺字段时按空数组恢复；因此导出的城市结构和声音事件可以被外部工具按稳定时间轴读取，仍不宣称已完成完整 RenderVoice 跨版本重渲染。

第86轮把长时扩展推进到 585 栋、48 社区和 85 个庭院。`ContinuousWorld.settle()` 不再每个乐句无条件重建派生庭院/街墙缓存：结构操作立即刷新，自然成长隔句刷新；建筑身份、占地合法性和音乐结算仍按每个乐句执行。与此同时修复连片组件分段在超过 6 栋时的数组结束下标错误，避免大城运行时错误。

第87轮把 `City DNA v1` 从展示副本推进为可继续创作的 JSON：`runtime.model` 保存与二进制作品相同的连续世界/音频模型状态，另存渲染游标和镜头；`CityArchive.read_dna()` 校验 schema 并返回可恢复状态，`latest_dna()` 按时间选择最近完整导出。Demo 菜单的“继续最近DNA”直接走同一 `_start_world()` 与音频时钟恢复路径。JSON 中的 Vector2/Packed 数组仍由导出层转成普通数组，音频模型恢复时兼容这两类状态。

第89轮用实际 `continuous_valley.tscn` 做 DNA 往返：加载 JSON 时恢复 Demo 镜头 `pan`、`SampleRenderer` 的 `_pad_stereo_` 状态、合成器 `stereo` 节点和移动体路径，再由同一 `_start_world()`、`scenery.restore()` 与 `AudioClock.start_output()` 接回运行。该路径已由 `tests/dna_demo_roundtrip.gd` 覆盖，JSON 不再只是离线展示格式。

第90轮把移动体推进从恒定巡航改为可读的运动状态：公交、马车、有轨车和汽车按载具类型使用不同加速度，停站和让行会逐步刹车；路径采样按最大角速度缓转，`advance()` 输出前再做一层每帧朝向限幅，避免急弯或换腿时的瞬时反向。`motion_speed` 随移动体快照保存，旧 DNA 缺少该字段时按零速兼容恢复；`tests/round90_motion_realism.gd` 覆盖连续采样、速度上限、加速度步进、转向和快照恢复。

第105轮补上交通的目的地意图：现代汽车优先从功能区中心生成可达目标，尝试目标时跳过断河或断路路径，避免为了“跨城”而产生隐形瞬移；行人按确定性轮换选择商街、公园、公共设施和住宅入口，目的地类别与中文旅程意图随移动体快照保存。意图只改变路线选择和视觉反馈，不新增经济模拟或常驻声部。

第106轮把功能区从派生标签推进为实际用途：`TerraceNeighborhood` 在扩展城保留少量工业地块，`ContinuousWorld` 生成真实工业建筑并从跨社区成员聚合工坊带；公共文化站点聚合为文化声场。`ContinuousSynth` 对 `workshop` 使用更密的机械脉冲，对 `choir` 使用疏朗的合唱间隔；`CityTraveler` 会将两类中心纳入现代汽车目的地，旧时代仍按时代门槛使用马车/有轨车。工业建筑、功能区和角色元数据均进入世界快照与 DNA 分叉链，验证见 `tests/round106_industrial_cultural_zones.gd`。

第107轮把换乘从静态线路关系推进为运行时旅程：`_annotate_transfers()` 从每条线路的真实 `stops` 计算共享站点与目标线路，公交、马车和有轨车到共享站点后按稳定序列切换线路，保留当前道路完成后再接入新线路；换乘会增加可读停站、目的线路和 `transfer_count`，并随移动体快照恢复。共享站牌在同一道路节点只绘制一次，用金色双环表示换乘节点；汽车仍不借用公交线路，时代门槛保持古典马车、工业有轨车、现代公交/汽车。

第108轮把停站载荷推进为容量交换：车辆根据站点所属中心的商贸、工坊、文化、公共绿地和换乘角色计算确定性需求目标，在停站时先下车再上车，`boarded`、`alighted`、`transfer_passengers` 与 `passenger_load` 一起写入移动体输出和快照；交换量增加停站时长，车窗灯继续显示当前载荷。当前切片覆盖容量与站点需求，票制、跨多个乐句的乘客目的地迁移和长期需求仍留在后续内容层。

第109轮把交通反向接入城市成长：`_transit_growth_bonus()` 读取真实线路站点和换乘站，对靠近站点的商业/工业候选提高成长排序，对远离路网的候选保持原有 L1/L2/L3 规则。交通不会替换协和、道路连通或地形合法性条件，只在同层级候选间改变落点，因此公交密度会逐句形成可读的功能带，并在下一次 `refresh_functional_zones()` 后进入商贸/工坊与节奏角色。

第91轮把线路站点变成可读的视觉骨架：`ValleyScenery` 遍历活动线路的 `stops`，从 `CityRoadNetwork.nodes` 放置唯一站牌；同一节点被多条线路共享时只保留一个标记。站牌不创建额外道路或声部，颜色只表达线路身份，公交移动体继续用停站环和载客窗灯表达当前状态。

第79轮把第五类 `highland_pass` 接入同一生成入口：窄河、强坡地、弯折河线和更大的台地退让由地形族参数决定，公共设施、绿廊、中心与 `inland-line` 不复制另一套规划器。这样切换地形会同时改变水体、声学、支路几何和可视色调，存档只需保存稳定的地形族与种子。

公共设施覆盖使用入口到入口的步行图；首片交通已按站点功能计算容量交换，完整票制和用途配额另算。交通事件只占已有节奏/环境预算，不为每辆车创建常驻声部。

### 8.5 存档与回放边界

存档写临时文件，回读校验后才替换当前版本；保留上一份有效文件，损坏文件不得覆盖有效档。稳定 ID 不来自数组位置，坐标保存为数值，超出 JSON 安全整数的值保存为字符串。回放由稳定事件 ID、提交帧和同版本随机子流驱动；悬停、试听和预览不消耗正式随机流。

AudioPlan 的字段、排序和 PCM 提交规则见 `12_声音架构.md` §10 与 `spec.audio.md` A26；存档按 `spec.run.md` 的 R2a 和本节字段保存。新增字段先更新本节和所属 spec，再改代码。
