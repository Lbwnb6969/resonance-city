# 19 · 城市生成管线：六层结构

> 2026-10-09 新增。本文回答 `技术调研-地形道路与多功能城市生成_2026-10-09.md` 提出的缺口：
> "环带撒点解决不了街坊与临街面；河道缺排水拓扑；桥需要真正几何；家族≠社区"。
> 本文给出**从地形到建筑**的完整六层管线，取代"只在锚点周围撒点"的单一生成方式。

---

## 1. 为什么需要分层

`14_城市生长.md` 描述的"环带采样 + 评分"只能回答"下一栋房子放哪"，回答不了：

- 房子朝哪？（临街面）
- 这一片是住宅还是商业？谁决定？
- 为什么这里有一条主街，那里没有？
- 河上那座桥怎么来的？

**只撒点长不出城市，只会长出一团房子。**

正确的顺序是（来自调研的核心结论）：

```
① 地形      → 高程、坡度、水系、可建性
② 骨架      → 城市中心、主路网、连接意图
③ 社区/功能区 → 区域划分、用途配额、区位偏好
④ 街坊      → 道路闭环围出的街区
⑤ 地块      → 街坊内切分，临街面、朝向、容量
⑥ 建筑 + 生长事件 → 在地块上出现，接入音乐
```

**每一层都向下一层提供约束，向下不越级。**

---

## 2. 分层详解

### ① 地形层

见 `13_地形与自然.md` 与 `spec.terrain.md`。

**关键修正（来自调研）**：河道不能只"从最高点按梯度流向海"——会在局部低洼或平地停住。需要**排水拓扑**：

| 步 | 规则 |
|---|---|
| 1 | 填洼（priority-flood）：把无出口的洼地填平，记录哪些洼地变成**湖** |
| 2 | 保留priority-flood无环父图；有下降取D8最陡邻居，填平区沿父图指向出口，不能在平台重新选出环 |
| 3 | 累积流量；流量 > 阈值的水道 → 河；宽度 ∝ `sqrt(流量)` |
| 4 | 河流终止于海或湖；**不允许终止于平地** |
| 5 | 河两岸留缓冲带（宽度 ∝ 河宽），缓冲带内不可建 |
| 6 | **第一切片可用明确控制的河谷模板**，先解决城水配合，不追求通用水文 |

**内部采样栅格**：空间对玩家是连续的，但地形查询可以缓存在栅格上（如 4×4 子格）。**采样在栅格、放置是连续**——两者不矛盾。

### ② 骨架层

**先定中心与连接，再长房子。**

| 步 | 规则 |
|---|---|
| 1 | 在可建区选 **1–3 个城市中心**（大型城市多中心，不都朝一个种子收缩） |
| 2 | 计算**可达性场**（从中心沿可建区扩散，代价 = 距离 + 坡度 + 绕行） |
| 3 | 用**方向场**（tensor field）生成主路候选：平地用规则网格场，坡地用等高线方向，中心附近混合径向场 |
| 4 | 主路经**局部约束**修正：越界/水域/坡度上限 → 拒绝或转向；与已有路接合 → 吸附为共享节点；过短/急转/重复 → 拒绝 |
| 5 | 交点必须是**共享节点**（"画面交叉"不算连通） |
| 6 | 主路整形后**重新检查**水域/占地/交点；曲线渲染从路网图派生，保留拓扑↔几何对应 |

**桥**：河是"带跨越属性的特殊边"。桥必须同时满足：两岸落脚点存在、跨度合理、桥头能接路。**玩家划过一条河不自动成桥**——它只是提出桥的候选，仍需几何成立。

### ③ 社区与功能区层

**这一层是调研指出的最大缺口：家族 ≠ 社区。**

| 概念 | 定义 | 稳定性 |
|---|---|---|
| **家族**（Family） | 一个共鸣点源出的全部建筑 | 随生长变化 |
| **社区**（Community） | 沿可建邻接图发展的规划区域，允许混合用途 | **稳定 ID，不随音级/成熟变化重算** |
| **功能区**（District） | ≥2 个活跃社区 + 用途/公共设施/线路构成的分区 | 由章程、锚点、成员用途和线路派生，稳定 `zone-*` ID |

Demo 第104轮已落地第一层派生实现：居住带、商贸核心、公共绿地带、混合中心和换乘节点从活跃社区、建筑用途、绿廊、公共站点与交通线路自动更新；功能区不重写建筑或社区身份，只为 UI、统计和编曲提供稳定角色。第106轮进一步让扩展城的部分内台/台地地块实际使用 `industrial`，由多个工业建筑派生稳定 `zone-industrial-core` 工坊带；活跃文化公共站点派生 `zone-cultural-core` 文化声场。两者分别映射 `workshop` 与 `choir` 音乐角色，并允许汽车将其作为有意图旅程目的地；完整用途配额仍属于后续施工。

**社区划分算法**：
1. 从**锚点**（中心/地标/玩家播种点）沿**可建邻接图**加权扩张
2. 扩张代价 = 道路穿越 + 坡度 + 岸线 + 边界
3. **不用欧氏距离 Voronoi**（会把隔河两岸划成同一片）
4. 小区合并，大区按支中心分裂
5. 用主路/河岸/山脊作为**可见边界**

**用途分配**（来自 Watabou 区位评分 + Citybound 用地模型）：

| 用途 | 区位偏好 | 内部形态 | 需要保留的关系 |
|---|---|---|---|
| 住宅 | 稳定可达、靠绿地、避强干扰 | 小地块、院落、短巷 | 能到商业/公共中心 |
| 商业 | 主街、广场、多社区连接点 | 连续临街面、较密 | 服务多个社区 |
| 工业/工坊 | 足够大平地、骨干连接、边缘 | 较大地块、疏密分明、缓冲带 | 与住宅有取舍 |
| 公共/文化 | 中心、重要节点、景观焦点 | 大地块、显著留白 | 有服务范围 |
| 绿地/自然 | 岸线、山脊、碎角、生态走廊 | 连续留白 | 参与区划边界 |

**混合用途**：同一个住宅社区可以有一条商业街或一座公共建筑。**用途不应把所有房屋锁成永久同音**——用途决定建筑"长什么样"，音级仍由玩家与和声决定。

### ④ 街坊层

- 从平面道路图提取**闭合街坊**（按转角遍历闭环）
- 扣除路宽、岸线、公共保留区
- **没有闭环的边缘街道**：沿道路布置带状地块（不能因为没闭环就永远不长房子）

### ⑤ 地块层

每个地块记录：用途、容量、**临街边**、入口、占地多边形、坡地基础、社区 ID。

- 沿最长边递归切分，控制最小面积、角度扰动、尺寸变化、留空概率
- **临街面必须真实可得**：找不到真正街面时不能"退回最长边"当成临街
- 建筑朝向以**街面为基准**，同一区域只做小幅变化

**地块分三层落点**（2026-10-10 新增，见 `01_执行规格/spec.fabric.md` 表 FB1）：

| 层 | 来源 | 说明 |
|---|---|---|
| **L1 临街地块** | 本层产出，临街边 ≥2 个方向 | 主力生长位 |
| **L2 内地块** | 本层产出，临街边 =1；庭院内地按 FB2 例外，不需基础邻居条件 | 内部加深肌理、生成庭院 |
| **L3 空地** | **不在本层**——由 `14_城市生长.md` 的环带采样产生 | 任意合法陆地，速率减半、冻结在群 |

**为什么 L3 不在本层**：地块层是"有路才切地"的管线，
而玩家**可以在任何合法陆地上播种**（这是支柱 E 的要求）。
两条路都必须存在：**地块管线产生城市肌理，环带采样保证落点自由**。

**资产限制（必须正视）**：固定视角的 2.5D 贴图**不能通过任意旋转变成正确的另一侧建筑**。
→ 连续布局**先只选资产支持的朝向**，并让街面与朝向模板配合；需要自由街道方向时，**必须补对应视角的资产**或改用可投影几何。这是本层的硬约束，不能靠旋转贴图绕过。

**连片资产需求**（2026-10-10 新增）：连片需要三类新资产或新绘制层——
**山墙贴片**（无窗无门）、**檐口融合的描边层**、**连排顶面合并贴图**。
它们**属于 P1 资产范围**，且必须过 §质量红线 的三格测试。
**在连片资产到位之前，不得声称"城市读作一片"已达成。**

### ⑥ 建筑与生长事件层

见 `14_城市生长.md`。与音乐结合的关键：

```
on_city_tick(player_intent):
    update_local_planning_fields(player_intent)   # 引力带/播种/踩路改变局部目标
    enqueue_connection_and_land_use_goals()
    while planning_budget_left and queue_not_empty:
        proposal = pop_next_goal()
        feasible = apply_terrain_geometry_and_access_constraints(proposal)
        if feasible:
            commit_local_plan(feasible)            # 提交的是"空地 + 连接意图"，不是立即造楼
    lots = eligible_lots_in_active_growth_regions()
    choices = score(lots, 城市用途缺口, 玩家意图, 音乐角色缺口)
    if choices.has_viable_option:
        schedule_birth_at_phrase_boundary(choose_deterministically(choices))
    else:
        expose_reason_and_other_growth_options()   # 说清"缺临街面/坡太陡/用途不足"
```

**关键**：
- 生长是**在合法地块上出现**，不是在空地上撒点
- **几何不合法必须拒绝**；但**音乐规则不应提前消掉所有张力**——不能自动把所有"音乐不理想"的候选都剔掉
- 生成器要能**说清为什么没长**（比无声停止有用）

## 3. 四张关系图必须分开（调研的核心洞见）

**不能用一个邻接表回答全部问题。**

| 图 | 回答什么 | 用于 |
|---|---|---|
| **物理连通图** | 能否到达（道路、桥、坡道） | 交通、服务覆盖、可达性 |
| **地块边界图** | 属于哪里（行政/用途） | 社区 ID、功能区、统计 |
| **声学耦合图** | 彼此如何影响（距离核 + 遮挡 + 地形） | R/V、音频、诊断 |
| **编曲图** | 这一乐句谁演奏（角色槽） | 声部调度 |

| 空间层 | 音乐接口 | 不能混为一谈 |
|---|---|---|
| 建筑/地块 | 音级、音色、成熟、调音事件、占地 ID | 建筑数 ≠ 同时发声数 |
| 社区 | 主题、声部组、成熟轮廓、内部密度 | 用途不应锁死同音 |
| 多社区连接 | 主题呼应、对唱、交接 | **道路连通 ≠ 声学连通** |
| 全城 | 配器角色、进出场、动态留白 | 合成优化 ≠ 编曲好听 |
| 地形 | 反射/吸收/遮挡/环境声床 | **河流阻断交通，不自动证明阻断声音**（反之亦然） |

**社区 ID 稳定性**：社区 ID 不随音级或成熟变化重算。社区主题、声部组、建筑 ID 分别保存。地标吸收时保留来源地块与玩家音级历史。

## 4. 性能与数据结构

| 需求 | 方案 |
|---|---|
| 近邻查询 | 均匀桶或四叉树（不是全城两两） |
| 道路求交 | 局部脏区域更新 |
| 局部耦合 | 脏区域更新（新增一栋不重算全城） |
| 地块/街坊 | 空间索引 |
| 建筑身份 | 稳定 ID（不随音级变化） |

**禁止**：每次新增一栋就全城两两重算；通过听觉合并悄悄丢掉建筑身份。

**必须分别定义的数字**（调研要求）：
- 渲染建筑数
- 空间查询对象数
- 声学邻居数
- 声部组数
- 同时演奏数

这五个数**不是同一个**，见 `18_城市规模.md` §1。

## 5. 迁移影响（诚实评估）

**迁移不是把 `Vector2i` 换成 `Vector2` 就完成。**

| 现行位置 | 现状 | 需要新增/替换 |
|---|---|---|
| `city_growth.gd::advance` | 从锚点四邻格挑位置 | 从合法**地块**挑候选；用途/占地/可达/音乐分开处理；拆开社区 ID 与建筑 ID |
| `city_growth.gd::connected / conditions` | 共享格边连通与成熟判断 | **物理连通与声学关系分开**；连续空间索引与真实占地 |
| `city_roads.gd` | 道路主要阻断既有相邻关系 | 完整道路图、交点、路宽、桥、临街面、正面发展作用 |
| `city_generator.gd` | P0 固定规模布局 | 地形输入、中心与起始区域、生成版本与稳定 ID |
| `city_era.gd` | 地图范围扩张与来客 | 扩张边界连接、区域潜力、保护既有城市与遗产 |
| `city_demo_view.gd` | 固定等距画面与网格资产布局 | 连续世界位置、高差/基础、道路曲线、资产支持的朝向与遮挡排序 |

**受影响的下游**：存档、选择命中、迁移预览、道路操作、成形识别、声学、资产朝向、镜头——**都要接同一个世界坐标与对象身份模型**。

## 6. 推荐实施切片（来自调研）

**不引入完整第三方引擎，分层移植到 Godot。**

| 切片 | 内容 | 证明什么 |
|---|---|---|
| **1 · 河谷切片** | 一条河、一个缓坡、两岸可建地；主街 + 一处合法桥；几个用途不同的社区、商业节点、公共留白 | 看到"沿街建、沿岸留、沿坡转"；体验一次同时改变城貌与声音的操作 |
| **2 · 局部生长切片** | 玩家移动播种点或改变引力带 → 后续道路/地块/用途局部变化，已形成社区保留 | 至少两条选择同时造成可辨城貌与听感差异 |
| **3 · 几十社区规模切片** | 多中心、不同区形态、分尺度编曲 | 实测帧耗、空间查询、音频下溢，**决定预算** |

**只保留三项检查**（调研建议）：
1. 生成后完整占地不落水、不重叠
2. 主要功能区有正确道路可达
3. 同一操作确实带来预期城貌与声音变化

**城市感对照**：平原 / 河谷 / 坡地三个地形例子，同样的用途目标应形成不同道路与布局。

## 8. 当前技术合同：规划、事务与存档共用一个世界

本节是施工 AI 的唯一技术落点。研究稿、第三方源码和历史报告不能另写一套字段或提交顺序。

### 8.1 城市画像只提供结构倾向

每座城保存一个 `CityProfile`。它影响规划候选和形态统计，不直接指定某栋建筑，也不改变玩家音级规则。

状态：字段合同已定；连续河谷已接画像参数、公共设施、绿廊、中心和庭院等切片。完整画像与五地形族独立通用规划仍待实现；当前范围见 PROJECT，不能把共用模板当通用生成已完成。

| 字段 | 作用 |
|---|---|
| `terrain_family` | 平原、河谷、坡地、港湾等地形族 |
| `center_count` / `center_levels` | 中心数量与主/次中心层级 |
| `street_pattern` / `block_scale` | 街道形态、街坊宽深分布 |
| `road_cross_section` | 路宽、人行道、绿化带和桥/坡道偏好 |
| `density_gradient` | 中心到边缘的密度和轮廓变化 |
| `mixed_use_ratio` | 住宅、商业、工业、公共用途配额倾向 |
| `green_network` | 岸线、山脊、公园和口袋绿地组织 |
| `transit_form` | 步行、车马、有轨车、公交的时代交通形态 |
| `architecture_style` | 建筑组件、朝向和轮廓套件 |
| `heritage_bias` | 历史保留、地标和遗产连接倾向 |

庭院、园林、港城、工业等形态预设必须同时改变路网、街坊、绿地、密度和建筑语法；不能只换色板。细节由固定子流派生，新增树、路灯或装饰不能重排既有建筑。

### 8.2 世界数据边界

| 对象 | 必须保存的最小字段 | 身份规则 |
|---|---|---|
| `WorldSnapshot` | schema/generator/spec/asset 版本、根种子、五子流计数器、地形、道路、地块、建筑、社区、待提交动作、音频帧与城市锚点 | 版本化；旧 schema 显式迁移或拒绝 |
| `TerrainField` | 原始高程、坡度、排水面、流量、水体/林地多边形 | 查询可栅格缓存，放置仍用连续几何 |
| `RoadGraph` | 稳定节点/边、中心线、宽度、共享交点、高程层、桥跨度和桥头 | 画面曲线从图派生 |
| `Lot` | 外环/孔洞、真实临街边、入口、用途、社区 ID、朝向和占地 | 预留地也有稳定 ID |
| `Building` | `building_id`、`lot_id`、`family_id`、`community_id`、位置/海拔/占地、音级、阶段、音色时代、历史来源 | 建筑身份不随音级、声部合并或视觉连片改变 |
| `Community` / `District` | 稳定规划社区、父子分裂关系、用途构成和派生标签 | 家族、社区、功能区分开 |
| `VoiceGroup` / `RenderVoice` | 前者保存成员和编曲信息；后者保存实际波形、增益、声像、滤波和排程签名 | 逻辑组不等于实际 PCM 节点 |

### 8.3 规划、事务和音频的提交顺序

一次玩家操作必须共用几何/规则计算走完预览和落定。下图是结构提交链；L2 局部声音可在尚未渲染拍点先提交 AudioPlan，使用同一来源身份但不同提交帧，不等待本链完成，也不提前写 R/V：

```text
玩家意图
→ 合法几何候选
→ 预测 WorldDelta
→ 等待对应音频/乐句提交帧
→ 局部道路与地块计划
→ 建筑/公共设施事件
→ 声学边变化
→ AudioPlan
→ 视觉揭示
```

`WorldDelta` 至少包含 `delta_id`、来源操作、请求帧、提交帧、几何变化、身份变化、声音变化、视觉变化和失败原因。额度动作、地形动作、桥、公共设施和生长都必须通过同一 `WorldDelta`；失败只回滚预测，不删除已有建筑或静默迁移。

声音准备同属该任务：独占结算完成后深复制建筑声音投影，模型原版本提交时接纳，迟到输入或未完成任务不采用该投影；发布记录只读，调音覆盖复制对应记录，运行时投影不进DNA。公开建筑声音接口保留独占副本。结构准备进入工作线程池：主线程复制当前WorldSnapshot，后台只使用独占副本计算下一乐句；大的声学边与环境缓存根冻结为只读，后台复制为独占可写根，其他派生容器沿原独占副本。主线程新环境查询写environment_pending小增量，读取先增量后基底；下一次捕获冻结增量，后台按原键合入基底。同步回退的声学写入先复制冻结根，图重建/恢复更换根而不清空已发布容器；新增查询不改变任务输入版本或正式随机流。字段为运行时派生缓存、不进DNA，键仍为原实体对/精确坐标。发布后的庭院几何、声学边与路径记录只读共享，社区标签附在庭院选择副本上。验证入口为round132_frozen_capture.gd（并发隔离、增量、迟到输入、继续PCM）与round132_large_supply_live.gd（城市实供音）。结果附提交帧、乐句/操作版本及客流修订。请求、取消或客流变化让旧结果失效，到原定帧才交换城市状态，旧状态由后台任务回收，画面继续等实际可听帧揭示。任务对象、线程句柄和派生缓存不进入DNA；加载、切城与退出先回收旧任务。后台未及时完成时保留原同步结算语义，不能丢失输入或改写已输出PCM。当前每句一个成长任务，不代表家族成长已能无依赖地并行；后续按空间分区拆独立查询，再按稳定身份合并。

### 8.4 交通对象不得混成一条数据

路线、站点、步行接驳和换乘分别保存：

- 路线引用有序道路边和方向；
- 站点拥有道路入口、停靠表现和时代类型；
- 步行接驳只沿真实可走边，不能跨无桥水面吸附；
- 换乘是独立代价和事件；
- 车辆沿路线弧长移动，改线时完成当前边或在站点接入，不能瞬移。

扩展台地道路还要求每条支路的首尾点与其 `from`/`to` 节点坐标一致；移动体按活动线路稳定轮询，弯道横向偏移保持在车道宽度内。该合同由 `tests/expanded_routes_contract.gd` 以 6 辆车连续模拟 60 秒验证。

以下合同从历次切片提炼，轮次证据保留在[归档](../废弃/文档/2026-10-10_正文终审前/城市生成管线历史实施记录.md)，完成范围见 PROJECT：

- 公共设施覆盖使用入口到入口的真实步行图；容量按 E7-a 分配，不重复计服务。公共设施可先于社区三栋成形进入既有节奏槽；绿廊、中心、站点与线路仍从同一次规划生成，不设置固定 8 站限制。
- 道路 `from/to` 必须与路径端点一致；内台路线只引用真实道路边。车辆/行人使用安全距、加速度、限转向和稳定让行优先级，改线在站点或完成当前边后接入。共享站牌以稳定节点 ID 去重，不生成视觉捷径。
- 时代控制载具：Ⅰ–Ⅲ 马车、Ⅳ 有轨车、Ⅴ 公交/汽车。公交站点交换记录载荷、上下客、换乘、乘客目标站与停站时间；汽车沿可达功能中心往返/停靠，行人轮换真实入口并避免立即折返。上述运动状态随快照保存，不凭视觉位置重建身份。
- 带衰减的站点需求记忆参与后续载荷、同层候选成长偏好与换乘节奏密度；交通不覆盖地形/协和/道路合法性，不为每辆车创建常驻声部。工业/商业用途配额由真实用途锚点与成员规模派生，工业缺口优先；文化设施容量独立，不能以已有服务代替完整文化用途配额或票制。
- 成长搜索使用最近四个家族前沿和局部候选；分层/合法性先于同层偏好。逻辑成员、相位与音高历史不因 70 RenderVoice 代表轮换消失，完整预算、淡化和恢复沿 A26。
- 道路段、地块、公共地、最短路树、声学/服务与庭院锚点均为派生缓存；保留原候选顺序和精确几何判定。新增邻居只补新组合，移动/移除/公共几何变化走完整重建；桥先更新拓扑再作本句成长。不能由缓存序号生成稳定 ID。
- 显示使用可听帧前的旧城副本，到帧释放；投影/成熟阴影与交通接入缓存不改变命中、揭示或快照。供音补偿仍按未渲染 PCM 空位、事件帧和原缓冲工作；结构峰值与供音成本分别测，不用无下溢宣称已达 60fps。

#### 8.4-a · 玩家公交线路（第164轮）

玩家可以在连续空间沿真实道路逐站选择站位，至少两站后提交。站位先由 `CityRoadNetwork.access` 投影到道路，并保留稳定站 ID、道路 ID 与弧长；靠近既有节点或作者站时复用该 ID，不因数组顺序生成身份。线路预影使用 `walking_route` 得到每一段真实道路路径，默认按玩家站序往返，首站再次选择则形成闭环；跨水面、无路或拓扑已变化时拒绝。物理道路和节点永远不因设站被切割或新增。

作者站点与作者线路分别保存为 `authored_transit_stops`、`authored_transit_lines`；运行时 `transit_lines` 继续保留 `stops`（车辆往返行程）、`legs`（`from`/`to`/`path`/`length`）和 `edges`，并附 `intent_stop_ids`/`route_stops` 标明玩家原始站序。提交只排入下一乐句，边界重新核验道路拓扑和站位。站点覆盖、社区关系、换乘和客流均读取实际道路可达结果；不会创建地形捷径、全城增益或常驻新声部。旧快照缺少作者字段时按空恢复，原有自动线路保持不变。

显示绘制分为保留地形、实时流水、保留城市地面和动态建筑/操作层。保留层缓存本地投影和绘制命令，平移只改共享变换，缩放仅更新屏幕固定线宽；地形身份与几何变化更新地形层，实际可听城身份/乐句触发城市地面六部分的精确依赖比较，只有道路、中心、绿廊、公共设施、占地或庭院街墙实际绘制内容改变才更新对应CanvasItem；地形变化全量失效，公共描边依赖缩放。绘制顺序与旧整层相同，投影只留活跃几何，黑屏恢复由引擎自动重绘。社区名称、地标候选与容量摘要按同一可听城缓存，流水/成长动画继续按音频帧运行；显示缓存不进入WorldSnapshot/DNA，不消耗正式随机流。

移动体道路接入缓存区域候选超集，不量化位置或缓存每个移动坐标的结果；仍按精确最近点、原始道路段顺序、同距容差和水体阻隔选择。候选只读，拓扑变化失效，工作线程持有独占缓存容器；远离道路沿原扩大查询。路口代理裁剪只能提前排除不满足既有距离/优先级条件的对象，不能省略邻近冲突。站牌/灯/公共建筑小景可保留绘制命令，揭示透明度、树风和移动体继续由实际可听帧更新。

建筑阴影按固定地面块缓存R8最大覆盖并集，块以整型地面坐标识别、带相邻采样边维持线性滤波；成熟覆盖只合并新增成员。新增建筑先校验整批遮罩键均未存在、批内不重复，再只登记新增补丁及其相交块；量化覆盖为0时保留几何但不创建/重传全透明贴图，首个显示帧已开始揭示时直接按实际可听进度合成相关块。失败不提交部分成员，调用方使用完整成员核对；旧记录的遮罩键不因其他新房插入而失效。可听透明度变化只提交变化建筑及相交块，不遍历或上传整城；成员移除、移动、类型/比例变化或揭示回退只重建受影响块，空块释放。镜头仅更新共享变换，不改变遮罩身份。原生与脚本后端均只读发布既有遮罩数组，显示缓存不进世界/DNA，不改随机流或提交帧。验证入口为 tests/round131_local_shadows.gd（R8、跨块滤波、增量显现及失效）和 round131_large_supply_live.gd（实际城市与供音）；新增登记、迟到首帧、重排与透明块语义的现行验证为round138_transparent_shadows及round138_regional_supply_live；旧131比较器同步支持未上传透明块。GPU线性滤波对照允许1/255色阶差。

阴影补丁按纹理路径与最终像素尺寸共享缩放后的alpha，位置和整型边界仍逐补丁精确计算；只读字节数据不参与世界身份，按本次活跃补丁裁剪。城市地面保留相同地形身份下的本地投影，描边闭线必须复制投影数组，重绘后只留仍使用的几何；地形噪声/相位/家族/配置变化使缓存失效。成熟建筑共用一个unshaded CanvasItemMaterial，未成熟建筑保留独立揭示Shader，回退重新取得独占Shader，不改变一拍揭示、命中、色调和深度排序。缓存降低重复准备及材质数量，冷启动成本与整帧另测，不能据共享材质宣称120fps。验证入口为round134_shared_masks、round134_ground_projection、round134_growth_batching和round134_large_supply_live。

交通邻居只在当前帧建立道路桶与空间桶；同道路保留全部代理，异道路只剔除不可能同时接近共享路口的代理，合并后恢复原遍历顺序。精确位置或路网运行时代际不符时使用全量代理及权威道路接入；代际标记不进WorldSnapshot，拓扑不变保留身份。静态小景投影按位置/地形身份复用，移除公共布局同时删除缓存，移动体与动画仍逐帧更新。新线路无法从已抵达站点接入时等待并重试，不提交空路径或跨水跳跃。验证入口round135_traffic_equivalence与round135_large_supply_live；组件索引规模与合法城市规模分开记录。

三河段性能样例复用受控街坊模板并重映射所有规划ID，按当地河心/岸宽保持道路及占地距岸；每个城市私有settings后再延长矩形地形，不能污染其他世界。新增河段沿两岸纵向连通，跨河仍只依靠桥。正式包包含52次真实成长所得1,511栋压缩快照，恢复精确二进制几何和随机流，载入后音频游标从样例乐句继续；包检查包含该数据的哈希及Shift+E入口。

客流按spec.city的乐句合同归集；后台只按捕获时观察队列长度拆出晚到后缀，在结果交换后按原顺序合入。旧可听视图只转交本次推进新增的观察，不移走历史快照数据；玩家操作仍校验版本。验证入口round136_regional_contract、round136_transit_commit及round136_regional_supply_live。

Windows阴影最大覆盖合并使用CityMaskUnion的原生批处理，每批按补丁原顺序计算同一R8最大值和整数揭示舍入，并返回写时复制输出；成熟与未成熟覆盖分批，不能逐补丁复制整城遮罩。几何、成员失效、可听揭示和显示缓存仍由原显示层维护；无原生后端时使用等价脚本循环，统计与对象句柄不进DNA。

工作线程同时从同一输入快照准备旧城显示副本；它沿原恢复规则重建成员顺序，独占发布前的庭院/声学/服务派生值，不消耗正式随机流。输入版本和提交帧有效且任务已完成时，声音边界引用原不可变快照，显示直接交接准备副本；迟到玩家输入/取消或任务未就绪保留原同步与重建语义；客流按前述乐句归集合并。回收只释放输入快照引用，不清空仍待可听帧的历史字典。显示中的待播操作/交通记忆只修改显示副本，原快照独立；存档先剔除运行时view/derived，再深拷贝原序列化历史，旧档沿原重建路径恢复。

地图名称使用独立CanvasItem保留绘制命令；几何缓存跟随可听会话/乐句、地形与字体，屏幕布局跟随镜头/窗口、选择与主题来源。缓存精确投影、文字尺寸和避让结果，不能把每帧HUD重画传播到名称层；显示裁剪不删除社区身份或改随机流。名字布局是派生显示缓存，不进WorldSnapshot/City DNA。验证入口round137_map_labels与round137_regional_supply_live，后者只替换旧名称绘制路径作性能对照。

同一可听乐句的显示缓存以独立RefCounted会话标记及乐句序号识别，不能以临时World副本地址识别。切换旧城副本时刷新数据绑定，保留不变的城市几何；调音、镜头缩放和新会话仍按各自输入失效。会话标记不进快照，也不引用整个声音模型。

### 8.5 存档与回放边界

存档写临时文件，回读校验后才替换当前版本；保留上一份有效文件，损坏文件不得覆盖有效档。稳定 ID 不来自数组位置，坐标保存为数值，超出 JSON 安全整数的值保存为字符串。回放由稳定事件 ID、提交帧和同版本随机子流驱动；悬停、试听和预览不消耗正式随机流。

City DNA 使用与二进制作品相同的完整世界/音频模型状态，另存渲染游标和镜头；Vector2/Packed 数组转 JSON 数值数组，恢复须同时接回音频状态和镜头。`resonance_audio_plan_v1` 包含采样率/乐句帧、作者决策、世界事件、待播声音和声音轨迹；声音轨迹、移动体状态缺失时沿版本兼容规则恢复，派生显示缓存不进必需字段。这证明可继续的记录能力，完整跨版本 RenderVoice 重渲染另验。

AudioPlan 的字段、排序和 PCM 提交规则见 `12_声音架构.md` §10 与 `spec.audio.md` A26；存档按 `spec.run.md` 的 R2a 和本节字段保存。新增字段先更新本节和所属 spec，再改代码。

规划影响图的边是派生缓存，不是第二套建筑关系真值。它必须引用稳定 community_id、public_sites.id、anchor_id、planning_reservation_id 和世界版本；道路或公共几何改变时局部失效，章程/卡牌变化时按作用范围重算。它不进入 c/R/V 公式，不改变声学边的身份，不改变正式随机流。

WorldSnapshot 保存玩家提交的章程、锚点和卡牌选择；规划影响边、候选排名、服务分配和编曲选择按版本派生。WorldDelta 一次提交同时包含章程/锚点变化、留地变化、建筑/公共设施事件及其来源；失败只回滚预测，不删除已有对象。后台准备使用独占快照，迟到结果按版本丢弃，保持现有提交帧语义。

生成层仍按“地形 → 骨架 → 社区 → 街坊 → 地块 → 建筑”的六层顺序工作。规划章程在社区/街坊层输入，关键锚点在地块/公共对象层落定，普通建筑在建筑层自动生成；不能让规划章程直接指定每栋房子的坐标。

章程实现以稳定社区ID集合与parent_id谱系解析范围，最近层的直接选择覆盖祖先继承；锚点元数据复用public_sites单一对象，来源、占地、入口与容量不复制成第二套真值。成长只把规划偏好加入已通过空间检查的候选排序，协和/连接判定继续执行；关系按当次世界版本派生，按标签取最大且无正式随机抽取。结构请求仍经过现有request、后台独占快照、settle和可听帧揭示；公共操作的试听副本保留待播章程及其他结构意图，再替换当前公共候选，真实城市不被写入。
