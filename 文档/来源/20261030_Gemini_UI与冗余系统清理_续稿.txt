3. 三段改造前后的具体操作流程对比

流程一：营造水岸街区，听见声部变化并切换母曲与调式

  - 改造前（Before · 6 步跨 3 个面板，伴随后台伪经营打断）：
    1.  玩家点 [筑屋] 在河岸建起两栋“水畔圆廊（venetian_loggia）”；后台 WaterfrontRoleSeed 偷偷将第一栋设为
        bakery（面包坊）、第二栋设为 garden_cafe（茶座）。
    2.  屏幕上方 GuideWhisper 横幅催促：“沿屋门接通小路……”。玩家修路并添一栋民居后，Life 立即派出面包师揉面、买面包、坐茶座。
    3.  数秒后，上方不断弹出 Toast：“☕ 2位街坊在花下喝完一盏茶”“♫
        共鸣品质 2/5”，房屋外墙被自动挂上门垫与花盆，金色飞章射向左上角五线谱。
    4.  玩家按 L 想看音乐变化，却先看到 +35%、水岸与栖居互哺 · 1 组、场所空间 诊断码、以及底下又重复一遍的
        原有用途与连接，真正的《当前合奏》只有末尾 3 行。
    5.  玩家想把母曲固定为《深流》：必须关掉 L，按 F1 打开帮助手册，在底部小字栏连点 MusicPreferenceMode 与
        MusicPreferenceStyle。
    6.  玩家还想把调式换成《C宫五声》：必须关掉 F1，按 Ctrl+O 打开《作品收藏》，切到第 3
        个页签《留声机与名胜图鉴》，滚到底部点击“宫商河韵 · C宫五声”，再关掉收藏馆。
  - 改造后（After · 3 步原位闭环，零打扰）：
    1.  玩家在 [筑屋] 选水畔圆廊落笔，房屋保持纯粹建筑身份，不被偷改用途，无后台揉面/品质弹窗与飞章打扰。
    2.  用 [修路] 接通沿岸街道，水岸空间契约自动成立，岸边自然派生布篷与浮灯；下一小节安全边界，竖琴流水（Pulse:
        Flowing）平顺汇入母曲。
    3.  玩家点击左上角五线谱（或按 L）打开《城市总谱》：一眼看见 Pulse · 流水拨弦 ←
        石榴巷1号，并在同一面板顶部直接点选切换为《深流低语》与《C宫五声》。

流程二：单屋造型微调、切换木构/圆塔、放置传世地标与 12 秒独奏静听

  - 改造前（Before · 按钮被藏、面板套娃、地标割裂）：
    1.  玩家点选房屋打开 RoofCompassRing：顶部挂着 ★ 3 星级，底部挂着 [看功能区] 或 [安排面包坊] 按钮。
    2.  玩家想把房屋改为“木构”或“圆塔望楼”，在罗盘上找不到入口（被 lean_inspector.gd 的
        pop.style_button.hide() 隐藏）。
    3.  点击顶部 [详情] 弹出右侧 HouseDetailSheet；点击里面的 [用途] 弹出底部 HouseRolePalette；点击左翼
        [原型] 又弹出右侧 PrototypeBook——改一栋房子要开关 4 个不同位置的面板。
    4.  想放置“海神竖琴灯塔”：需去左上角点 [名胜] 印章，在左侧抽屉滑过 6 座旧屋式地标才能找到；放好后再点击该灯塔，右上角突然冒出一个粗糙的
        GroundLandmarkActions 按钮框。
    5.  想听 12 秒独奏：必须记住按住键盘 P 再左键点击房屋（且在 free 连续母曲下若该屋是 residential 还会因
        SoloSpotlight.eligible 的角色限制而失败！）。
  - 改造后（After · 单一净空罗盘，一步直达）：
    1.  点选房屋，净空罗盘展开：无 ★ 星级、无经营催促按钮；左翼直接调整
        [时代]、[屋式与原型]（灰泥/木构/石砌/圆塔与时代原型合一）、[微雕]；右翼直接换色或吸管取色。
    2.  点击罗盘底部动作岛的 [♫ 独奏] 按钮（任意有效声部房屋均可触发），镜头自动轻柔聚焦屋顶、附近漫步居民驻足倾听 12 秒。
    3.  在底部 [筑屋 -> 地标] 直接选取并放置地标；点击已放置的地面地标同样呼出上方净空罗盘（移动/旋转/独奏/回收），交互完全统一。

流程三：老玩家在转换城/旧档中查阅历史权益并领取旧手札与来信

  - 改造前（Before · 3 处重复入口、后台每 0.5 秒空转轮询）：
    1.  即使已截止成长（growth_cutoff），InspirationDraft._process 仍每 0.5 秒调用
        Receipts.collect -> take_events 遍历全城计数器。
    2.  同一个“待选手札与旧来信”同时出现在：左上角 [保留手札] 徽章、左侧 J（手记） 抽屉的 HistoricalTasks、以及
        F1（帮助手册） 底部的 CityLetters。
    3.  点开 J 页的 [查看已得手札与历史权益]，界面直接打印 小数0.350000 等内部调试账本文字。
  - 改造后（After · 平时静默休眠，一处查阅兑现）：
    1.  新自由城无待领权益时，InspirationDraft 完全休眠不轮询，左上角零多余徽章。
    2.  若打开带有未领 credits 或未完 active_vignette 的旧城/转换城，左上角浮现 [旧卷待启]
        徽章，点击即可直接翻开三张保留手札完成选择（支持翻卷与 Undo）。
    3.  按 J 或 F1 -> [历史权益与旧城转换]，可在同一页面清晰查阅已收录的 18 张手札卡片、历史和弦留痕并手动继续/领取旧来信（隐藏 6
        位小数余量展示，底层字段原值保留）。

2. 三大专项技术核查：防漏算、防误删、防重复

专项核查一：彻底阻断“界面隐藏了但后台继续算”的调用链

1.  demo.gd:_process() 中的每 0.5 秒 UI 账本刷新（第 450～468 行）：
      - 现状：即使 place_panel 永久隐藏，且处于 free 模式，demo._process 仍每 0.5 秒调用
        life.summary()、_refresh_concert()、_refresh_district()、_refresh_bakeries()、_refresh_workshops()、_refresh_cafes()、_refresh_household()。其中
        _refresh_bakeries() 会遍历全城面包坊调用 life.bakery_status()，_refresh_workshops()
        会遍历全城工坊调用 life.workshop_status() 与 town.update_craft_progress()。
      - 切断位置：在 demo.gd 的 life_ui_timer 分支与 _refresh_place() 中，当
        state.CreationPolicy.is_free(state) 为真时，跳过
        _refresh_bakeries()、_refresh_workshops()、_refresh_cafes()、_refresh_household()
        的周期状态机拉取；炊烟与已存旧装饰仅在建筑几何变更（_after_edit / 读档发布）时按静态数据同步一次。
2.  life.gd:_tick_life() 中的每 0.5 秒品质哈希与规则扫描（第 232～241 行）：
      - 现状：每 0.5 秒计算 hash([state.revision, state.Quality.data(state)]) 并分批调用
        _refresh_quality -> Quality.refresh -> Quality.amenity（内含
        courtyard_plans() 与道路距离扫描）。
      - 切断位置：在 Life._tick_life() 中，当 state.CreationPolicy.is_free(state)
        为真时，直接跳过 _quality_timer 与 _quality_cursor 分支。
3.  inspiration_draft.gd:_process() 中的每 0.5 秒收据差分（第 34～41、97～100 行）：
      - 现状：每 0.5 秒运行 poll() -> Receipts.collect(demo.state) ->
        Receipts.take_events(demo.state) ->
        Receipts.counters(demo.state)，遍历所有房屋、库存、和弦与收据字典。
      - 切断位置：当 demo.state.harmony_journey.has("growth_cutoff") 为真时，poll() 直接跳过
        Receipts.collect(demo.state)；当同时满足 Journey.credits(journey) == 0 and
        Unified.pending(demo.state).is_empty() 时，将 InspirationDraft 的
        set_process(false)，仅在切城/读档/旧来信领取信号时唤醒检查一次。

以下四项体验缺乏静态代码层面的动态证据，必须在施工落地后通过真实实窗（gl_compatibility + 物理音频设备监听）验证并微调参数：

1.  撤除飞章与顶部通知后，“空间成景 → 声部合流”的可感知度验证：
      - 验证场景：在安静的新自由城中，当玩家闭合一座四合院落或拉通一条水岸长廊时，完全去掉 JuiceFlight 飞章与文字 Toast
        后，仅靠即时落笔音 + 空间成立短动机 + 下一小节安全边界的声部（Warm / Flowing）汇入 +
        左上角五线谱微光，玩家能否清晰感知“我的这一笔改变了城市音乐”？若视觉归因偏弱，只微调建筑窗户或水岸浮灯的柔和呼吸光效，绝不恢复飞章轰炸。

        TactileDock。
