2. 最关键的设计与实现问题（重点挑战现行假设）

问题一：【空间→音乐归因断裂】空间契约与发声引擎脱节，且多重延迟与自动轮替冲淡了因果感知

  - 源码事实：
    1.  city_creation_functional_zones.gd 产出了 spaces（含四类场所的 stage 与
        eligibility），但当前正式音频路由
        scripts/audio/city_creation_core_orchestration.gd 与
        city_creation_orchestration_plan.gd 完全没有读取
        functional_zones().spaces（仅在第 27 行简单判断 ctx.era == "modern_eco"
        or ctx.water < 5.）。
    2.  已有的 144 秒田园母曲容器（scripts/audio/city_creation_master_score.gd +
        city_creation_authored_score.gd）目前仅通过开发者接口 request_master
        逐段触发；更严重的是，city_creation_authored_score.gd 第 32
        行写有 if data.revision != owner._pluck_city.revision: ... discard(owner,
        data); return false——这意味着只要玩家在城里落下一笔（city.revision 自增），母曲就会被立即丢弃并退回旧谱！
  - 薄弱假设挑战（为什么玩家听不出是哪项操作导致了变化？）：
      - 即使按 文档/54 将 spaces 接通到母曲分谱，现行设计假定“成区后提升分谱档位，在下一小节切流”。但查看
        scripts/audio/city_creation_stream_transition.gd 第 68 行：job.deadline =
        (floorf((clock + 1.) / 3.) + 1.) * 3.。由于一次 3 秒小节加上 +1s 缓冲，加上
        BudgetRebuild 与路网发布耗时，玩家修通道路成区后，长轨实际换流需要等待 1.5～4.5 秒！
      - 在这几秒等待期内，如果母曲恰好处于伴奏静默段（如 P2 减法段或 P5 收束段，见
        city_creation_orchestration_plan.gd 第 40 行 pulse = passage not in
        [3,4,5]），玩家刚建好的水岸或庭院在长轨里根本不会发声！
      - 同时，旧有的 PhraseTide（scripts/audio/city_creation_phrase_tide.gd 第 50～80
        行）每 2
        小节（6秒）按“起承转合”自动在视野内的主次聚落间切换主奏声源与声像。玩家静止不动时音乐也在自己换轨，落笔改变空间时反而要等数秒，因果归因必然混乱。

问题二：【风貌锁死功能区】代码层将建筑时代（Era）与百工/礼乐契约硬绑定，违背“单一风貌/混搭皆完整作品”

  - 源码事实：
      - 查看 scripts/world/city_creation_artisan_contract.gd 第 6、12 行：百工契约仅认
        BODIES = ["sawtooth_atrium","iron_conservatory","twin_gable"] 与
        clock_turret。这四个原型全部属于蒸汽钟表（clockwork）与现代生态（modern_eco）风貌！如果玩家建一座纯古典田园（pastoral）或文艺复兴（renaissance）小城，哪怕手动将房屋设为
        workshop（制琴工坊）并留出标准前庭，在 spaces 中也永远是 0 个百工空间，永远无法激活百工 Echo 分谱！
      - 查看 scripts/world/city_creation_civic_contract.gd 第 7、13 行：礼乐契约仅认 BODIES
        = ["ionic_stoa","roman_basilica","rotunda","guildhall"] 且限定 eligible 为
        pastoral 和 renaissance。在钟表与现代风貌下，除放置限量地面地标外，普通文化建筑永远无法形成礼乐 civic 空间。
      - 查看 scripts/world/city_creation_lane_contract.gd 第 91 行：连续窄巷即使满足全部条件晋升为
        stage = "district"，其 eligibility 却硬编码为 {"district": eligible, "warm":
        false}，成区却不给任何音乐资格。

问题三：【数值退场引发的隐藏死锁】直接停掉抽卡与自动任务，会导致新自由城无法使用地面地标、饰色、调式与近景生态

  - 源码事实：
    1.  地面地标死锁：scripts/world/city_creation_placed_landmarks.gd 第 77 行校验 if not
        Legacy.unlocked(city).has(blueprint): return city._fail("这张传世蓝图尚未获得")。而
        city_creation_legendary_wonder_plan.gd 第 13～20 行规定，蓝图只能通过**“抽中 3
        阶虹彩稀有度手札（rarity_ranks == 3）”或“同一微景来信完成 2 次（vignette_echoes
        >= 2）”**解锁！当前自由模式已停掉自动来信派发，下一步一旦停掉新 XP
        与新抽池，所有新建自由城将永久无法放置四座独立地面地标！
    2.  饰色与调式死锁：scripts/world/city_creation_state.gd 第 207、212
        行中，切换特殊调式（set_music_mode 的 C 宫五声、F 大七）与 6
        款房屋饰色（set_house_finish）仍强制校验 archive_unlocks 与
        growth_memories（city_creation_growth.gd 要求烤出面包、送装木饰、办节庆演出）。这直接违背了 文档/55
        第 2 节“新自由城基础工具、基础母曲与基础声部不通过印章、图鉴或任务解锁”的原则。
    3.  近景生机断供风险：门前花盆（city_creation_harmony_flora.gd 读
        house_harmony_tier）、屋顶与门廊蝴蝶/萤火虫（city_creation_wildlife.gd
        读 house_harmony_tier）、外墙木饰风铃/织锦彩窗/八音盒（city_creation_craft.gd 读工坊送货台账
        house_improvements 等）、炊烟与柜台面包（city_creation_renderer.gd 读
        bakery.status）目前全部依赖后台经营闭环（买面包→喝茶→送木饰）。若 M85
        简单停掉经营消费者而不把这些视觉表现改接到自由模式空间条件，自由城将变成没有花盆、风铃、彩窗、炊烟和蝴蝶的“死城”。

问题四：【自动涌现越界与 UI 遗留干扰】后台静默变形篡改作者意图，旧打卡 UI 与错误静音偏好仍在生效

  - 源码事实：

        阶段（落笔提交后），未经任何预览，自动将距弯路 4.5m 内的双格直屋篡改为折弯屋（写入 bend_angle_deg 与

        处生成三席茶伞阵并强行压平半径 3.0m

二、选择方向：三种迭代取舍对比

围绕核心问题——“玩家为什么愿意落下一笔、如何察觉这一笔的价值、为什么愿意继续修改和欣赏”，提出以下三条真正不同的演进路线：

| 对比维度        | 方向 A（推荐）：沿现主干深化<br>「双层声画归因与全风貌契约箱庭」                                                                 | 方向 B：轻量化重构<br>「无门槛直觉声部画笔沙盒」                                                                                  | 方向 C：剧场化演进<br>「空间触发自主生活剧场箱庭」                                                       |
| :---------- | :-------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------- |
| **核心体验逻辑**  | **塑形即发声，成区有先导**。保留四类场所契约与 144s 六段母曲；新增“0.18s 短槽空间先导动机 + 下一小节长轨分谱合流”双层归因；打通全风貌契约，解绑自由城地标/饰色/微景的旧经营锁。 | **所点即所听，取消成区门槛**。放弃 `trait/cluster/district` 三级几何契约与 144s 六段曲式，退回 24s 单段循环；建筑高度与风貌直接决定音高与音色，玩家用“街坊画笔”手涂配器区域。 | **筑台引客来，因人而生乐**。保留自由城后台自主生活流（无需玩家催促的烘焙、品茶、送艺、巡演），空间成区只搭舞台，必须等居民走入入座或聚集，才唤醒对应声部与街景。 |
| **玩家归因清晰度** | **高**。普通落笔听材质/音高；空间成区瞬间有定位在源头的先导动机与视觉轻拂，6秒内必有分谱露面，镜头静止时不乱跳声源。                                       | **极高（但浅）**。每次点击直接改变循环音轨权重，但缺乏“围合院落、理水造桥”带来的空间顿悟感。                                                            | **低（滞后且易混淆）**。玩家造好水岸或礼乐前场后，需等待居民寻路抵达才能听到变化，极易重蹈“不知为何突然响起”的覆辙。                      |
| **系统复杂度**   | **中等可控**。直接复用已完成的空间契约、和声表与音频池；仅修补契约风貌盲区、增加成区先导触发器并清理自由模式旧锁。                                         | **低（但需大量废弃现有资产）**。需废弃 M84 已验收的七个空间契约模块与 48 小节母曲框架，回退工程进度。                                                    | **高**。需长期维护 300 屋规模下的全城寻路、供需配对与音频触发同步，M85 性能减负空间极小。                                |
| **内容与工程成本** | 复用现有 4 短槽与预编译音库合成先导动机；在现有 `master_score` 上扩展 `version3` 分谱；UI 仅做减法与入口合并。                            | 工程裁剪快，但浪费了 M83–M84 在空间拓扑与母曲和声上的大量投入，且长期留存容易沦为 5 分钟玩具。                                                        | 需为自由模式编写大量无经营前置的 NPC 剧本调度与容错逻辑，测试矩阵（路网中断、座位占用）极庞大。                                 |
| **主要风险**    | 若母曲多档分谱（Tier）编写区分度不足，长听仍可能平淡；需通过实听校准各档织体差异。                                                         | 失去“空间几何塑造室内乐”的核心差异化壁垒，变成普通涂色块音乐盒。                                                                            | 违背 `文档/54`/`55`“不以等待 NPC 偶遇作为基础音乐前置”的定稿原则，且大城卡顿风险高。                                |

推荐结论：选择【方向 A】

理由：项目的灵魂在于**“真实空间关系（围合、临水、前庭、高差、连通）与室内乐总谱的相互映照”。M83 与 M84
前期已经把最难的几何拓扑和空间契约啃了下来，当前体验断层并非主干方向错误，而是“最后一公里的归因反馈被长轨换流延迟和静默段吞没”以及“旧时代/经营锁尚未从空间表现上解开”**。采用方向
A 能以最小的架构震荡，把现有技术基座真正兑现为玩家可感知的创作正反馈。

三、推荐方案：一体化玩家体验链设计

我们将玩法、系统、音乐、美术与交互收束为同一条闭环体验链： 「直觉落笔 → 触感短音反馈（≤187.5ms） → 空间成景与先导动机确认（1.2s） →
母曲分谱安全合流（≤3.0s） → 驻足静听与总谱溯源 → 个人作品封存」

1. 玩法与营造交互：为什么愿意落下一笔？

(1) 工具栏收束与“零门槛全画布开放”

  - 四类核心营造入口（改造 scripts/ui/city_creation_demo.gd 与
    city_creation_tactile_dock.gd）：
      - 底部主工具栏收束为 4 个营造画具 + 1 个交互模式：
        1.  筑屋（Build）：默认直选四风貌（田园、文艺复兴、钟表、现代）与高频原型；左键点击或拖拽画屋，悬停已有房屋顶面/侧面直接加层或拓房；二级开关切换“房间
            / 露台”。
        2.  修路（Road）：整合小径、石板灯街、林荫道、轨街与砖石铺装；二级选项提供街具偏好（留白/路灯/花箱/树池/长椅）与跨水方式（自动/平桥/拱桥/浅水汀步）。
        3.  理水（Water）：开挖池塘、从河道/池塘引水渠、Shift 填水。
        4.  自然（Nature）：合并地形塑形（隆起/浅洼/台地/柔化/复原）与植物种植（乔木/灌木/花丛单点与笔刷）。
        5.  点景与试听（Inspect & Audition，快捷键 P
            或直接左键点选已有建筑）：弹出上下文微调环（旋转、配色、饰色、折翼/导角、原型切换、独奏聚光灯）。
      - 兼容性保护：原数字键 1～9 与内部 select_tool(0..8) API 完整保留，确保已有测试探针与快捷键习惯零破坏。
  - 解除新自由城的隐藏内容锁（改造 city_creation_state.gd、city_creation_placed_landmarks.gd）：
      - 在 CreationPolicy.is_free(state) 为真时：
          - finish_available(finish) 与 set_music_mode(mode) 直接返回 true（无需先解锁
            growth_memories 章节或 archive_unlocks 成就，即可自由选用全部 6 款饰色与宫商五声、印象水光等调式）。
          - PlacedLandmarks.preview 与 validate_geometry 在 free 模式下不再拦截
            Legacy.unlocked(city)（每张蓝图全城限放 1
            座的物理唯一性及净空/平地校验保持不变，但玩家无需先去抽虹彩卡或刷两遍旧来信即可直接放置灯塔、歌咏台、花苑与天文钟楼）。

(2) 自动涌现与作者控制的严格边界

  - 必须预览并由玩家确认的结构变化（禁止后台静默改写）：
      - 弯路折翼（改造 scripts/world/city_creation_curve_hug.gd）：废除 State._commit
        中落笔后静默修改 bend_angle_deg 的逻辑。改为在筑屋预览阶段计算
        CurveHug.sample：若双格屋贴近弯路，预览网格直接展示贴合弯路的折角轮廓与提示
        “贴合弯路微折 · 按 Tab 保持直墙”；玩家松手提交即为所见形态，且单笔 Ctrl+Z 完整撤销。
      - 随形原型与水岸茶座种子（改造
        city_creation_build_brush.gd、city_creation_waterfront_role_seed.gd）：仅当玩家在筑屋面板选择“随形生长”时才自动匹配水畔圆廊/山庄及面包坊/茶座默认用途；若玩家显式选定了“山墙木屋”或“柱廊门庭”，绝不后台篡改其原型。且当新屋将派生室外茶座时，利用现有的

3. 音乐与声画交互：如何察觉这一笔的价值并愿意长听？

(1) 核心机制链：玩家操作 → 空间/状态变化 → 声画反馈 → 后续创作动机

[玩家落笔/修路/理水]
   ├─► (0ms) 几何/预览即时落位 + 候选接触AO
   ├─► (0~187.5ms, CueGrid下一16分音符) 
   │     ├─ 若为普通落笔：播放对齐当前实际播放小节和弦的【材质/高度触感短音】（4短槽之一）
   │     └─ 若此笔促成空间首次晋升 District（或跨岸 Canon）：
   │           ├─► 【声：1.2s 空间先导动机】在源建筑世界声像处奏响该声部代表乐器的短句引子
   │           ├─► 【画：0.8s 局部材质轻拂】源空间特征物（水波/布篷/风铃/前阶）微幅响应 + 底部单行归因轻提示
   │           └─► 【乐：下一3秒小节边界合流】长轨分谱切入新 Tier，并在首2小节内保证一次可听呈示（Audible Intro）
   └─► [后续创作动机]
         ├─ 听见先导动机与分谱合流 → 尝试延伸街面、连接对岸或围合内院，探索配器对答
         └─ 觉得某处太热闹或想留白 → 挖一汪池塘、种一片橄榄林，或切为 Quiet 疏朗编配驻足静听

(2) 解决母曲连续性、操作归因与长听疲劳的六项具体规则

1.  全局连续母曲游标（修复 city_creation_authored_score.gd 编辑丢弃问题）：
      - 将母曲播放状态从“一旦 city.revision 改变就 discard 的临时开发者预览”升级为正式常驻传输：建立全局游标
        master_cursor（0..144s 循环，对应 P0..P5 共 48 小节）。
      - 玩家编辑城市（revision 增加）时，绝不重置或丢弃母曲游标，仅重新评估当前视野与全城的 functional_zones().spaces
        资格，更新各职责（foundation / pulse / answer / lead）的目标档位（tier）。
2.  预烘当前母曲六段分谱，消除 3～6 秒换流延迟（改造 city_creation_stream_transition.gd）：
      - 现行 StreamTransition 在空间变化后才启动线程解码整轨 24 秒音频并合成 48 秒过渡 WAV，且 deadline
        强行加 1 秒再向上取整到 3 秒小节，导致严重滞后。
      - 改进办法：对于当前激活的母曲与调式，后台预加载当前段与下一段的四职责分轨；同一段落内发生空间档位（tier）升降时，由于同母曲同段落的所有
        tier 严格共享 24 秒拍钟相位，直接利用现有的 12 个长轨播放器池进行下一小节边界（0～3.0s，平均 1.5s）的 150ms
        包络交叉淡入淡出，结合落笔后 ≤187.5ms 的短槽先导动机（Signature
        Motif），实现“落笔即有先导回音，紧接着小节线无缝汇入合奏”。
3.  新成区“2小节呈示保护（Audible Introduction）”：
      - 解决“造好水岸/百工时恰好赶上母曲 P2/P5 伴奏休止段，导致毫无声音变化”的反例：当某类空间在当前城市首次晋升为 district
        时，无视当前段落对伴奏的常规休止门限，允许对应职责（如水岸 Flowing 或百工 Echo）在接下来的 2 个小节（6秒）
        内以轻柔增益（-21dB）呈示一次，随后再平滑归入母曲当前段落的织体密度规则。
4.  镜头焦点稳定锚定（废除自由模式下的自动 PhraseTide 乱跳）：
      - 在自由模式下，停用 PhraseTide.arrange 每 2 小节在主次聚落间强制轮换主奏声源的逻辑。
      - 改为**“镜头焦点相关性 + 2小节（6秒）离开迟滞”：镜头中心 18 米内已成区的空间决定当前可听配器；当玩家平移镜头跨区时，旧区配器保持 2
        小节迟滞再淡出，新焦点稳定停留满 1.5
        秒后在下一小节切入，避免快速扫视地图时音乐频繁闪烁。若音源建筑被拆除或道路被切断，则不设迟滞**，在最近的安全边界立即撤回资格。
5.  跨岸卡农（Cross-River Canon）的严格双源契约：
      - Answer 声部的最高档 Canon 必须满足：两岸（不同 river_x
        侧或被水域分隔）各自存在已接路的真实空间来源，且通过一座实际桥梁（road.bridge
        == true）或显式共鸣连线（musical_links）连通。仅在河上修一座孤桥、或只有单岸建筑，绝不授予 Canon。
6.  修正 quiet 与 fixed 偏好（修复 city_creation_orchestration_plan.gd 第 25 行）：
      - fixed：锁定玩家选定的母曲家族（如《田园晨风》），但空间成景依然正常切换该母曲下的 Warm / Flowing / Echo /
        Lyrical 分谱。
      - quiet：不再强制切换为 felt_nocturne 夜曲！保持当前母曲与调式不变，将编配密度锁为稀疏（仅保留 Lead 简编与轻柔
        Foundation，伴奏增益下调 4dB，生活装饰短声冷却翻倍至 12s），满足极简/安静玩家的长时间陪伴需求。
      - 失败条件与撤销：任何未成区的尝试（如门前高差断路、被外伸柱脚阻挡、未接路）绝不播放“错误蜂鸣音”，仅播放正常的轻巧落笔木音，并在房屋卡片与 L
        页用温和清晰的一句话指明原因（如 “门前高差尚无可用接续 · 添一段缓坡小路即可连通”）；按下 Ctrl+Z
        撤销成区操作时，播放清脆的回退双音（history），空间街景当帧撤回，对应分谱在下一小节自然淡出。

四、具体场景推演与反例检验

以下场景均基于实际代码机制与推荐方案推演，不依赖“恰好进入 P4 高潮段”等巧合假设。

1. 三个核心可执行场景

场景 A：首次 5 分钟（真实空地起步 → 听见第一笔与第一次空间成景）

        大调主和弦的木吉他在位泛音；紧接着下一小节，母曲《田园晨风》的 Simple 长笛主奏与 Pizz 低音轻拨从 h1

3.  作品收藏与重开（Ctrl+O）：玩家打开作品收藏，点击“收藏此刻”，生成带封面校验、镜头角度、光照相位与音乐偏好的不可变作品快照（resonance_creation_work_v1）。切换到另一座示范城再切回，空间资格、街景与母曲偏好 100%
    恢复一致。

2. 五类极端反例检验（压力测试）

1.  反例一：单屋 / 无水小城 / 刻意大面积留白
      - 操作：玩家在整张地图上不挖一滴水（甚至远离基础河道在高山角落）、只建一栋小屋与一片橄榄树林，随后挂机聆听。
      - 表现：不弹任何“缺水岸/缺工坊”的催建提示；单屋播放完整的六段 Simple + Pizz 母曲；大片树林使 Ambience
        的林风与鸟鸣权重升至 0.75，与单屋长笛形成极简牧歌；若玩家在干地上多建几栋屋连成窄巷或石板街，无需水域即可激活 Sway 推进织体。
2.  反例二：复杂混搭（四风貌同街 + 异风貌桥岸 + 穿插用途）
      - 操作：同一条弯街左侧是古典长馆（pastoral）与连拱茶座（renaissance），右侧是折顶工坊（clockwork）与全景山居（modern_eco）。
      - 表现：视觉上共享同一套微法线、接触 AO 与明度范围，异风貌桥头挡墙与路口高程平滑过渡（M83 已保底）；空间契约各自独立判定（左侧出
        civic 与 waterfront，右侧出 artisan 与
        courtyard）；音乐上绝不同时播放四首不同时代的主题曲造成打架，而是由当前锁定的同一首母曲统领和声，左侧贡献
        Flowing 推进、右侧贡献 Echo 接腔，实现“异风貌同母曲合奏”。
3.  反例三：快速连续编辑（1秒内狂点 8 间房、连续拉路、立刻按 Ctrl+Z 撤销）
      - 操作：玩家快速拖拽连建多格房屋并立刻撤销。
      - 表现：AttentionMixer 处于 Mode.SCULPTING，背景长轨自动让位
        -1.2dB，短音队列（容量 5）自动合并相同音高并淘汰过期候选，每
        0.1875s 最多发声 1 次，绝不出现音符爆音堆叠；后台 BudgetRebuild 与 Life
        异步工作线程丢弃中间过期版本，不会阻塞鼠标输入；按下 Ctrl+Z 整笔撤销后，未落定的成区先导音与派生街景立即取消，母曲游标丝毫不乱。
4.  反例四：跨区镜头快速扫掠（从西岸水岸快速拖向东岸高地，再拉远到全景）
      - 操作：玩家在 2 秒内把镜头从水岸拖过河道、掠过百工区，最后停在空旷山林，或滚轮拉远到 zoom = 80m。
      - 表现：由于有“新焦点稳定 1.5 秒才触发候选 + 旧空间 2
        小节离开迟滞”双重保护，镜头快速路过百工区时不会触发走马灯式的切轨；当镜头拉远至全景（zoom
        > 32m）时，CameraOrchestration 平滑提升混响湿度（wet 从 0.13 过渡至 0.24）与低音 Foundation
        支撑，短促生活点景自动随 CueGrid.zoom_attenuation 衰减静音，呈现宏观交响空间感。
5.  反例五：删除声源、切断桥梁或用邻屋外伸柱脚堵死前庭
      - 操作：玩家正在听跨岸 Canon 与礼乐 Lyrical，突然删掉跨河石桥，或在百工前庭正前方旋转放置一座反向爱奥尼长馆使其外伸柱脚侵入前庭。
      - 表现：public_space_obstacles.gd 与 _region_network 立即检测到前庭受阻与分量断连，spaces 中的
        district 资格当帧降级为 cluster/trait，L 页实时显示 “前庭净空受阻” 或
        “跨岸连接已断开”；派生浮灯/布篷立即收起；音频上不对已删除/断连来源使用 2
        小节迟滞，在当前小节安全边界立即将 Canon 降回单岸 Echo 或静默；随后玩家按 Ctrl+Z 恢复桥梁，资格与配器精准复原。

### 10.1 相对 54 / 55 新增的规则（Added）
1. **成区双层声画归因（先导动机 + 2小节呈示保护）**：
   - 当玩家操作使某处空间在已发布路网下首次获得 `district` 级音乐资格（`warm / flowing / echo / canon / lyrical / virtuoso`）时，除等待长轨在下一安全小节（3秒边界）切入对应分谱外，必须在确认资格当帧通过空闲短槽（`effects`）于该空间世界声像处触发一次 **0.8～1.2 秒的专属配器先导动机（Signature Motif）**，伴随源空间特征物一次低幅视觉轻拂与单行来源提示。
   - **休止段呈示保护**：若首次成区时母曲恰好处于伴奏静默段（如 P2 或 P5），允许新激活的支撑职责在接下来 2 个小节（6秒）内以轻柔增益完成一次可听呈示，随后再服从母曲段落的留白门限，消除“成区却无声”的归因盲区。
2. **自由模式全画布默认解锁（消除数值退场死锁）**：
   - 在 `CreationPolicy.is_free(state)` 为真时，四座独立地面地标（`placed_landmarks`）、全部 6 款房屋饰色（`FINISHES`）与全部调式（含 `gong_pentatonic`、`impressionist_major7`）直接对玩家开放选择，不再要求先达成 `rarity_ranks == 3`（虹彩手札）、`vignette_echoes >= 2`、`growth_memories` 或 `archive_unlocks`。独立地标每城每类限放 1 座的物理唯一性及平地/净空校验保持不变。
3. **自由模式近景微景改接空间来源**：
   - 自由模式下，门前花盆（`HarmonyFlora`）、外墙木饰/风铃/织锦彩窗/八音盒（`Craft`）、炊烟（`BakerySmoke`）与蝴蝶/萤火虫（`Wildlife`）不再依赖后台虚拟采购、茶聚或工坊送货次数，改为由已生效的空间契约（`spaces` 的 `cluster/district` 及邻树/临水关系）只读派生，并受 `automatic_decoration` 开关统一控制。经典 `legacy` 模式继续按原经营台账驱动。

### 10.2 相对现行实现与旧规格覆盖/修正的规则（Overridden / Corrected）
1. **解除风貌（Era）对百工与礼乐契约的硬锁定**：
   - 修正 `city_creation_artisan_contract.gd` 仅认钟表/现代原型、`city_creation_civic_contract.gd` 仅认田园/文艺复兴原型的限制。田园与文艺复兴风貌下的双层露台作坊或显式工坊用途（配 `1.8m` 净空前庭与可达道路）合法派生 `artisan`；钟表与现代风貌下的拱会/玻亭/全景台地或显式文化用途（配 `1.8m` 净空前场与可达道路）合法派生 `civic`。
   - 修正 `city_creation_lane_contract.gd`：已成区（`stage == "district"`）的连续窄巷合法提供 `warm`（或轻柔室内乐内声部）资格。
2. **母曲常驻传输与镜头焦点锚定（覆盖旧自动轮替与编辑丢弃逻辑）**：
   - 覆盖 `city_creation_authored_score.gd` 中因 `city.revision` 变化而丢弃母曲的逻辑：城市编辑只更新分谱档位计划，母曲全局播放游标（`P0～P5`）保持连续推进。
   - 在自由模式下停用 `PhraseTide` 每 2 小节自动轮换主次聚落声源的机制，改为**镜头焦点相关性 + 1.5 秒进入确认 + 2 小节离开迟滞**（已删除或断连的声源不设迟滞，在安全边界立即撤回）。
3. **修正 `quiet` 偏好与后台自动折弯（覆盖冲突实现）**：
   - 修正 `city_creation_orchestration_plan.gd`：`quiet` 模式与夜景/静听不再强制将母曲替换为 `felt_nocturne`，而是保持当前母曲与调式、降低伴奏密度（`thin`）与短声频率。
   - 覆盖 `city_creation_curve_hug.gd` 在 `State._commit` 中的静默折弯行为：贴弯路折翼必须在落笔预览阶段显示候选轮廓并允许玩家取消，禁止提交后后台篡改作者已选直墙形态。
   - 自由模式左上角 HUD 收起“拓房/加层/露台/接路”四项打卡任务与采购/茶聚计数器。

### 10.3 明确保留的规则（Retained）
1. **音频与性能硬预算**：12 长轨、4 短槽、6 总线、2 自然声、唯一 `layer 3` 领唱、`80 BPM / 0.1875s` 量化网格及 `PAN_LIMIT = 0.65` 保持不变。
2. **三类城市数据保护边界**：Schema 1～20、M80 外部 `schema1` 谱面校验、经典 `legacy` 完整经营循环、显式转换前独立备份保留。已有自由城的 `harmony_xp`、`xp_remainder`、未用 `credits`、已生成 `pending_draft`、已得 `ranks/rarity_ranks`、单调 `receipts` 与历史来信完整保留，提供手动领完入口，绝不清空或伪造历史。

### 10.4 仍需实测与真实听评决定的事项（Pending Live Verification）
1. **首次成区先导动机的音量与时值平衡**：1.2 秒短槽先导动机与随后小节长轨合流之间的增益衔接（暂定 `-12dB` 短槽先导 + `-21dB` 呈示过渡），需在实窗录音与真人试听中检验是否自然、有无掩蔽主旋律。
2. **窄巷与高地台庭的 `Warm` 织体区分度**：闭合内院、连续窄巷与高地台庭共用 `Foundation` 职责预算时，采用同一 `Warm` 分谱还是区分轻拨/暖弦色彩，需根据首曲多档实听效果决定。
3. **300 屋大城裁剪经营预热后的帧时与首次入座延迟**：停用 `free` 模式全城服务点对预热、改为长椅/茶座按需局部寻路后，需在同机 300 屋夹具上实测 `graph_ms` 与首次入座耗时，确认无单帧尖峰。
