当前产品循环是：**选区域发展章程 → 选社区范围 → 放置公共设施/交通节点/重要建筑 → 普通建筑按规则自动生长 → 服务、规划、声学和编曲重新计算 → 听见并看到下一次机会**。玩家不逐栋摆普通建筑；规划影响不直接改 `c/R/V`，也不绕过道路服务、落点分层或 70 RenderVoice 上限。

用户明确裁定优先；现行 spec 定义实现规则，阅读稿解释意图。已被替代的表、旧 fixture、历史报告不会因为日期相同或写着“已部署”恢复效力。遇到未闭合的产品选择，记录到待裁定清单；已有明确规则的工程实现自主推进。

设计批准、代码实现、技术验证、真人体验是四种状态。局部实现不代表整条规格完成；历史技术 PASS 不证明新版已通过，也不证明好玩。

默认不读取项目根 [废弃目录](../废弃/README.md)、历史轮次报告、研究包和本次审查记录。原文档废弃与 `90_存档` 已统一放到 `废弃/文档/`。需要追溯特定证据时再定向打开；不递归汇总整个文档目录，也不要求开工通读全部阅读稿。

施工 AI 不得新建平行技术定案、源码调研或日期化总结来承载现行规则。规则写入所属 spec 或 10–19；外部项目写入 [参考索引](参考索引.md)，资料包选择与阅读顺序遵循 [参考资料 AI 索引](参考资料AI索引.md)；进度和验证写入 `PROJECT.md`、`03_任务/` 或 `验证记录/`；未裁定内容写入 [待裁定与依赖](待裁定与依赖.md)。重要旧稿移动到项目根 `废弃/文档/` 并注明替代位置，不删除关键原文，不在文档内重建废弃目录。

**写入纪律：** 已有章节能承载时直接修改；禁止在现行文档末尾追加“第 N 轮定案/研究/总结”来制造第二入口。新增内容必须归入唯一权威章节；若只是过程记录，写入 `PROJECT.md`、`03_任务/` 或根目录 `验证记录/`。需要保留的旧稿先移到根 `废弃/`，并在归档 README 写明替代位置和未吸收内容。
