# 文档阅读入口

这是现行文档入口。项目进度以 [PROJECT](../PROJECT.md) 为准；旧报告中的“当前”只指对应轮次。

| 要做什么 | 读哪里 | 用途 |
|---|---|---|
| 接着做工程 | [PROJECT](../PROJECT.md) → [规格索引](01_执行规格/README.md) → [P0](03_任务/P0.md)/[P1](03_任务/P1.md)/[P2](03_任务/P2.md) | 当前实现、下一步、对应规则与验证 |
| 运行当前 Demo | [Demo快速开始](Demo快速开始.md) | 连续河谷操作；旧便携包是独立快照 |
| 理解设计 | [00_设计意图](00_设计意图.md) → 10–19 阅读稿 | 目标、体验与系统关系；数值取 spec |
| **查落点与连片** | [spec.fabric](01_执行规格/spec.fabric.md) | **任意陆地落点的三层后果、共享山墙/连排/庭院、街墙连续度** |
| 查具体规则 | [十份执行规格](01_执行规格/README.md) | 现行公式、阈值、接口与适用范围 |
| 查未定设计 | [待裁定与依赖](待裁定与依赖.md) | 剩余问题、已闭合旧问题、只影响哪些任务 |
| 验收本次改动 | [DOD](02_验收/DOD.md) | 选最低充分检查；命令存在不等于通过 |

用户明确裁定优先；现行 spec 定义实现规则，阅读稿解释意图。已被替代的表、旧 fixture、历史报告不会因为日期相同或写着“已部署”恢复效力。遇到未闭合的产品选择，记录到待裁定清单；已有明确规则的工程实现自主推进。

设计批准、代码实现、技术验证、真人体验是四种状态。局部实现不代表整条规格完成；历史技术 PASS 不证明新版已通过，也不证明好玩。

默认不读取 `废弃/`、`90_存档/`、历史轮次报告、研究包和本次审查记录。需要追溯特定证据时再定向打开；不递归汇总整个文档目录，也不要求开工通读全部阅读稿。
