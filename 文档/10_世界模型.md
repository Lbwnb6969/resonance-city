# 世界模型 · 连续城市与局部墙格

## 两层空间

城市使用连续世界坐标、高度、方向和真实占地。道路是曲线与路口图，区域是轮廓与权重场，植被是带种子的实例集合。它们不读取房屋格坐标。

社区房屋有自己的局部模块拓扑。墙面格描述哪个面、哪一层、哪一段可以添加或移除房屋/露台；经房屋变换映射到世界。格是编辑和邻接结构，最终墙面不需要画格线，也不需要长得像一块块棋子。

| 层 | 表达 | 查询与用途 |
|---|---|---|
| 城市连续层 | 位置、曲线、多边形、高程 | 占地、道路入口、区域影响、植被避让 |
| 房屋局部层 | 模块单元、墙面锚点、层高、邻接 | 房屋块/露台扩展、开口、转角和屋顶拼接 |
| 表现层 | 网格/贴图、材质、接缝、LOD | 显示和选择；不充当世界数据 |

局部规则格或不规则四边形拓扑都可用于原型。先验证点击和墙格效果，按连接质量选择；不预先强制 12×12 上限、WFC 算法或每格一栋房。局部网格维持稳定，编辑时只改变占用和依赖，避免整栋重排。

现有世界用 `(x,y)` 表示地面、`h` 表示高度；3D 几何对应 `(x,h,y)`。当前等距投影为 `screen = origin + ((x-y)*28, (x+y-h)*14)*zoom`，缩放/平移只改投影。逆投影需要已知地面高度；坡地和墙面拾取查询真实几何，不能在高度未知时仅反解到平面。28/14 是现有显示配置，换渲染路线可替换投影，仍保持同一世界身份和局部锚点。

## 玩家点击意味着什么

悬停可扩展墙面，显示一个贴合该面的轻量候选。点击添加指定单元或露台，系统补齐周边结构；在已存在部分执行移除，系统重新解释邻接。社区扩展可以生成相连房屋块，同时保留门、庭院和逐栋可选择性；不限制成“只在一栋旧房轮廓里装饰”。

扩展锚点保存所属房屋、面 ID、局部位置和目标层。重建后通过稳定 ID 重新定位，不靠三角形序号或缓存数组下标认领作品。未选中的城市部分不出现网格，也不受格吸附影响。

## 身份与关系

| 对象 | 保留的身份 |
|---|---|
| 房屋/房屋块 | 稳定 ID、局部拓扑、材质、时代、作者来源 |
| 道路与桥 | 路径、宽度、入口/路口、拓扑版本 |
| 功能区 | 玩家轮廓、用途倾向、风格和可覆盖对象 |
| 玩家街坊 | 名字与明确成员；可跨内部 CID |
| 音乐区域/连接 | 来源对象、风格、网络、静音/独听状态 |

玩家街坊、功能区、几何连片和音乐网络各自有用途，允许重叠而不互相代填。旧 `Community/CID` 可继续作为服务和编曲分桶；不能替玩家规定街坊边界。新生房屋是否加入玩家街坊由显式扩展意图决定，名字不会自行认领整片 CID。

## 几何与声音

空间合法性检查完整占地、道路净空、水体与高差。道路入口来自真实可达道路；隔河无桥不产生步行捷径。共享墙只是连接关系，不合并逐栋作者、音高或操作身份。

旧距离核 `c`、全对集合 `E`、近邻 `N₁₂` 和 R/V 可以用于复现旧混音或分析，不能冻结房屋、要求协和才可建或决定区域升级。规则无边不等于听不见；声场由实际混音决定。[space](01_执行规格/spec.space.md)、[harmony](01_执行规格/spec.harmony.md)

## 五种关系各管一件事

| 关系 | 数据与职责 | 更新原因 |
|---|---|---|
| 物理可达 | 道路节点/边、高程、桥头、入口；人物车辆找路 | 改路、建桥、移动入口 |
| 空间与用途 | 地块/公共轮廓、功能区影响、留地、服务覆盖 | 区域画笔、设施改造、占地变化 |
| 建筑形态 | 共墙、檐口、转角、高差、围合庭院 | 房屋单元增减、邻接几何变化 |
| 声场 | 当前视野、距离、关注、声音控制与真实活动 | 镜头、控制、声音来源进退 |
| 音乐组织 | 区域风格、显式连接、动机/角色槽与应答 | 玩家编排、来源变更、庆典 |

同一对房屋可以共墙但音乐独立，也可以隔河应答但不能步行直达。功能区是用途意图，玩家街坊是作者归属，内部 CID 是计算分桶；三者不互相替代。选房、改名和镜头移动不消耗世界生成随机流。

房屋块要区分“建筑实体”和“附属模块”：新房分配建筑 ID，加层/露台保留宿主建筑 ID 并分配模块 ID。共墙和联合屋顶是派生关系，不能用一张联合图顶替所有成员的命中。拆块后仍能查来源与撤销；支持依赖来自实际结构，不从声学邻接推断。字段与旧档迁移见 [开发接口](20_开发接口与迁移.md)。
