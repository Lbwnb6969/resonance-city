# 施工文档规则

本文件约束施工 AI 的文档写入位置。它是文档治理规则，不是玩法规格。

## 现行文档的唯一入口

| 内容 | 唯一位置 |
|---|---|
| 当前目标、进度、下一步、风险、验证结论 | `PROJECT.md` |
| 设计目的与不可替代的体验要求 | `文档/00_设计意图.md` |
| 世界模型、身份、关系图、技术合同 | `文档/10_世界模型.md`、`文档/19_城市生成管线.md` |
| 城市生长与玩家操作 | `文档/11_核心循环.md`、`文档/14_城市生长.md` |
| 声音结构、声部、编曲和 AudioPlan | `文档/12_声音架构.md`、`文档/01_执行规格/spec.audio.md` |
| 地形、道路、桥、交通和自然 | `文档/13_地形与自然.md`、`文档/19_城市生成管线.md`、`spec.terrain.md`、`spec.city.md` |
| 单局、存档、回放、时代和模式 | `spec.run.md`、`文档/15_时代与地标.md` |
| 具体阈值、公式、接口、验收边界 | `文档/01_执行规格/` |
| 验收命令和通过条件 | `文档/02_验收/DOD.md`、`文档/03_任务/` |
| 尚未裁定的产品选择 | `文档/待裁定与依赖.md` |
| 外部项目、源码、网址和用途 | `文档/参考索引.md` |

同一条规则只能有一个权威位置。其他文档只解释或链接，不复制第二套数值。

## 新内容应该放在哪里

1. 新设计先判断是否改变用户目标或现行规则。改变规则就改对应的 `spec` 或 10–19 正文，并在 `PROJECT.md` 写状态；不改变规则的实现细节放到所属技术正文。
2. 新的外部项目、源码入口或网址只登记到 `参考索引.md`，注明相关子系统、具体入口和使用边界。不要把仓库说明、源码大段复制到现行文档。
3. 运行日志、截图说明、历史轮次、失败尝试、研究过程放到 `验证记录/` 或 `文档/废弃/`。它们不能使用“当前规则”“必须实现”等措辞覆盖现行 spec。
4. 未裁定的选择只进入 `待裁定与依赖.md`，同时写清阻塞的任务；不要在技术研究稿里悄悄定案。
5. 一个施工任务只新增一个必要的规范段落。已有章节能承载时直接更新，不新建日期化正文档，不新建平行规格。

## 施工 AI 的写入限制

- 默认阅读顺序：`PROJECT.md` → `文档/README.md` → 当前任务对应的 spec、任务单和 DOD。默认不读 `废弃/`、`90_存档/`、历史报告、源码阅读包。
- 不把“已检索”“已写代码”“技术路线选定”“局部测试通过”写成“全系统已完成”。状态只能使用：`已裁定`、`已有切片`、`待实施`、`待验证`、`待裁定`。
- 不在正文加入第三方仓库源码、长日志、完整测试输出、重复的历史背景或同一规则的第二份解释。
- 新增实现合同必须同时说明：对象/字段、提交时机、稳定 ID、失败行为、验证入口。缺一项就放到任务或待裁定，不写成现行规则。
- 修改规则后先搜索旧表、旧阈值和旧链接；发现冲突必须在同一变更中处理，不能留下“新旧都像当前”的写法。
- 参考项目只提供实现启发或 API 事实，不能替代本项目的设计决策。具体采用范围以 `参考索引.md` 的“使用边界”为准。

## 归档与移除

重要内容不删除。被替代的文件移动到 `文档/废弃/`，并保留原文件名；归档目录的 README 记录替代正文和仍需回收的局部内容。只有生成缓存、重复的临时产物和明确无价值的空文件可以删除。

每次归档至少写明：原文件、替代文件、保留价值、是否还有未吸收内容。若一份历史稿仍被正文或 `PROJECT.md` 链接，先修链接或回收必要内容，再归档。

## 文档变更后的最小检查

检查现行入口链接、规格索引、重复规则、废弃目录链接和新增参考项目索引；只运行能证明本次文档变更正确的检查。文档改动不自动触发全量游戏测试。
