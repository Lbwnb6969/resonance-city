# 声音与反馈

## 1. 定位

声音不参与资源循环、胜负、任务门槛或建筑合法性。它的职责是让玩家感到“我刚才的操作被世界听见了”，并帮助玩家理解空间关系。视觉反馈始终独立可读，关闭声音不会让玩法失效。

## 2. 默认声场

1. **视野内优先**：镜头内的道路、房屋、功能区和自然以低密度环境层、短动机和局部拟音回应。
2. **远处偶发**：每个乐句最多少量远端回应，位置来自城市真实存在的区域；不让远处音效抢走当前操作焦点。
3. **特殊时刻全城发声**：新区域完成、地标落成、昼夜切换或玩家主动请求时，暂时提高全城声部并在一个乐句内回落。
4. **静默也是状态**：空地、尚未确认的预览和被玩家静音的区域保持留白，不用噪声填满。

## 3. 区域音乐连接

玩家可以把区域加入同一“音乐网络”，也可以为不同区域选择不同音乐风格（例如暖庭、集市、临水、夜花园）。连接只改变配器、音色、节奏密度和过渡方式，不改变道路、建筑或功能区合法性。

- 同网络区域共享调性和少量动机，距离越远，连接越稀疏；
- 相邻但未连接的区域保留各自风格，在边界使用短过渡层；
- 玩家取消连接后，当前乐句完成淡出，下一乐句恢复独立风格；
- 所有声音连接都可试听、撤销和保存。

## 4. 技术边界

采用“少量实时声部 + 事件化拟音 + 混音聚合”：同时活跃的音乐声部先以 32 个为目标上限，远处区域使用共享 stem 或事件片段；每栋房屋不创建独立常驻 AudioStreamPlayer。声音事件绑定稳定区域/操作 ID，不绑定临时预览节点。声音生成失败只丢弃该次反馈，不回滚已经确认的城市操作。
