# 第1部分｜项目适配设计总纲

**版本：整合提案1.0｜2026-10-27｜适用基线：上传项目M73快照**

本文件是文档37与38的统一后续设计。当前实现以源码、根backlog和文档35/36为依据；新规则均是待施工方案。任务细节见 《40_分阶段施工与验收》，原文纠错见 《41_代码审计与两版取舍》。

## 1. 当前阶段与这轮的目标

项目已经具备相当完整的造城底座：道路三种绘制方式、有机房屋、四时代原型、地形与水岸、街具、居民生活、供需与手札，以及固定声部预算的交互音乐。根backlog记录M01～M73、UI01～04、RF01～08全部通过。本次运行了Harness、文档链接检查及8项Harness自测，均通过；没有Godot可执行文件，因此本次没有重跑实窗、旧档或听音验收。

现在最值得投入的不是继续增加互不关联的功能，而是使已有功能形成玩家能够理解、操控和享受的整体：**画出一座自己喜欢的城，看到生活发生，听到空间关系被演奏，再决定下一笔。**

本轮达成三个结果：

1. **创作顺手。** 开局能够选择所有现有普通时代风貌和核心画具；常用操作清晰，细项不挡住施工区域；空间变化可撤销。
2. **声音有作品感。** 有可辨认的动机、句法、段落与休息；城市改变听得出来，镜头移动不会不停打断旋律。
3. **成长不抢走创作。** 手札和地标提供新想法，生活系统解释城市为何变得丰富；不再同时催多个任务。

本轮不增加新经济货币、失败结算、重开惩罚、抽卡付费、全新交通模拟、多人联机或3000～5000栋规模目标。既有可用能力继续保留。300屋编辑与已有作品集用作回归场景，不等于最大规模承诺。

## 2. 产品主循环与玩家实际选择

### 2.1 一个主循环，三种反馈

**造形 → 生活与演奏 → 看与听 → 调整或收藏 → 继续造形。**

同一笔建造应尽量同时带来三种反馈，而不是产生三条独立任务线：

| 玩家行为 | 立即可见的反馈 | 随后可听/可观察的反馈 | 下一次有意义的选择 |
|---|---|---|---|
| 沿水岸建一排房屋、留出步道 | 建筑与水岸形成连续轮廓，步道可走 | 水岸风格候选增加，下一乐句出现摇曳织体 | 扩成密水巷，还是留下开阔岸线 |
| 接通面包坊与茶座 | 路径成立，实际居民送达 | 在原伴奏留白处产生轻应答，不提高全城音量 | 增加另一处生活点，还是保留安静庭院 |
| 在高地做台阶和柱廊 | 台地体量、真实进出路径形成 | 可见行走触发受限短音，高地织体具有留白 | 增加层次，还是把视线留向远方 |
| 点选一个街区试听 | 焦点有轻微标识 | 该街区进入既有领唱候选；换句后听到差别 | 保持当前段落或回到自动选择 |
| 获得一张灵感手札 | 轻提示进入已有手札入口 | 选取后获得可定位的外观或变奏选项 | 使用、暂存或暂不理会 |

建筑数量不是音乐复杂度的线性旋钮。密城也应有静区；小城也能演出一段完整音乐。不要让玩家必须堆满房屋才“听到完整版”。

### 2.2 前十分钟目标体验

这些时间是试玩观察窗口，不是倒计时机制。

- **0～2分钟：** 空地、核心画具与一条轻提示。玩家自选时代，落下一栋房屋，听到温和的首屋回应；不弹抽卡、时代门槛和经营账本。
- **2～5分钟：** 画路、扩建、改颜色或加水岸。能迅速发现拖画、点画、撤销；几栋建筑形成一个稳定可听的主题。
- **5～8分钟：** 安排一个生活用途，看见居民活动；若出现灵感，提示进入收件夹，继续操作不会被打断。
- **8～10分钟：** 平移或点选另一个街区，能解释声音为何变化；可停下来听，也可继续造。

试玩重点不是“十分钟必抽一张卡”，而是玩家是否愿意再添一笔、能否找到撤销、是否听出自己城市的区别。

### 3.1 何谓自由，何谓成长

“开局自由”指所有现有普通风貌、基础工具、道路和街具可选择。形状条件、空间净空、地标占地仍然有效：它们保障造城结果正确，不是进度门槛。

新城默认自由创作。现有手札仍可发现装饰变体、特殊地标和乐句变奏；原型库、核心音乐风格、基础造景不藏在随机卡后。玩家可关闭灵感提示继续建城，不影响基础音乐完整性。

旧城保留历史解锁、抽卡、库存和数值规则。通过显式“开启自由创作”转换建造政策；转换前保存备份，不伪造历史茶聚、问答或完成任务记录。**本轮不再将产品主标签写成轻肉鸽**：没有失败重开与一局式构筑时，称“自由造城与灵感收集”更符合实际体验。

## 4. 建造交互：减少干扰，同时保留精确控制

### 4.1 道路

当前 `city_creation_road_tool.gd` 已支持拖画、点击转精确直路、Tab切直/曲。后续重点是呈现与事件分配，不重写整套道路几何。

| 输入/界面 | 统一行为 |
|---|---|
| 左键拖动 | 沿用当前自由画，预览与提交共用同一几何计划 |
| 左键点击后移动再点 | 精确直路；曲路继续使用现有控制点/终点流程 |
| Tab | 活动道路草稿中切换直/曲，保留已有限制 |
| 右键 | 保留现有取消及特定锁段语义；不再兼任切曲直 |
| 滚轮 | 默认缩放镜头；指针在宽度控件上时才调整宽度 |
| `[` / `]` | 修路模式下切换既有宽度档，输入框聚焦时不捕获 |
| 可选Shift+滚轮 | 只有确认不与现有操作冲突后，才作为宽度快捷方式 |
| Alt | 继续用于既有吸附释放/操作修饰，不改变肌肉记忆 |
| 铺装/街具控件 | 显示当前值，点击打开有文字与图标的选择面板；保留8/6项完整选择 |

先用已有离散宽度，不在本轮引入无级宽度导致全链路重测。`原宽`按当前道路身份与样式解析，`原款`保留旧装饰；不能等同于固定默认值。

默认不再将全部道路选项铺成四行。普通状态一行，展开选择仅占必要区域；屏幕空间不足时向侧面展开。验收以1024和1440宽窗口中真实控制点可见、可点击为准，不强制“高度减少60%”。快捷键有轻提示，不能为了极简把功能变成只能猜出来的手势。

### 4.2 房屋

沿用 `city_creation_lean_inspector.gd` 已隐藏风格、合唱、性情按钮的结果，保留时代/原型、配色、加建与微雕入口。用途和详细外观沿用已有详情页及共用用途选择器。

自动折翼、连檐和圆角继续服从已有适用条件。用户手动指定过的形变优先，不因道路微调悄悄重塑房屋。微雕循环必须显示当前模式，支持返回默认；阳台、外挑和折翼的碰撞、入口、拾取与撤销保持一致。

### 4.3 留白与自动微景

微景只在可以解释的空间关系中出现：路与屋夹角、围合边缘、低坡水岸。`1.5～3.2m`仅是文档37的试验范围，应以已有尺度和实际净空校准。

派生流程必须先找到真实道路邻接或围合，再排除门口、路面、椅子、桥头和水面；同一空间最多一个派生候选。不满足条件时留白就是正确结果，不用花、石台或灯填满。

`Plan.support`已被经营条件消费，草遮罩也使用pockets。改变pockets时必须区分：生活支持是否来自真实可达街景；装饰隐藏是否只是玩家外观偏好。视觉开关不能意外剥夺旧城权益，已经不存在的支撑也不能无限保留虚假运营状态。旧城采用原规则，转换后使用新规则，并显示实际停业原因；已有完成奖励不回收。

## 5. 音乐：一座城组织一段音乐

### 5.1 现状与真正要改的内容

已核对：`lead()`每小节重复同一组拍点；`counter()`部分槽位重复一个companion；`foundation()`从0.2095秒起持续2.60秒；`long_form.gd`主要控制段落音量和周期事件。它们能解释机械感风险，但“实际每3秒全城断气”仍需分轨及Master验证，因为其他声部和混响可能覆盖。

已经有环形PCM写入：`music.gd::_add_note()`的wrap会执行模索引。缺的不是另造一个环形缓冲区，而是连续谱材、正确包络、换曲处理与测试。

本轮音乐的优先级：**乐句可记住 → 伴奏会流动和休息 → 段落有变化 → 城市能改变它 → 多风格扩展。** 音符更多只是手段，不是质量结论。

### 5.2 五种职责，保留现有四层编号

原文38把领唱从layer3改称“第四层”，会冲撞当前唯一领唱守卫。采用语义职责字段 `role`，保留现有 `layer` 的工程含义。

| 音乐职责role | 现有layer | 主要承载 | 设计约束 |
|---|---:|---|---|
| foundation：根音与持续和声 | 1 | foundation长轨 | 连续支撑但不持续占满低频；根据和声处理交接尾音 |
| pulse：分解织体 | 2 | air/terrace或当选的次区轨 | 一个主要推进纹理；其他伴奏降密度或退出 |
| answer：内声部与回答 | 2 | 既有家族胜出伴奏轨 | 主旋律长音/休止处回答；必要双音可由同一领唱stream预混 |
| lead：主题 | 3 | 唯一当选街区长轨 | 一个领唱所有者；切换与会场模式都遵守归属守卫 |
| sparkle：生活/建造点缀 | 4 | 既有4短槽 | 自动星芒沿用每小节最多2颗及优先级；不与操作反馈无限争抢 |

12长轨、4短槽、6总线、2自然声是音频资源预算，不代表12条永远同时出声。低音区、内声部、旋律可有适量重叠；MIDI基频不是整个乐器的频带，不承诺“频率完全错开”。

深流段的低音领唱仍是 `role=lead, layer=3`，由段落音域profile决定允许的音区。不可把它改成layer1来躲避领唱守卫，也不可再被旧 `note()->fold()`折回高音。

### 5.3 乐句与和声

每个核心风格先创作一个8小节主题及可解释的变体。至少包含呈示、应答、展开、收束功能；允许复现动机，不要求8小节处处不同。主旋律与伴奏共享和声时间线。

音符使用拍位置而不是散落的秒常量：第一阶段固定80 BPM、4/4、每拍0.75秒、8小节24秒。常规细分使用四分、八分、十六分；已有22ms一类微时差可独立保存为 `micro_offset_ms`，不能拿随意偏离网格当“人性化”。

伴奏由经过选配的和弦音与转位形成。允许持续音、重复音、固定音型，不采用“相邻音高绝对不能相同”的错误规则。真正避免的是所有小节、所有风格都机械使用同一音高和节奏。

经过音是乐句中的弱拍连接；必须有调式、前后音与解决位置依据。它不能先被强制吸附成和弦音、再声称保留经过音。短音玩具仍以和弦内音安全吸附为主，两种规则分别实现。sus4→3只在当前和弦与调式允许时使用，五声调式不强塞缺失音。

音域采用整句候选路径选择：在合法音级与乐器音域内，综合旋律轮廓、跳进、终止位置和前后句连接，决定整句八度布局。可先用小规模动态规划或枚举有限八度方案，不使用逐音 `clamp()`生成新的半音。若一句无法容纳，选择已编写的窄音域变体，而不是最后强裁。

### 5.4 三种核心风格先完成，六种作为后续内容

| 风格ID（拟新增） | 第一批/后续 | 城市倾向 | 主要差异与约束 |
|---|---|---|---|
| `pastoral_breeze` | 第一批 | 古典庭院、低密花园 | 木管主题、吉他指弹，句尾留白；明朗但不过亮 |
| `deep_flow` | 第一批 | 现代临水、开阔岸线 | 毛毡琴、低中音内声部，展开段有流动织体，深流段移交低音领唱 |
| `felt_nocturne` | 第一批 | 夜景、静坐、安静模式 | 稀疏琴音和泛音回答，允许长休止；不追求2.2/s密度下限 |
| `waterside_sway` | 第二批 | 连拱水巷、跨岸街区 | 摇曳型问答与竖琴织体；先在4/4下写作，不冒称真实6/8船歌 |
| `clockwork_dance` | 第二批 | 钟表工坊、轨街 | 轻机械脉动与木管短句；第一版为4/4舞曲，不冒称3/4圆舞 |
| `highland_pentatonic` | 第二批 | 高地、石阶、柱廊 | 五声音阶、开放五度与疏密互答，不依靠统一降八度制造区别 |

曲库名称不使用“齐马蓝复刻”“萨蒂原曲”等表述。参考曲用于分析与设计方向，新谱材需独立创作。现有8个track/style键与新的风格ID通过适配表关联，保留旧档和旧stream别名。

真正3/4、6/8、变速是另一个拍钟工程：需要同步修改小节、cue网格、演出计划、缓存与录音标记。本轮先保留80 BPM的可靠同步，不以加密音符冒充125 BPM。

### 5.5 144秒曲式：三个材料家族，六段安排

24秒是同步单元，不应每24或48秒换成陌生歌曲。一个主题完成六段后才能选择下一个；镜头切换改变配器和来源，尽量保留主题连续性。

| 段落 | 时间 | 变化应发生在哪里 |
|---|---|---|
| P0 呈示 | 0～24s | A主题、轻伴奏，明确动机 |
| P1 展开 | 24～48s | B变体，增加流动织体或回答，不能只是加音量 |
| P2 透气 | 48～72s | A的薄织体/高音色版本；低音后退，但不靠Master静音制造休止 |
| P3 回望 | 72～96s | B重组，恢复根音支撑、互答或不同转位 |
| P4 对比 | 96～120s | deep_flow使用C深流；其他风格使用适合自己的静段/开放五度/独奏 |
| P5 收束 | 120～144s | A终止变体，减密度并准备下一主题或调式 |

每段的差异至少在乐谱事件、音域或配器中有真实改变；不规定所有段都换主题。频谱变暗与听感包裹是可尝试结果，不能声称移低八度必然得到260～320Hz质心。

### 5.6 城市到音乐的可解释映射

保留已有地形调式、镜头焦点、家族胜出与地区连接，增加统一的配器计划输出，避免多个系统各自抢音量。

| 输入 | 决定什么 | 不决定什么 |
|---|---|---|
| 当前焦点及街区身份 | 领唱归属、可听空间位置 | 不直接重启全曲 |
| 风貌、临水、高地等稳定上下文 | 风格候选和配器权重 | 不每帧随机换风格 |
| 真实运营与完成送达 | 下一乐句回答机会、可用声部 | 不制造无限叠加的音量奖励 |
| 道路连接/真实跨区关系 | 回答对象与空间对答候选 | 不凭“附近有两栋屋”虚构完成事件 |
| 昼夜、静坐状态 | 织体密度与配器倾向 | 不无条件覆盖玩家固定风格 |
| 玩家选择 | 自动/固定风格/安静，及试听焦点 | 不改变生产倍速，也不伪造城市成果 |

风格候选先稳定约一个小节，再在乐句边界提交；首版最短持有一个24秒单元。领唱归属的细粒度切换继续走现有安全逻辑，风格与主题换曲使用更长边界。连续快速拖镜头期间只更新待选目标，不排队播放所有路过街区。

优先级：暂停/静音 → 显式试听或演出 → 玩家固定风格 → 稳定城市上下文 → 昼夜修饰 → 细节生活事件。安静模式是声音偏好，独立于现有影响生活的 `temperament`。

判定城市映射是否有效，应对同一种子、同一主题做受控A/B：只改变道路连接、生活运营或焦点中的一项，记录对应plan差异并实际听到变化。不能通过直接给播放器换音轨来伪装“城市组合”。

## 6. 连续音频、切换与缓存的工程契约

### 6.1 先补切换，再延长尾音

当前 `smooth_variation.gd` 将layered stream的小节前0.12秒视为可直接替换窗口。延长尾音后这个假设失效，必须同一任务修复。`theme_pcm.gd`关于静音缝的注释和相关断言同步更新。

稳妥的首版策略：

1. 在现有模索引混音中生成跨小节基础声部，起音与释放由音色包络决定；不能只把所有duration统一设为3.15。
2. 在和弦变化处对旧音尾与新音起音做受控衔接；不允许大量旧三度跨入冲突和弦。循环首尾单独检查和声。
3. 伴奏/基础层切换使用预生成PCM过渡或同一播放器内部的复合流，避免新建播放器。切换片段的源相位、目标相位和共享拍钟必须明确。
4. 领唱换宿主用短的淡出—移交—淡入，始终只有一个可听领唱所有者；避免两个完整主题同时交叉淡化。
5. 冷启动不带上一轮尾音“凭空提前响起”；以启动淡入或首圈专用片段处理。稳定循环、第一次播放、暂停恢复和换调分别验收。
6. 未能在边界前备好新谱材时继续旧主题，并记录延迟原因；不得临时同步生成所有音库阻塞编辑。

这里不假定六总线中的某两条永远空闲，也不把四短槽当通用第二组长轨。M78先用一个主题完成过渡原型、确定资源与音质，再推广。

### 6.2 缓存与首启

新增 `preset/section/role/register/seed` 后，`chamber_roles.prepare()`的cache key、stream key、`bank_cache.SOURCES`及导出stamp必须一起更新。角色编号和风格名不能只改生成器，不改播放选择器。

缓存键至少包括：生成器版本、乐谱内容哈希、风格、段落材料、调式、角色/音域配置、确定性种子和采样配置。缓存失效时有可用的最小默认声部，不让首屋长时间无声。

每条24秒、22.05kHz、16位单声道PCM约1,058,400字节。若盲目生成 `6风格×6段×10调式×12轨`，即使不计变体也约4.57GB原始PCM；固定播放器数量不能解决存储与生成成本。

因此只预烘焙最小默认集合，共享相同角色素材，变体按需构建并有界缓存；其余在安全后台流程预备。后台不得访问非线程安全场景节点，发布需校验城市revision与请求版本。QOA轻量库、运行时解码、导出stamp与`<100,000,000字节`仓库限制都要实测，不承诺在压缩率未知时“六风格零成本”。

### 6.3 声音验收的正确用途

- **硬正确性：** 无NaN/Inf、无削波、预算不变、拍钟不漂移、唯一领唱、空队列/缺素材可回退、主线程无明显合成阻塞。
- **诊断：** 音头密度、RMS、频谱质心、段落音域、静音分布、边界波形和缓存命中。不同风格分别建基线。
- **听评：** 音色是否刺耳、动机是否可辨、循环是否露缝、变化是否打断、静段是否自然、五分钟是否疲劳。

参考数据中的3.18/s是检测器的混音音头统计，不等于MIDI事件数。11次主旋律起音/24秒与1.13/s不矛盾，它们测量对象不同。RMS也不是LUFS。测量只说明具体录音，不能推出“好听程度百分比”。

## 7. 音乐分析工作流：特征、设计、谱材分开

### 7.1 三份数据，禁止混写

| 文件类型（拟定） | 允许包含 | 不能声称 |
|---|---|---|
| `reference_features.json` | 源哈希、分析器版本、BPM候选、调性估计、时间窗特征、置信信息 | 已提取逐音旋律、逐和弦时间线或分轨 |
| `style_brief.json` | 从特征得到的创作建议、段落方向、人工选择及理由 | 建议值都是实测真值 |
| `score_preset.json` | 独立编写并验证的音符事件、和声、织体、音区和段落表 | 从整曲频谱直接恢复原作 |

直接复用当前已有的 `数据/音乐参考/齐马蓝_组合参考.json` 作为第一份可信输入，它明确标注 `analysis_reference_not_runtime_preset`。外部 `mIDDLEFILE/music/analyze.py` 在用户本机，上传快照不含该工具和全部原始结果；不假定本次环境能执行它。

### 7.2 可复现过程

1. **登记参考。** 记录文件哈希、时长、解码与分析配置；保留分析器输出原件。
2. **规范化特征。** 严格映射实际字段；单位、缺失值、NaN、空时间窗和时间轴单调性必须检查。不把缺失调性默认为E大调。
3. **标注结构建议。** 按原时间窗或明确归一化区间提出“更疏/更暗/更流动”等建议；不能默默六等分就称乐段识别。必要时人工调整边界。
4. **原创谱材。** Agent根据风格brief写出8小节乐句、和声与变体；统计不足以确定的内容写 `authored`，不写 `measured`。
5. **静态验证。** 拍位、音域、调式/和弦标签、音色枚举、段落引用和缓存键通过后才生成PCM。
6. **真实城市录音。** 使用普通建城API生成城市，以当前正式音频路径录制；同时记录transport起点、段落ID、风格、领唱来源与音库签名。
7. **同口径比较。** 用同一分析链处理参考和游戏；相对RMS用于看起伏。听评另生成响度匹配副本，原始录音保留；不让“更响”掩盖谱材问题。
8. **仅改最主要缺陷。** 每轮挑一个具体问题修改并保留前后录音，避免一次改谱、音色、音量和相机而失去归因。

### 7.3 拟定乐谱最小契约

`score_preset.json`必须有：`schema_version`、`preset_id`、`content_hash`、`tempo_bpm`、`meter`、`loop_bars`、`seed_policy`、`harmony`、`materials`、`sections`和`provenance`。

每个音符至少记录：`bar`、`beat`、`duration_beats`、`midi`或可解析的调式音级、`velocity`、`timbre`、`role`、`articulation`。`passing_tone`为真时还须说明目标/解决音；音符跨小节允许，但不能产生无限尾音。运行时适配层统一换算为现有 `start/duration/midi/gain/timbre/layer`，增益通过集中映射，不把MIDI力度直接当线性音量。

第一版允许的时间配置固定为80 BPM、4/4、8小节。不支持的拍号明确拒绝，不静默变成4/4。解析JSON数据，不执行输入的GDScript，不把style_id直接拼成代码符号。

## 8. 地标、手札与生活的整合

### 8.1 地标由玩家放置

保留四个传世家族及现有已获权益。新城达到条件后出现“可放置地标”，玩家选址、旋转、预览、放置；没有合法地块就保留待放置状态。取消或拆除不回收永久蓝图。

地面地标需要真正的新实体契约，不能只是把屋顶网格Y坐标设为0：稳定ID、蓝图ID、位置朝向、占地、支撑高度、入口、草遮罩、拾取、碰撞、撤销重做、保存冷读均必须接通。

首版每家族提供一个固定体量，基于既有视觉构件适配基座；保留原家族命名与权益，不将已有浑天仪权益悄悄换成另一种剧场奖励。先用一个地标贯通全部接口，再扩四种外形。不开放任意多层扩建和复杂内部寻路。

旧档的冠冕属于派生展示，实际手札权益应完整保留。默认不改变已保存城市的外观；转换时让用户选择保留旧展示或收为可放置蓝图。两种表示不能重复计收益，禁止加载旧档时自动往空地塞地标。

### 8.2 灵感手札

采用已有HarmonyJourney和统一领奖入口，不新增Harmony Flow计数器。每次最多一个轻提示；卡片可稍后选，记录不能丢，也不能重复领。继续沿用原稀有度、保底、重读及数值，首轮不同时重平衡整个供需体系。

先做两张样板：一张水岸装饰/柔和回答，一张柱廊藤蔓/织体变奏。每张都有获得条件、适用地块、可定位外观、音乐作用、关闭装饰后的行为与旧档默认。

装饰只出现在合法空间，稀有不等于更大、更亮或更吵。手札带来的变奏从下一乐句生效，不改变BPM、不叠第二领唱。基础风格始终可用，新卡给变体与个性。

### 8.3 居民与长椅

M64已有真实上楼、凭栏及通路验证，不能当作待从零开发。新增重点是M72独立街具长椅与现有居民行为的接通：候选座位、占用、接近路径、就坐、起身、座椅删除后的安全退出。

不能为展示动画创建第二批装饰居民；使用现有生活实体。播放音乐回应仍通过完成事件和既有短音队列，不能在椅子脚本里自行新增播放器。

静坐沿用现有漫步相机与V入口；只有接入真实座位的椅子/阳台才可选。1.15m只是初始视线高度，实际由座位变换及模型尺度确定；Esc/V恢复原相机位置、控制和选择，不把玩家卡在建筑内部。

当前项目是Compatibility渲染，本轮不把浅景深作为交付前提。先做好构图、遮挡与退出；若特效路径在本地不支持，就不引入它。12秒巡礼复用现有收藏/运镜能力，随时可打断，不成为新的成长系统。

## 9. 视觉收口：修关系，而非再加覆盖物

统一的验收顺序：**城市远景 → 街区轮廓 → 路屋/水岸接合 → 屋面材质 → 微观装饰。** 每个修改需要同机位前后图；夜景不应用过亮发光隐藏模型缺陷。

| 问题候选 | 首选处理 | 不默认采用的处理 |
|---|---|---|
| L/U凹角屋谷瓦行变形 | 核对面划分、UV与真实坡向；排水天沟仅在结构合理处生成 | 所有接缝覆盖粗压条 |
| 多路交叉口铺装尖角 | 修接缝/分区/铺装方向，保持道路身份 | 每个交叉口强制放石徽 |
| 树池穿草 | 将真实装饰足迹纳入草遮罩及增量脏区 | 给整个街区清空草 |
| 石桥接岸生硬 | 依据真实岸高与坡度生成护翼和过渡 | 每座桥复制同一悬空石块 |
| 遮阳篷与植物僵硬 | 共享风向与时间，保留不同相位和材质振幅 | 全城同相摆动、石件也摇晃 |

文档35明确保留union凹角P3和首次smooth/Undo停顿；原文37/38另列的“最后四处”须先复现再决定是否为bug。不能在没有原图证据时宣布已经定位全部美术问题。

自动装饰允许关闭，尊重玩家留白。截图不设“所有画面色相不得超过三种”之类生硬门槛；通过墙、屋顶、植被、水面的层次和焦点判断画面是否干净。

## 10. 存档与兼容：明确升级，不伪造无成本迁移

### 10.1 为什么需要版本设计

目前最高扩展为Schema19；`era_unlocks`同时参与UI、建造API、时代验证和现代共鸣校验。直接把四时代塞进新城，会触发现代时代缺少共鸣证据的失败。只把按钮变亮又会被State拒绝。

本轮建议新增Schema20的独立扩展块，版本号在M75确认未被其他工作占用后使用。若已占用，按当前最高版本递增，并同步所有文档/任务。不要以“Schema1～19兼容”为理由把新实体塞进无校验的旧字典。

### 10.2 三类状态必须分开

| 状态类别 | 内容 | 历史/撤销规则 |
|---|---|---|
| 创作政策 | `creation_policy=legacy/free`及迁移版本 | 旧档缺省legacy；显式转换持久化，不伪造成就 |
| 永久成长 | 已获时代纪念、手札、蓝图、收藏记录 | 沿用既有已赚取权益保留语义，撤销建筑不重复发奖 |
| 作者内容 | 房屋、道路、新地标、局部装饰选择、城市音乐偏好 | 纳入事务快照、撤销重做与冷读 |

拟定扩展包含 `creative_settings`、`placed_landmarks`、地标ID高水位及必要表现偏好。座位占用、实时音符、合成缓存、短音队列和相机过渡是派生/瞬态，不保存为城市事实。可保存音乐风格偏好与确定性种子，但无需保证跨进程样本级继续同一尾音。

建造可用性由集中函数（拟新增 `can_build_era`、`can_assign_role`）判断，兼顾自由政策与历史模式；各UI及State入口调用同一规则。验证器在free政策下检查有效时代/用途及几何，不要求伪造旧解锁；legacy政策保持原校验。

### 10.3 迁移与回退

- Schema1～19读取仍走原验证，缺失新字段有确定默认。原档只读加载不自动重写。
- 用户选择转换时创建隔离备份，再产生新版本保存。旧成就、库存、卡牌和作者几何保持；对表现或可用性变化作可理解提示。
- 新版本读旧档是向后兼容；**旧程序不保证读新版本存档。** 回滚程序使用转换前备份，不剥除未知字段伪装降级。
- 现有375旧档及27作品是历史回归集合，必须按新程序重新运行。新增free新城、legacy未转换、显式转换、地标事务、 malformed字段、未知蓝图与ID冲突案例。
- 新功能回退开关只能影响表现或路由，不可偷偷丢弃已保存地标。某蓝图不可用时保留身份并用明确占位/禁操作策略处理。

## 11. 范围、优先级与停止标准

施工按 《40_分阶段施工与验收》 的M75～M86执行。每个大里程碑内拆小步，单步验证，不一口气跨模块修改。

**先证明的最小整体：** 自由新城 → 常用修路操作 → 8小节原创主题 → 连续基础层与安全切换 → 三核心风格 → 真实城市改变回答/配器 → 144秒段落 → 保存再打开仍正确。

在此成立之前，不扩写六风格大曲库、不开发装饰稀有度的完整资产矩阵、不做新镜头特效。后续地标、手札与生活都必须回到这个循环。

完成条件：没有存档/操作/声音正确性阻断；核心体验有实际试玩和可听录音；所有拟定范围完成或逐项说明阻塞；不足有具体时间戳/机位。主观评分可记录，但不要求固定9.2分，不把“零削波”写成“音乐已经好听”。

这一轮交付应让玩家更愿意建、停下来看、再听一会儿。不能仅用新增脚本数量、全绿测试或系统名词证明目标达成。
