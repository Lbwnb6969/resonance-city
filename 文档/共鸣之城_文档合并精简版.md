### 共鸣之城 · 设计意图

#### 一句话

亲手塑造一座会回应你的城市：点击社区房子，让房屋和露台按邻接关系长出来；画道路、放重要建筑、划功能区、种植被，让系统把简单意图变成自然漂亮的地方。音乐增强感官和成就感。

#### 玩家掌握什么

玩家掌握大形状、位置、连接和风格，系统负责门窗、檐口、屋顶接缝、台阶、路缘和小装饰。社区由玩家点击推进；空地不会因为等待而自动填满。房屋墙面有局部格，城市其他部分连续无格。

以 Foundation、Tiny Glade、Townscaper 三个本地参考库为基础，重新构建一款全新的《共鸣之城》。Townscaper 提供社区点击、局部邻接生成和编辑历史；Tiny Glade 提供连续空间、建筑接合与自然表现；Foundation 提供独立建筑功能、居民行为和可持续街坊生活。三者在本作的新世界模型里组合，具体规则、代码和生产素材由本作实现。[来源](参考索引.md)

水体、道路、植被的生成与表现首选 Tiny Glade 参考，Foundation 补充地形、水岸、道路可达和居民活动的系统关系。房屋墙格不扩展成城市道路或自然的网格。性能是实现要求：局部编辑只重建受影响对象，连续自然按空间块组织，测量完整有声场景的帧时与编辑延迟，再决定细节预算。

道路以 Tiny Glade 那种自由画、转弯和接头顺滑的手感为目标，想怎么画就怎么画；同时提供两点直拉。预览与落定使用同一连续曲线，路口融合并去掉内部路缘；路线受真实墙面/水岸的空间约束，不受城市格限制。

#### 五个体验支柱

| 支柱 | 做出来的表现 |
|---|---|
| 简单动作，丰富结果 | 一次点击补齐房屋/露台；一条路径带出入口、路缘与台阶 |
| 结果可理解 | 玩家指定的位置和轮廓稳定，小细节有受控变化；邻接改变只更新相关局部 |
| 城市连成一个地方 | 房屋有共享墙、连续檐口和庭院；路、门、坡、树之间有自然过渡 |
| 作品有历史 | 五时代、历史街区、强力建筑、玩家命名与作品保存让旧选择继续有价值 |
| 城市会回应 | 视野内为主要声场，远处偶发回应，特殊时刻全城参与；听觉不决定建造资格 |

#### 美术方向

草地仍需持续在 Tiny Glade 参考基础上改进，当前程序草簇与平面底色不构成最终观感。房屋及其社区/功能区参与整个游戏的音乐；和谐、舒服的听感和城市建设之外的正反馈优先。街坊演出时，周围房屋以应答、亮窗或轻量动作参与，不能只让演奏庭单独发声。

美术以本地 Tiny Glade 参考库为基础，统一暖软材质、自然接合、丰润植被与舒服光影。清楚体块承载高价值细节，保留道路入口、建筑接缝和自然边缘；根据完整场景性能调整细节密度。[完整美术标准](17_美术规格.md)

第一时代继续采用古希腊/古罗马的暖石、陶瓦、柱廊、庭院、橄榄树和柏树。后时代各有材料与轮廓词汇，整个项目保持统一的比例和光影。

#### 长期方向

玩家从一个舒服的小街坊起步，扩展城市、形成不同功能区、解锁能改变建造方式的强力建筑，再决定如何更新或保留旧街区。自由建设是默认体验；城市史作为可选引导，完成后仍能继续同一座城。摄影和音频导出保留为作品交付方向。

#### 取舍

选择最能达成体验的方案。先把一次点击、一段道路和一个接缝做好，再扩大内容与城市规模。采用现有代码能节省工作的部分，玩法变化需要时可以更换架构、渲染方式或库。

硬边界只保留玩家控制、空间合法、撤销/作品完整性、声音不设玩法门槛及素材权利。原有 R/V、债务、每乐句额度、音程冻结、固定乐章数和音频答题不再约束默认建设。它们的旧实现资料仍可检索。[版本整合说明](版本整合说明.md)

#### AUDIO-VIEW / AUDIO-OPTION · 来源和控制

AudioPlan 保存版本、提交帧、source/receiver/event ID、角色/音高/音色、起止/包络、增益/声像和签名；实际活动标记只读已渲染可听窗口。声音节点槽和来源对象是两个 ID，复用节点不借用旧事件。

普通视野调度从当前可见城市选择，画面外回应只取真实来源，冷入不补播历史。玩家明确控制覆盖自动选择，退出独听恢复原设置。精确选区用成员 ID，不能扩大成全 CID；区域音乐连接保存来源与修订，重叠控制按明确静音优先、独听/聚焦优先于自动的顺序处理。

全城演出按区域轮换或合奏代表实现参与，仍计装饰、环境、尾音和交叉节点。来源撤销/删除后停止未来事件并淡出已有尾音；Reply 只一次、不递归。响度、相位/控制隔离、同源试听和设备时间规则见 [开发接口](20_开发接口与迁移.md)。

首次验证一段视野进出、一处远端回应、一场全城演出，以及静音后完成同样建设；只改变声音意图时几何、进度、生成 RNG 均保持原样。

### 编辑事务执行规格

#### UNDO-SAVE · 事务与试听

Intent：操作 ID、工具、来源/目标、参数、种子、依赖版本；WorldDelta：对象新增/修改/移除与来源链；UndoEntry：前后差量、生成/资产版本和影响范围。历史查看不推进正式随机流。

最低充分验收包括取消零写入、迟到任务拒绝、组合笔画只撤一次、改造后撤销恢复来源、部分公共空间面积与残余一致。具体多组件和私有试听合同见 [开发接口](20_开发接口与迁移.md)。

#### WORK-VERSION / PROGRESSION · 作品合同

根种子与命名子流/计数器、生成器/规格/资产版本一起保存。新局部拓扑升级对应 schema；旧字段读入不自动重新撒楼、改材质或扩大作者名单。改名保留已失效成员来源，未知版本和损坏档不覆盖有效作品。

可继续编辑、同版本确定回放、跨版本重合成分别验证。日常/手选种子、具名快照、图鉴和来信保持可选，使用真实事件，不加入债务或强制日程。自由建设的保存和普通批量操作从开局可用；城市史揭示内容，聆听可随时回编辑。

时代演出保留局部音色先行、逐渐传播、最后正式提示；首版以约80秒基线试做，期间不锁建设。传播进度/历史范围可恢复，玩家新编辑优先于旧演出任务。保留外观/音色/动机/编曲四个维度分开承诺。[完整合同](20_开发接口与迁移.md)

#### ERA-SPREAD · 首版状态与时序

新版目标：`EraTransition` 保存 old/target era、起点、开始时间、时长、对象ID/位置/修订、各对象到达与完成进度、历史保留集合和 notified 状态。一次传播是一项显式时代操作，不能把迟到的几何任务当作新的换代。

| 阶段 | 首版基线 | 状态变化 |
|---|---|---|
| 萌发 | 第0–2小节 | 起点音色先变，随后原基础沉降/重生 |
| 扩散 | 第2–38小节 | 按到起点的稳定空间距离/ID排序，每栋有独立进度 |
| 收尾 | 第38–40小节 | 完成远端交叉与重生，保留历史对象 |
| 正式入代 | 满40小节且本批已完成 | 更新正式时代标签，只通知一次 |

有音乐时统一演出轴可对齐拍点；无音频设备时同一状态机从保存的场景时间继续，不能冻结换代。每栋先音色提示，再两拍沉降、四拍回升、一拍落稳作为动画起点；减弱运动保留进场顺序，改用原地交叉。具体动画参数集中在演出配置，不散落进工具限制。

开始时保存对象名单/坐标。玩家中途编辑使该对象任务失效并按新修订重排；新房使用所在区域当前已显示的时代材料，不因开建而被旧任务覆盖。历史区/地标跳过替换，远端/隔河不按道路连通筛掉。没有可转代对象时仅做现有城市/环境的收束，不生成房屋充数。保存恢复保留进度和已通知状态。

### 空间与身份执行规格

输入：世界位置、高程、占地、道路段、局部墙面锚点。输出：合法性、命中对象、连接候选与影响范围。

全局使用连续坐标；房屋局部单元通过本地变换映射到世界。不使用局部格索引作全城道路/声音邻接。房屋、道路、区域、作者记录都使用稳定 ID，几何缓存仅引用它们。

检查完整占地、入口、道路净空、水体和支撑；不以 R/V 或音程筛掉建造。道路接入用真实曲线和拓扑，旧声学耦合与可听声场分开计算。

验证：墙面/世界映射往返、转角/层高命中、连续道路不量化、跨河无桥无步行捷径、存档 ID 不随排序改变。

旧运行数值独立保留在 [兼容数据](../数据/兼容规格/README.md)，由参数生成器读取；不作为本规格的建造条件。

#### SPACE-DUAL · 查询合同

| 查询 | 输入 | 输出 |
|---|---|---|
| 墙面命中 | 视图射线/逆投影、可见房屋、当前编辑模式 | building/face/cell ID、局部坐标、候选方向 |
| 完整占地 | 目标轮廓/体积、高度、地形/道路/保留地 | 合法性、实际冲突对象与范围 |
| 连接 | 相邻边/屋顶/道路入口及接口标签 | 接头、净空、支撑依赖、dirty 范围 |

选择优先已显示可编辑面，透明角落/未揭示部分不抢命中。空间索引只是 broad phase，最终求交使用实际轮廓/高度；不能只检查中心点或几处样点就承诺完整占地合法。失败不分配新实体、不修改旧拓扑。对齐容差是统一模块尺度参数，不在渲染与规则各写一份。

查询统一提供原始高度、坡度、水体/岸线、基础与真实占用。引水修改连续水路，平整记录前后高度差；植被只保存意图与显式改动，实例从同种子生成。临时空间缓存不成为持久作品真值。

几何冲突在预览中明确，覆盖作品使用独立可撤销替换，失败不改高度或删房。通用水文保留原地貌/排水面分开、平地父图无环和稳定回退；旧模板预算不定义地图或建筑总量上限。

检查坡路、桥头、树根贴地、门前净空、同种子重做及含孔洞留地避让；关闭音频自然时间照常，季节不改道路/建筑拓扑。

### 操作与反馈执行规格

地图状态使用命中候选和就地工具；房屋编辑显示局部格提示，城市其余不显示网格。面板输入优先于地图，Esc 取消当前草稿/关闭面板，不撤其他已提交操作。

验证鼠标/键盘同意图、文本快捷键隔离、小窗口候选可读、取消、镜头移动和真实可听事件显示。

完整旧参数、公式和合约 ID 见 [迁移前 spec.ui](../废弃/文档/2026-10-14_综合优化前/文档/01_执行规格/spec.ui.md)。

## 10_世界模型

来源：[10_世界模型.md](10_世界模型.md)

### 世界模型 · 连续城市与局部墙格

#### 两层空间

城市使用连续世界坐标、高度、方向和真实占地。道路是曲线与路口图，区域是轮廓与权重场，植被是带种子的实例集合。它们不读取房屋格坐标。

社区房屋有自己的局部模块拓扑。墙面格描述哪个面、哪一层、哪一段可以添加或移除房屋/露台；经房屋变换映射到世界。格是编辑和邻接结构，最终墙面不需要画格线，也不需要长得像一块块棋子。

| 层 | 表达 | 查询与用途 |
|---|---|---|
| 城市连续层 | 位置、曲线、多边形、高程 | 占地、道路入口、区域影响、植被避让 |
| 房屋局部层 | 模块单元、墙面锚点、层高、邻接 | 房屋块/露台扩展、开口、转角和屋顶拼接 |
| 表现层 | 网格/贴图、材质、接缝、LOD | 显示和选择；不充当世界数据 |

局部规则格或不规则四边形拓扑都可用于原型。先验证点击和墙格效果，按连接质量选择；不预先强制 12×12 上限、WFC 算法或每格一栋房。局部网格维持稳定，编辑时只改变占用和依赖，避免整栋重排。

现有世界用 `(x,y)` 表示地面、`h` 表示高度；3D 几何对应 `(x,h,y)`。当前等距投影为 `screen = origin + ((x-y)*28, (x+y-h)*14)*zoom`，缩放/平移只改投影。逆投影需要已知地面高度；坡地和墙面拾取查询真实几何，不能在高度未知时仅反解到平面。28/14 是现有显示配置，换渲染路线可替换投影，仍保持同一世界身份和局部锚点。

#### 玩家点击意味着什么

悬停可扩展墙面，显示一个贴合该面的轻量候选。点击添加指定单元或露台，系统补齐周边结构；在已存在部分执行移除，系统重新解释邻接。社区扩展可以生成相连房屋块，同时保留门、庭院和逐栋可选择性；不限制成“只在一栋旧房轮廓里装饰”。

扩展锚点保存所属房屋、面 ID、局部位置和目标层。重建后通过稳定 ID 重新定位，不靠三角形序号或缓存数组下标认领作品。未选中的城市部分不出现网格，也不受格吸附影响。

#### 身份与关系

| 对象 | 保留的身份 |
|---|---|
| 房屋/房屋块 | 稳定 ID、局部拓扑、材质、时代、作者来源 |
| 道路与桥 | 路径、宽度、入口/路口、拓扑版本 |
| 功能区 | 玩家轮廓、用途倾向、风格和可覆盖对象 |
| 玩家街坊 | 名字与明确成员；可跨内部 CID |
| 音乐区域/连接 | 来源对象、风格、网络、静音/独听状态 |

玩家街坊、功能区、几何连片和音乐网络各自有用途，允许重叠而不互相代填。旧 `Community/CID` 可继续作为服务和编曲分桶；不能替玩家规定街坊边界。新生房屋是否加入玩家街坊由显式扩展意图决定，名字不会自行认领整片 CID。

#### 几何与声音

空间合法性检查完整占地、道路净空、水体与高差。道路入口来自真实可达道路；隔河无桥不产生步行捷径。共享墙只是连接关系，不合并逐栋作者、音高或操作身份。

旧距离核 `c`、全对集合 `E`、近邻 `N₁₂` 和 R/V 可以用于复现旧混音或分析，不能冻结房屋、要求协和才可建或决定区域升级。规则无边不等于听不见；声场由实际混音决定。[space](01_执行规格/spec.space.md)、[harmony](01_执行规格/spec.harmony.md)

#### 五种关系各管一件事

| 关系 | 数据与职责 | 更新原因 |
|---|---|---|
| 物理可达 | 道路节点/边、高程、桥头、入口；人物车辆找路 | 改路、建桥、移动入口 |
| 空间与用途 | 地块/公共轮廓、功能区影响、留地、服务覆盖 | 区域画笔、设施改造、占地变化 |
| 建筑形态 | 共墙、檐口、转角、高差、围合庭院 | 房屋单元增减、邻接几何变化 |
| 声场 | 当前视野、距离、关注、声音控制与真实活动 | 镜头、控制、声音来源进退 |
| 音乐组织 | 区域风格、显式连接、动机/角色槽与应答 | 玩家编排、来源变更、庆典 |

同一对房屋可以共墙但音乐独立，也可以隔河应答但不能步行直达。功能区是用途意图，玩家街坊是作者归属，内部 CID 是计算分桶；三者不互相替代。选房、改名和镜头移动不消耗世界生成随机流。

房屋块要区分“建筑实体”和“附属模块”：新房分配建筑 ID，加层/露台保留宿主建筑 ID 并分配模块 ID。共墙和联合屋顶是派生关系，不能用一张联合图顶替所有成员的命中。拆块后仍能查来源与撤销；支持依赖来自实际结构，不从声学邻接推断。字段与旧档迁移见 [开发接口](20_开发接口与迁移.md)。

## 11_核心循环

来源：[11_核心循环.md](11_核心循环.md)

### 核心循环 · 塑造、欣赏、继续

#### 主循环

观察 → 点击房屋或画出城市意图 → 看见局部生成 → 欣赏视觉与声音反馈 → 修改、撤销或继续。

小动作直接落成，大动作先预览。社区点击不强制经过章程、卡牌、选音和 Enter 四道步骤；道路拖拽松开可提交，特殊建筑先选址，功能区和植被用连续画笔。操作结果跟随手，配乐换声部可等合适的音乐边界，城市不必等 16 秒乐句才回应。

#### 前五分钟

| 阶段 | 玩家做什么 | 系统兑现 |
|---|---|---|
| 入场 | 看见一个可继续编辑的古典小街坊和河岸 | 镜头留下明确空地；没有需要修复的声音问题 |
| 第一点击 | 点一处墙面，向旁边或上方增加房屋块/露台 | 墙格落点可读，转角、屋顶与栏杆自然补齐 |
| 第一条路 | 拉一条路接到门口 | 转弯、入口平台、台阶和交叉口形成；不搬走旧房 |
| 第一片空间 | 放一个小公共建筑或刷一片花园 | 院地、支路、植被避让；玩家看出不同性格 |
| 继续 | 再扩社区、修改路形，或撤销后换一种布局 | 旧选择稳定、变化可逆；城市发出轻量反馈 |
| 可选聆听 | 给两片区域选风格或连接音乐 | 听到变化；跳过此步骤也可继续建造 |

教学只在当前操作需要时出现。第一步就允许撤销；常用动作可见，不用找深层菜单。

#### 两种值得试的空间方向

河湾仍可保留旧“深流、织机、暖庭”创作语言，但它们现在是空间/声音风格预设。

| 方向 | 空间选择 | 声音回应 | 后续选择 |
|---|---|---|---|
| 深流 | 临水、较宽间距、长屋檐与安静步道 | 低慢声部与长音，保持空气感 | 扩展滨水露台、加桥或地标 |
| 织机 | 较密连排、拱廊、交叉路口和集市 | 轻快拨弦和短节奏 | 增加平台、连接街区或留小广场 |
| 暖庭 | 内庭、花园、公共台阶与绿廊 | 温暖中音和稀疏装饰 | 连成文化区或保留开敞空地 |

它们不锁用途、不强制某种音级，也不靠活力收益分出最优解。同一地形用不同道路、密度和地标组织出不同城市，是重玩价值的来源。

#### 玩家动词

新河湾演奏庭已有“邀请街坊演出”：道路连通的居民赴约，到齐后24秒主奏/邻屋应答，结束继续日常；可提前结束，不限制编辑。只有完成实际演出驻留才累计一场，取消不结算。居民行程与演出进度进入作品，重新打开接续。它是一次可玩的公共活动，完整经营供给和公共建筑能力继续制作。

点社区房屋扩展/移除；拉路/改路/建桥；放置、移动和改造特殊建筑；划功能区；刷植被；选择、命名街坊；撤销/重做；保存/恢复；可选区域声音风格、连接、独听、静音。地形编辑按功能需要加入，不附上旧每乐章次数和不可撤销限制。

章程可作为“紧凑核心、走廊连接、蓝绿文化”布局预设，提供提示或工具参数；卡牌可作为后期可选变化内容。两者不再是每次建造的前置流程。公交和轻量服务保留已有资产与接口，先服务空间活力，延后复杂容量、客流和票制。

#### 期待与推进

短期是一次点击带来的好看变化；中期是街坊连成独特轮廓；长期是新建筑、新时代、历史保留与更大的作品。后期强力建筑提供批量塑形、立体平台、公共空间连接等能力，详见 [时代与地标](15_时代与地标.md)。

声音缺口、失谐诊断、债务与修复计数退出默认循环。区域搭配的评价来自玩家喜欢的城貌、操作手感和听感，不通过噪声、冻结或崩盘逼迫修改。

#### 空间取舍与作品记忆

留一块庭院、把路绕向河岸、做一段紧凑商业街，都会改变后续可造的形状。预览说明本次占地、入口、遮挡和保留的机会；系统不替玩家把“文化中心”长成整片建筑。画功能区只改倾向，实际房屋仍由点击产生，特殊建筑仍由放置产生。

深流、织机、暖庭与花园群岛提供不同密度、轮廓和材料组合，不设置隐藏优劣分。普通选房、批量材质编辑、撤销和保存从一开始可用；后期强力建筑增加复杂的组合能力，不能用它解锁基本编辑权。

保留旧作里的日常种子、自选种子、作品收藏、发现图鉴与城市来信方向。日常种子只是可选共同起点；图鉴收录实际造出的组合与地标，来信依据真实建设事件生成，可关闭。它们不强迫每日上线，不新增账号、排名、维护债务或长期不操作惩罚。局间解锁增加素材和新玩法机会，已经保存的作品始终可继续。

一段好看的街坊可以保存为具名快照，比较改路前后或换代前后；撤销负责最近操作，作品快照负责长期版本。两者保留来源、实际成员与生成版本，不用截屏代替可编辑作品。[作品规格](01_执行规格/spec.run.md)

## 12_声音架构

来源：[12_声音架构.md](12_声音架构.md)

### 声音架构 · 有空间的正反馈

#### 职责

声音加强感官、空间感和完成后的满足。它不决定建造、成长、解锁、资源或失败。声音风格可以独立于功能用途选择：集市不必永远是鼓，花园不必永远是弦乐。

房屋以及组成的社区/功能区是音乐的实际来源，和谐、舒服的听感与建设之外的正反馈优先于同时发声的数量。街坊演出让周围房屋参与应答、亮窗或轻量动作，保留它们的来源身份。当前新河湾可刷出音乐街坊并独立选择暖庭/深流/织机；真实房屋按焦点14米范围轮换、共享和声，风格在3秒乐句边界淡入，相位不重启。演出交替演奏庭琴声和参与房屋木质应答，日常主题退让；实际播放位置/增益驱动亮窗与音符，静音清可听提示。固定7条共享PCM，区域数不增加播放器；音乐连接/独听、完整视野/远端调度与空间音频仍未完成，见 [街坊与试听](../验证记录/街坊划区_2026-10-14/README.md)、[演出验证](../验证记录/街坊演出_2026-10-14/README.md)。

#### 三种声场

| 状态 | 主要来源 | 调度 |
|---|---|---|
| 日常 | 镜头内城市与少量边缘对象 | 以区域聚合、距离与关注度分配稀疏声部，出入视野平滑淡化 |
| 远端回应 | 非视野区域中真实存在的来源 | 偶发短动机/钟/拟音，与近景错开；使用可复现调度 |
| 特殊合奏 | 全城区域都获得参与机会 | 地标完成、时代庆典或玩家主动演奏；分批轮换、随后回落 |

“全部发声”表示全城参与同一演出，不要求每栋房在同一瞬间满音量。已有旋律/垫底/节奏/装饰角色、轮换、ducking 与留白继续用于编曲。镜头移动和区界变化带迟滞，避免抖动抢槽。

#### 玩家编排

默认自动根据视野组织声音。可选面板提供区域风格、连接/断开、静音/独听和恢复自动。风格预设可从深流、织机、暖庭开始，再加时代音色和夜景版本。

音乐连接是独立图，不等于道路：玩家可以让隔河区域应答、让非相邻区域共享主题，或保持相邻地区音乐独立。系统把预设风格适配到共同节拍/和声底座，保留区域音色辨识。连接变化在拍/乐句边界淡入，不挪房、不改路、不扣活力。首版优先做经过设计的片段、stem 与少量动机组合，复杂随机作曲按听感价值扩展。

#### 三层材料与来源

保留长音/底层、律动、装饰三层；加建造拟音和环境 Bed。每次建造先用短反馈确认操作，再让区域主题反映新空间。昼夜/季节只改变环境密度与材料，不形成建造门槛。河岸两拍应答可复用现有来源事件，无递归；水体隔断道路不意味着声音隔绝。

玩家主题来自真实作者记录或区域预设，使用稳定来源 ID。连排屋顶不自动把多个声音身份合成一个。精确选区独听按明确成员计算，旧 CID 独听不能冒充它。

#### 实现合同

保留 `AudioPlan → 逻辑声部组 → RenderVoice → PCM` 分层和固定音频增益校准。波形共享只有签名/相位/控制一致才可保持等价；`√k` 振幅是重新编曲的选择，不是同相波形功率守恒证明。

已写入设备缓冲的 PCM 不能被撤销；撤销城市立即恢复视觉与真值，声音在下一可写帧淡化到恢复状态。预览使用隔离状态，不推进正式随机流。界面标记来自实际可听事件，不从未来资格猜测。

旧代码的 70 RenderVoice 保留作当前配置。按实际供音与听感决定预算，城市变大优先轮换和聚合，不按栋数增加音轨。详细输入输出见 [audio](01_执行规格/spec.audio.md)。

#### 可选的空间演奏语法

这些组织方式从旧设计保留为音乐选项，玩家可直接选择；形态名称不授予建造资格。默认声场不需要玩家掌握这些规则。

| 语法 | 空间/来源 | 可听结果与实现边界 |
|---|---|---|
| 主从 | 一片选中区域与背景区域 | 一个清楚主旋律，其他声部退让 |
| 环形轮唱 | 围院房屋或玩家明确成员序列 | 按稳定极角/手动顺序每拍一个成员；n 个成员是 n 拍一圈，可跨乐句，连续相位不重置 |
| 双岸应答 | 真实来源与隔河接收者，或玩家连好的两区 | 来源后延两拍复述；应答 generation=1，不再生成新应答 |
| 平行进行 | 两区域共享一个动机 | 预设在五度/八度等经过听测的关系中配器 |
| 回声街/卡农 | 玩家确认道路方向或区域链 | 分站错拍进入；不把任意道路长度硬换算成音符 |
| 梯田赋格 | 有层次的坡地区域 | 由玩家选进入顺序，海拔本身不自动升音级 |
| 稀疏高潮 | 当前城市全部区域 | 逐步加入代表声部，再回落留白；所有参与仍计实际节点预算 |

旧“≥3 音级分别产生装饰”“≥4 音级报时”与排钟楼是三个不同内容：前两项是可选区域音型/报时预设，排钟楼是具体建筑的专属演出。均使用真实来源与稀疏排程，不变成音级收集任务，不同时无条件叠加。

#### 材料与编制

底层长音、律动、装饰是素材层；Bass、Pad、Lead、Rhythm、Ornament、Bed 是编曲角色，两者不一一对应。首片沿旧的一个主旋律槽、两个主要节奏槽、一次应答槽工作，数量属于配置，新的音乐素材按实际听感调整。降低电平仍然占 RenderVoice；装饰、环境、过渡尾音与全城演出都计预算。

地域风格先选“音色族 + 节奏疏密 + 动机长度 + 氛围”，再适配共同节拍/调性。连接前可同源试听，冲突时提供能听见的过渡或稀疏轮换。声部轮换保留区域身份，不会因镜头出入重新随机换曲。邻接信息能影响配器候选，但建筑功能和位置不固定绑定某种乐器。

昼夜用河水、风、鸟和灯火的小事件补空间感；树木不逐株发声。现有合成声保留为技术基线，真实采样/片段素材逐项登记许可和加载成本；VCSL、VSCO 等仅是来源候选，未取得的素材不写成已实装。公共增益校准、控制隔离、来源生命周期和活动标记见 [开发接口](20_开发接口与迁移.md)。

## 13_地形与自然

来源：[13_地形与自然.md](13_地形与自然.md)

### 地形与自然 · 构图、连接与留白

水体、道路、植被的主要生成/表现参考为 Tiny Glade；Foundation 补充地形、水岸、道路可达与居民目的地的系统关系。连续坐标是这些系统的真值，Townscaper 式局部墙格只用于房屋。性能要求为局部 dirty 更新、空间分块、共享构件/材质和距离细节，完整有声场景同时记录帧时与编辑延迟。

#### 地形提供机会

| 地形 | 城市组织 | 重点细节 |
|---|---|---|
| 河谷 | 双岸街坊、桥头、滨水露台 | 路沿/岸沿层次、桥脚、浅水带和反光 |
| 海岸 | 湾形轮廓、港口、坡地层次 | 水平线、海堤、台阶和开阔留白 |
| 湖泊 | 环湖小路、庭院、岛屿 | 稳定水边轮廓与倒影，保留静缓空面 |
| 山地 | 台地、挡土墙、阶梯和高低屋顶 | 建筑基础接地，坡路不穿模 |
| 林地 | 林缘社区、树群与绿廊 | 树冠成簇、自然边缘、地面阴影 |
| 平原 | 紧凑中心或自由街道 | 密度变化、公共空地和视觉焦点 |

地形不自动升降音级，也不要求 R_initial 达某个分数。可建空间、清楚入口和可继续编辑的位置才是开局质量依据。

#### 玩家工具

道路、引水、平整、挖湖和植被使用连续世界坐标。引水从已有水源画曲线；平整画一个范围；植被用密度画笔/树群；桥由玩家画出两端和过水连接。原型先做能改善局部构图的工具，不要求完整水文模拟后才能植树或拉路。

道路直接参考 Tiny Glade 的自由画与顺滑连接手感，同时提供两点直拉。已实现去抖、受限平滑切线与等弧长曲线，预览/提交共用结果；路带圆端、连续转弯，交叉/接入处取消内部路缘并裁去叠面。改变一条路只更新它及真实接头依赖，整笔撤销。建筑开洞形成门/拱和复杂坡地适配继续分期制作。

预览检查完整影响范围。覆盖玩家房屋或重要道路时，提供调整路径或明确的替换预览；不会默默移动/删掉作品。编辑记录高程、水边、道路与植被差量，可撤销。撤销重放同一次种子，不重新随机撒树。

#### 生成与资产

受控河谷已经存在，优先复用其高程、岸线、道路接入和可建性。新增地形族需要通用水文时，可采用原高程 + 填洼排水面、priority-flood 父图、流量累积和连续河宽，避免河流陷入平台或死循环；方法可按视觉和成本更换。

植被使用“树群骨架 → 灌木/草 → 稀疏石块”三层。排除门前、道路、房屋足迹、公共净空和玩家保留地；空地不提前画成已建公园。草石按块缓存和固定种子生成，镜头改变只影响显示密度。

#### 昼夜与时代

昼夜是连续自然表现，土地、城市身份和玩家作品不重置。古典柏/橄榄/葡萄架、中世纪橡树/药草、文艺复兴园林/绿篱、工业公园/行道树、现代屋顶花园保持时代辨识。季节在昼夜稳定后加入，改变色彩和自然细节，不销毁建筑。

水流、风、树冠用共享低成本动画。建造反馈可以锁拍，自然风和流水不必全部锁 BPM。留白按构图判断，不要求每个镜头达到固定百分比。[美术规格](17_美术规格.md)、[terrain](01_执行规格/spec.terrain.md)

#### 连续几何的制作边界

海、河、湖保持不同对象身份；湖海不能因为视觉相似就沿用河流应答判定。桥两端落在可达陆地，桥头与道路共享真实节点；水域留白不是步行边。坡地基础查询完整足迹的高差，台阶、挡土墙和植被使用同一地面高度，不能分别猜高度造成穿插。

通用水文采用原始高程做地貌、填洼面做排水；平地流向由无环父图确定，流量逆序累积，河宽随流量变化，河终止于海/湖或明确地图出口。既有 45% 可建比例和 8 次重采样是旧模板配置，不作为每种新地图的审美门槛；仍需保证有可编辑起点、道路和公共空间。回退保存原根种子、尝试编号和模板身份，不能悄悄换种子。

已有五族受控样例是河谷、湖盆、林岭、海湾、高地峡谷；它们不证明完整通用水文完成。旧陆地范围与三河段扩展也是样例配置，连续城市不受一个永远固定的矩形限制。扩地按真实高程/岸线连接，保留旧区域 ID 和玩家修改。

引水、挖湖或平整与旧结构冲突时，预影列出受影响对象；玩家改路径，或进入明确的可撤销替换操作。植被可以批量移除，不扣活力，不等下一乐句。自然风、水、昼夜在关闭音频时照常表现；音乐同步的光点单独读取可听帧。

## 14_城市生长

来源：[14_城市生长.md](14_城市生长.md)

### 城市生长 · 点击扩社区，关系补细节

#### 触发

玩家点击社区房屋的可扩展面，系统立即执行一次局部生成；按住/拖动可扩成一个连续笔画。每个笔画是一项可撤销操作。停手就停止新增房屋，时间只驱动环境、人物和音乐。

房屋局部墙格允许横向增房、向上加层或向外伸露台。格大小按模块比例设计，在短边、转角和高差处形成清楚锚点；不把单栋限制死在原轮廓中。路径、植被和特殊建筑在连续空间工作。

#### 房屋生成步骤

1. 命中房屋/墙面，得到稳定局部锚点及玩家目标。
2. 检查完整新增体积、支撑、高差、道路/入口/庭院净空；不看音程是否协和。
3. 更新目标单元，读取受影响的相邻面。
4. 生成结构，再补门窗、屋顶/露台、台阶/栏杆和装饰。
5. 发布局部结果与作者记录，用短生长动画和声音反馈解释变化。

首版用确定的邻接标签和小型模块库；WFC、规则求解或解析几何都是可选实现。增加模块时先覆盖端部、转角、T 接、上层和移除，避免组合规则指数膨胀。

#### 连接语法

| 关系 | 生成结果 |
|---|---|
| 同层共墙 | 移除内部面，连续檐口，保留独立房屋身份 |
| 相邻屋顶 | 统一屋脊/坡面接口；类型不兼容时保留清楚断点 |
| 高低房屋 | 竖直侧墙、阶梯或平台支撑；不生成贯穿庭院的大斜棚 |
| 上层外伸 | 柱/梁或可靠悬挑，门窗不能被支撑堵住 |
| 多面围合 | 可达庭院、花坛或露台；保留入口和真实净空 |
| 连续道路接近/穿过 | 门前短路、台阶、门洞/拱门；先尊重结构和玩家意图 |

允许干净的空结果。小装饰变化受材质族、比例和固定种子控制；相同关系的大形状应可预测。玩家删除一块后重新生成受影响邻接，不重新抽整片街坊。

#### 连续城市与功能区

道路由玩家曲线控制，系统补路口、路缘和入口。功能区是住宅/商业/文化/自然等生成倾向，不会自己刷建筑；它影响后续玩家点击时的模块、比例和装饰权重。特殊建筑由玩家独立放置，入口与道路、地形自然适配。植被画笔负责树群意图，系统补自然边缘。

旧临街 L1、内庭 L2、独立空地 L3 可保留作生成建议和预览分类。取消“L3 每两乐句自动出生、音乐性低冻结、必须等成熟才可用”的玩法语义。道路图、占地、公共净空和种子序仍可复用。

#### 地方的性格

保留完整旧形态词汇：环形合唱城、双子港、梯田赋格镇、深流、织机、回声街、独奏岛；暖庭、花园群岛补充空间风格。它们是玩家布局形成的视觉/音乐描述，不是需要音级正确才可成形的任务。成形后可以命名、继续编辑或保留为历史街区。

验证见 [fabric](01_执行规格/spec.fabric.md) 和 [DOD](02_验收/DOD.md)。

#### 视觉成形与时间分开

旧“胚、群、央、腔”可保留为资产轮廓词汇：小屋、连排、公共中心、突出地标体块。新版不根据等待、R/V 或音程达标把它们自动升级；玩家点击、加层、放建筑或明确执行街坊改造才改变实体。房屋的短成形动画可以在松手后完成已提交动作，不产生额外随机房屋。

道路编辑可补门洞、阈石、短台阶和相邻屋檐，但不能自动搬房或删房；形成穿楼拱道时预览实际开洞，保留楼层支撑。上层移除涉及支撑链时同时预览附属露台/柱梁变化；隐藏内部面不等于销毁内部单元。失败时保留原城市，并显示冲突位置。

“共享山墙 ≤0.10、最多6栋连排、庭院净空 ≥0.8”属于旧几何原型的调参记录。新版将连接容差随模块尺度统一配置；连排分段用于屋脊节奏和缓存，不作为玩家最多能点六栋的限制。庭院保留实际入口、净空和孔洞，不能用装饰贴片跨路、跨水或填满内院。

#### 进度

新能力由建设经历和可读的城市里程碑揭示，再由玩家决定启用。首个版本用“完成一个街坊 → 引入一座公共建筑 → 形成第二片区域”这类空间进展，不用失谐修复计数、R≥70、债务或精确拍点来解锁。

保留自由建设、城市史、聆听三种组织方式。默认自由建设；城市史引导时代和能力，章数/停留时长按试玩调整；聆听只冻结建设输入，城市作品仍可返回编辑。七乐章与旧崩盘条件退为历史实验，不是默认任务。

#### 后期强力建筑

强力体现在扩大玩家能做的事情，具有清楚体块和新的操作结果。以下为新版内容方向，未实现项按 [P2](03_任务/P2.md) 制作。

| 内容 | 可落实的能力 | 对城市的变化 |
|---|---|---|
| 元老院/市政厅 | 保存、套用街坊布局预设；批量改同类模块 | 玩家把自己的成熟语言推广到另一片地方 |
| 圆形剧场 | 沿公共轮廓生成台阶座席、广场与多方向入口 | 成为城市中心，可触发一次区域/全城演出 |
| 大教堂/穹顶厅 | 大空间、共享屋顶与长跨度拱廊 | 从小连排扩到有辨识度的公共建筑体块 |

不再因不协和而让效果沉默，不额外放宽存档或几何合法性。能力是可选工具，不会在旁边自动繁殖房屋。

#### 目录与落成

旧 27 座目录保留为内容池：首批古典元老院、神殿、圆形剧场，以及中世纪市政厅、大教堂、行会大厅。其余名称和造型已收入下方完整内容池；原条件仅供追溯，见 [原目录](../废弃/文档/2026-10-14_综合优化前/文档/01_执行规格/spec.city.md#33-地标目录v4-lmk-03目录保留连续占地优先)。旧“每句多长一栋、豁免失谐、R/V 加成”等效果已被新工具方向替代，不复用旧觉醒条件。

能力可用后从建造菜单放置，系统补齐道路入口、台基和装饰。使用完整连续占地预览；无需先吸收民居或满足两个音乐边界。替换已有房屋只在玩家明确选择改造时发生，展示影响对象，并能撤销。

#### 历史与时代传播

保留“局部变化 → 新旧并存 → 逐渐传播 → 最后确认入代”的视觉演出；支持一栋沉入地面后沿原基础长出新时代版本。减弱运动用同位置材质/几何过渡，不强制长电影或锁建造。表现时间与玩家继续编辑发生冲突时重新排受影响对象，避免旧演出覆盖新意图。

完成引导后继续同一座城。保存城市、截图/摄影、可读 City DNA 已有基础；高质量音频/壁纸导出另行实现。导出价值是留下作品，不能只留下分数。

保留“城市曼陀罗/和声结”作为可选导出样式：用城市布局、区域关系和真实主题来源组织图形，另保留不带 UI 的城市壁纸。电视塔的“频谱镜”、音乐面板的波形/频谱是可选欣赏或开发工具，数据来自实际 PCM；城市天际线本身不假称科学频谱。导出和可视化不参与建设评分。

## 16_界面与反馈

来源：[16_界面与反馈.md](16_界面与反馈.md)

### 界面与反馈 · 让动作留在城市里

#### 主操作

默认城市视图保持清楚。常用建造、撤销/重做和保存需要找得到；不规定常驻元素必须少于四个，也不把所有工具藏进悬停菜单。

房屋悬停显示当前墙格或露台候选，点击即生成；退出房屋焦点后辅助格消失。道路拖拽预览曲线和接头，松开提交。区域/植被画笔显示本次范围；特殊建筑显示占地、朝向、入口和冲突。选中对象才出现局部参数，不要求每次先选择音乐。

#### 反馈层

| 层 | 回答的问题 | 表现 |
|---|---|---|
| 即时 | 我命中了什么，工具是否工作 | 墙面高亮、路径轮廓、接头、短操作声 |
| 生成 | 这次改变了哪些结构 | 小范围墙/檐/台阶/植被补齐，旧房稳定 |
| 完成 | 这是我做出的地方 | 完整体块、短灯光/动态、区域音乐变化 |
| 长期 | 下一步还能做什么 | 空间候选、强力建筑能力和历史保留入口 |

预影与真实对象用线型/透明度区分。音频事件标记只指已经输出的来源；可用资格不能冒充已经演奏。

#### 撤销和输入

点击是一项操作，连续笔画合成一项；拖拽取消不写世界。撤销/重做覆盖房屋、道路、区域、植被和音乐连接。大型替换显示被影响对象，小改动不弹确认。

面板内输入框、Tab/Enter/Space 和取消由面板处理，不能泄漏到城市快捷键。Esc 先取消草稿或关闭面板，不撤掉已提交的其他操作；切城清空临时焦点。键盘与鼠标对同一动作输出相同的 Intent。

镜头聚焦到真实选中成员，避让面板和门口/屋顶；多尺度选择不把一栋偷换成整 CID。命名只存明确成员，音乐控制显示实际作用范围，默认有恢复自动声场的入口。

#### 信息与可访问性

显示本次空间后果、冲突和能力作用范围，取消常驻 R/V/E 债务和音频答题。灰度下仍能区分路、房、植被和公共空间；关闭声音可完成操作。减弱运动减少弹性和大幅过渡，不删反馈内容。声音设置允许关闭区域音乐、降低环境和控制特殊合奏。

#### 现有 UI 可复用

原生暖石面板、作者回访卡、逐栋命名、同源试听、输入仲裁和小窗避让已经有代码基础。把旧章程→卡牌→社区→公建→声音串联流程简化成工具入口；不要继续用旧流程作为全部新动作的门槛。[ui](01_执行规格/spec.ui.md)、[Demo](Demo快速开始.md)

#### 通知与镜头

保留首次成形、小地标落成、时代完成和作品收藏四类轻通知，按实际事件出现，可关闭和手动聚焦。普通每次点击不弹卡，庆典不盖满城市、不自动抢镜头。提示只描述确实生成的形状与可用能力，不用旧阶段条件文案暗示音乐达标。

缩放改变可见细节和自动声场候选，不改选中成员或玩家街坊。远景优先选区域，近景优先墙面/房屋；显式工具与对象选择优先于自动尺度。界面分别显示“查看/编辑对象”“声音作用范围”，取消后恢复之前明确的声音控制。默认不用黑屏听诊；黑屏仅保留为欣赏/开发听测工具。

文字大小按屏幕像素保持，地图名在静止时缓存，优先给选中街坊与焦点区域留位置。重叠名称避让/隐藏只影响显示，不丢掉成员或声音身份。截图和公开成品图不带调试 ID、阈值与内部 CID。

## 17_美术规格

### 美术规格 · 温暖微缩城市

#### 视觉主张

本作美术以本地 Tiny Glade 参考库为基础。 建筑接合、厚墙与屋檐、暖软哑光材质、丰润树群、连续草地与水岸、舒服的光影构成统一方向。性能取舍先简化远景微小结构，保留接地与空间层次。Townscaper 的点击生成服务房屋形状，Foundation 服务建筑生活与经营，二者服从这一美术方向。

#### 形、色、光

| 要素 | 制作要求 |
|---|---|
| 大形 | 厚墙、清楚屋顶、紧凑庭院、成簇树冠；街坊有高低和密疏节奏 |
| 比例 | 门窗和屋檐略夸张以便看清；柱廊、台阶、栏杆支持空间读法 |
| 色彩 | 暖奶油石、低饱和青/灰绿、陶瓦/珊瑚点缀；按主色/次色/焦点组织，不硬卡三种色相 |
| 材质 | 哑光、宽色阶和少量粗糙变化；石缝/瓦纹在合适镜头才可见 |
| 光照 | 主光方向一致、阴面有环境填充、接触阴影落地；夜光局部暖，不整城泛光 |
| 自然 | 水边、树群、草地在边缘过渡；草簇和石块节奏稀疏、留出干净地面 |
| 动效 | 建造有短促成形，风水低频连续；不用每栋持续大幅 squash 或高频闪光 |

#### 第一时代资产语言

延续已有古希腊/罗马暖石、陶瓦、凹窗、木百叶、柱廊、内庭、油灯、橄榄树和地中海柏。房屋/商铺/文化馆造型要有用途区别；装饰沿真实朝向和遮挡，不把成品贴图旋转充当新视角。

已有 8 类建筑四向、2 类树、环柱廊文化馆、石街、夜光和联合屋顶是制作基线，不是最终风格签核。保持其模型、制作脚本和 manifest，改进比例、材质、接缝和镜头表达。

#### 优先做好的五个接头

1. 共墙/转角：内面隐藏，檐口清楚连续。
2. 混合屋顶：高差用竖直侧墙/台阶，避免大斜棚盖住庭院。
3. 门与路：阈石、短入口步道、地面材质过渡。
4. 坡地基础：台基、挡土墙和支撑，不能悬空。
5. 庭院与树：留足入口和空隙，枝叶不穿墙，不用装饰填满。

#### 细节分级

| 距离 | 保留 | 简化 |
|---|---|---|
| 城市全景 | 屋顶体块、道路、水岸、地标、树群和主光 | 窗框、瓦粒、花盆、草石 |
| 街坊视角 | 门窗节奏、檐口、庭院、路缘、台阶 | 极细纹理和单片树叶 |
| 房屋编辑 | 可点击墙格、支撑、接缝、栏杆和局部材质 | 看不见的内墙和背面零件 |

先做同一街坊的三档视图。低画质减少装饰、阴影精度和远景动画，保留轮廓、道路连接和操作候选。

#### 渲染与性能路线

新河湾已用原创分枝/不规则叶团替换球冠与双锥，每类3种共享变体、顶点高低色阶与独立风。林缘草花石由植物种子派生，按8米块MultiMesh组织、查询局部空间真值，改水/路隐藏草而不漂移幸存实例。地面与道路使用世界坐标低频色阶，阴面填充与房基接触层接地；三尺度/白昼/夕光对照见 [本轮实窗](../验证记录/TinyGlade美术_2026-10-14/README.md)。当前画面仍需继续打磨建筑层次、树冠细节和岸边，自测性能通过不代表最终审美签核。

水体、道路、植被首选 Tiny Glade 的自然过渡与连续意图生成，Foundation 补充地形/水岸、道路可达和居民活动。优先把岸线、门路、桥头和树根接地做清楚；房屋局部格不参与这些系统的位置计算。每次编辑只更新受影响对象及其真实接缝依赖，保留其他区域的几何、实例和材质缓存。

当前新创作切片优先使用运行时低多边形 3D，直接支持墙面拾取、动态体块、屋顶/露台和连续路桥；旧 Godot 连续世界 + 2.5D 烘焙资产保留为对照与可复用生产资料。局部孔洞、自由镜头和混合表现按实际连接质量与成本继续取舍；用同场景画质、编辑延迟、内存和帧时决定，不先承诺任意旋转。

共享材质/atlas，按空间块缓存稳定结果，局部编辑只更新邻近依赖。重复构件/植被用实例化；MultiMesh 按空间块拆开以适应整体裁剪，不能认为所有实例都有独立剔除。近景增加细节，远景合批和 LOD。[官方说明](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html)

光照优先选择能达到目标的便宜方法：烘焙 AO、接触阴影、方向光和环境填充。高级 GI/反射只有在对照中提供明确视觉价值才加入，不照抄 Tiny Glade 的定制渲染器。

#### 判断效果

用户已明确当前草地未达到 Tiny Glade 感觉。第二轮降低地面斑块对比，草刺改为0.12–0.25米宽弯叶、增加树群周边密度，统一受光避免黑刺，后续还需连续草毯、疏密过渡与自然坡地。不得用性能合约PASS替代画面接受。演出反馈用真实来源的局部亮窗与小音符，不让整城闪烁或房体持续跳动。

同种子/同镜头比较粗模、基础细节和完整细节，白昼/黄昏/夜间共用一套体块与材料关系。先看轮廓、焦点和接地，再看材质；静图好看后继续检查点击、删块和镜头移动的接缝/闪烁。

当前完整交互场景先达到流畅 60 FPS；修改前记录的后期 3,000–5,000 栋、120 FPS 目标继续保留。未指定最低配置前不把 300 栋或 2,000 树写成产品上限；具体预算由 [规模](18_城市规模.md) 的完整场景测量决定。风格由实际画面收敛，自动测试不代替审美评价。

#### 把风格做进生成规则

大形先成立：街坊轮廓有高低、长短和空隙；路口/庭院留出负空间；地标的体块和前庭形成焦点。局部变化只在统一的比例、材料族和屋顶语法内发生，不把所有细节独立随机。屋顶节奏、墙厚、门窗间距、树冠比例和接缝表达属于一套 style profile，同地区共享基础语法，焦点建筑允许少量差异。

| 接合场景 | 必须读得出 | 省成本的处理 |
|---|---|---|
| 路到门 | 门洞、阈石、入口平台、两种地面过渡 | 短连接片复用；按入口与路面高度裁切 |
| 两个屋顶 | 屋脊关系、排水方向、高差侧墙 | 端部/转角/高差模块；近景才加瓦纹 |
| 坡路到台地 | 路沿、挡土墙、台阶和支撑 | 连续路条带加少量高度接头，不逐石建模 |
| 路穿特殊建筑 | 拱洞、梁柱支撑、可通行净空 | 预设洞口语法或局部布尔后缓存 |
| 露台到植被 | 栏杆、树根/花坛、可走边缘 | 成簇植被、地面色阶和接触阴影 |
| 桥到岸 | 桥脚、桥头坡道、岸线退让 | 主桥模块 + 两端适配，不铺满反射/粒子 |

按 Tiny Glade 方向统一制作，用同一城市比较细节密度、自然接合和光影质量。简化先减少小石粒、叶片、瓦粒和复杂反射，保留檐口厚度、入口、支撑、树群和舒服的光影。现有新河湾仍是程序几何原型；参考方向已经确定，画面质量继续以实际编辑视角收敛。

#### 光影、夜景与资产基线

旧 24 槽暖石/陶瓦色板、同系描边、单一主光、接触阴影和灰度对照作为现有制作基线；具体色数、黑描边禁令、固定色相族数量、每栋三种微动效不再是所有新路线的强制条件。主光方向、材质明暗和投影需一致，夜景靠真实门窗/灯具的稀疏暖点，不能满窗发白。前后遮挡和孔洞沿实际几何，室内被挡住的灯不穿墙。

古典油灯/火盆、中世纪火把/灯笼、文艺复兴烛台、工业煤气灯、现代电路灯和窗光保留各时代身份。换代不重置昼夜，历史区保留旧灯具。当前 150 秒昼夜是调速原型；季节保留春芽、夏荫、秋叶、冬枝/高地霜的素材方向，时长按长时观看调整，不强制两天一季。

2.5D 路线复用原始几何四向烘焙、地面锚点、索引色/调色和实际遮挡遮罩；3D 路线仍保留同样的体块/材料纪律。只缓存稳定部分，编辑时更新受影响接缝。建筑 ID、局部单元 ID 与物理实例槽分别记录，实例槽回收不能认领旧作者来源。具体制作字段和缓存失效见 [开发接口](20_开发接口与迁移.md)。

#### 艺术验收不是资产数量验收

同一街坊固定镜头、昼夜时点和布局，提交全景、街坊、墙面编辑三个尺度；再比较灰度、轻模糊图与实际点击/删除片段。看轮廓、层次、接地和连接后，再判断近景细节价值。资产目录数量冲突、旧 20/21 件或 34 资源不阻止把一处接头做对，也不证明美术令人满意。实际 Godot 画面与编辑片段是交付物，Blender 单件渲染只是制作检查。

## 18_城市规模

来源：[18_城市规模.md](18_城市规模.md)

### 城市规模 · 小地方成立，大城市可编辑

#### 规模目标与用途

保留旧规模梯度，用它们测试不同问题，而不把每个数字变成玩法条件。

| 样本 | 检查 |
|---|---|
| 20–30 栋河湾 | 点击、道路接合、风格、第一作品和撤销 |
| 80–150 栋、多片区域 | 功能区差异、局部重建、视野声场与导航 |
| 400–600 栋 | 连片层次、地标、空间缓存、整城编辑与供音 |
| 3,000–5,000 栋后期愿景 | 分尺度渲染、批量工具、流式载入和作品长期维护 |

旧 36–48 初始规划社区是大城样本配置，既不规定玩家街坊数量，也不要求社区自动分裂驱动建设。1,511 栋已有样本用于恢复/供音比较，不证明新玩法大城完成。

#### 三个独立数量

逻辑房屋/局部模块、显示实例、实际音频 RenderVoice 各自计数。几何联合不合并逻辑身份，视野剔除不删房，声音聚合不丢作者记录。玩家命名与功能区不被内部 CID 重编号。

#### 成本控制

- 空间索引用完整占地与道路段查询；只更新相交区域和邻接圈。
- 稳定地形/街面/屋顶和阴影缓存按来源版本失效；平移镜头不重建整城。
- 植被和重复模块按可裁剪空间块合批；远景简化，近景补细节。
- 后台准备使用不可变快照，主线程分片发布，过期结果丢弃。
- 音乐按区域和角色轮换，同样规模比较有声/静音，定位实际瓶颈。

#### 性能测量

目标 60 FPS。报告机器、分辨率、渲染后端、同种子样本、p50/p95/p99 帧时、点击到反馈延迟、重建耗时、峰值内存、draw call/实例数与欠载。区分冷启动、稳态、连续编辑、缩放和保存，不能只报平均 FPS。

先测真实 20–30 栋完整声音+动画+编辑切片，再测 400–600 栋。更大的测试只在扩展工具或缓存机制改变时提供新证据。预算从实测推导，不预设 12×12 墙格或 32 音轨上限；现有实现的 70 RenderVoice 配置在迁移前继续复用。

#### 大城的乐趣

大城需要批量房屋/材质编辑、快速区域选择、强力建筑和历史保留。新增规模如果只增加等待，不增加城市轮廓与编辑机会，就先改工具和空间组织。全城合奏轮换区域参与，不让栋数直接变成音量。[P2](03_任务/P2.md)

#### 恢复后期性能目标

修改前文档记录的用户目标是后期 3,000–5,000 栋、120 FPS 及以上，约 8.33 ms/帧；这一目标保留，先完成 60 FPS 的真实完整切片，再推进后期目标。120 FPS 是工程目标，不是限制用户只能造多少房子的规则。测试同时记录 1440×900 既有基线和目标发布分辨率，硬件档位由实测明确。

旧 700 栋静态烘焙压力图与新动态游戏分别计成绩。既有 607→609 栋、70 RenderVoice、零欠载的样本稳态约 32 FPS、最大同步结算 232.934 ms，尚未达成新目标；1,511 栋恢复样本也不证明动态编辑达标。共享 CPU/GPU 负载、冷缓存和发布模式都写入报告，不能把另一个游戏同时运行的成绩当作固定硬件基准。

持续编辑优先检查：局部网格上传、阴影/夜光重合成、空间索引、交通分频与音频供给争用。LOD 简化显示，后台/分片降低峰值，缓存减少重复计算；增加线程不能代替减少整城扫描。新增规则只更新受影响块与依赖圈，超出单片可及时完成的工作先发布清楚的轻量预览，不让画面长时间卡住。

旧每社区 4–40 栋和 36–48 社区配置继续帮助构建测试样本；内部计算区分裂不改变玩家街坊归属。音级/角色数量随音乐意图变化，建筑、逻辑声音组与 RenderVoice 三项分别报告。全城规模增长依靠分尺度表示与空间批次，不能用丢房、丢名字或缩减玩家作品换成绩。

#### 保留完整功能区词汇

用途、地形形态与音乐风格分开。下表的 14 类是内容语法，允许混合/重叠，不要求做 14 个互斥模式或 14 套全新生成器。首版优先居住、商业、文化公共、自然与混合区域；后续使用同一连续画笔和局部模块语法扩充。

| 内容词汇 | 空间与视觉重点 | 可选声音性格 |
|---|---|---|
| 居住 | 连排、内院、露台、安静入口 | 温暖中低音、稀疏旋律 |
| 商业 | 临街店面、棚架、连续步行面 | 清楚短拍、明亮拨弦 |
| 工坊 | 小院、材料棚、工作台、烟囱 | 木质/金属短音与低密度律动 |
| 圣所 | 台基、柱廊、安静前庭 | 长音、钟或合唱材料 |
| 港口 | 岸沿、码头、桥头、仓棚 | 空气感、远处呼应 |
| 梯田 | 台地、挡土墙、阶梯、高低屋脊 | 有层次的错拍进入 |
| 园林 | 林水、花坛、弯路、开敞空地 | 环境声与留白 |
| 市集 | 公共广场、摊位、商业接头 | 轻快装饰与间歇人声材料 |
| 学园 | 院群、回廊、公共读书/休息空间 | 清楚动机、安静交替 |
| 工业带 | 厂房、铁架、服务道路、轨道 | 克制机械节奏与铜管 |
| 滨水带 | 沿水步道、露台、公共岸线 | 河水、长音、双岸应答 |
| 山城 | 坡路、基础、观景台、多层轮廓 | 风与不同层次的区域主题 |
| 遗迹 | 旧材料、残墙、保留地标与历史区 | 前代音色、旧动机 |
| 枢纽 | 真实换乘节点、站前公共空间 | 有序短脉冲和到达反馈 |

刷区只改变范围意图和之后点击的内容偏向。一次区域套用到已有对象属于单独的批量改造，先显示影响范围并可撤销；区域本身不自动补住宅。音乐性格是预设入口，玩家可另选。港口/山城/滨水等也可作为地形标签，不必和居住/商业互斥。内部 Community 数量、成熟栋数、R 分数与区域面积不充当定义这些名称的音乐门槛。

## 19_城市生成管线

### 城市生成管线 · 玩家意图到可编辑作品

#### 职责分层

保留旧六层中有用的空间组织，加上两种入口；不要求一次操作都跑完整城市生成。

| 层 | 输入/职责 | 输出 |
|---|---|---|
| 意图 | 点击墙格、道路笔画、区域轮廓、建筑放置、植被范围 | 稳定 Intent，来源对象、参数和局部种子 |
| 地形 | 高程、水边、坡度和可建性 | 地面查询与真实边界 |
| 城市骨架 | 玩家道路、桥、交叉口和入口 | 连续几何与可达图 |
| 区域/空间 | 功能区、留白、公共占地、临街关系 | 权重场、净空、候选与连接 |
| 建筑/自然 | 局部墙格生成器或连续特殊建筑/植被生成器 | 模块、几何接头与实例 |
| 表现/声音 | 当前确定结果、视野和区域音乐网络 | 画面、动画与 AudioPlan |

#### 双生成器协作

房屋生成器管局部模块邻接；连续生成器管路、特殊建筑、区和树。用共同的占地/高度/入口查询及连接接口交互，不把两者塞进同一个全城 WFC。

典型过程：玩家拉路到门前 → 道路几何预览 → 查询屋面/地面和高差 → 产生门前平台/台阶/门洞候选 → 发布确认操作 → 更新道路与受影响房屋 → 同步失效植被、阴影和声音区域缓存。房屋格不把道路强行量化，路网也不重排整栋格。

#### 数据合同

| 数据 | 持久内容 | 临时/派生内容 |
|---|---|---|
| Intent/WorldDelta | 操作 ID、对象 ID、几何/参数差量、前后状态、种子、版本 | 输入焦点、鼠标位置 |
| WorldSnapshot | 房屋拓扑、道路/桥、区域、地形改动、植被意图、时代 | 空间索引、网格缓存 |
| authorship | 玩家街坊、名字、明确成员、来源关系 | 选区草稿、文字布局 |
| audio intent | 区域风格、连接、静音/独听意图 | AudioStreamPlayer、设备缓冲 |
| AudioPlan | 可重放声音事件、稳定来源和提交帧 | 线程、句柄、查询缓存 |

旧 `CityProfile`、WorldSnapshot、WorldDelta、独立 authorship 容器和 City DNA 可继续用。新字段使用版本化 schema，不能让后台 World 交换覆盖玩家名字。保存局部拓扑/生成版本及用户修改，保证资产规则升级不会重写旧作品。

#### 编辑事务

小点击可立即确认；拖拽/大型放置先预览，松开或确认按钮提交。预览不写世界、不消耗正式随机流。一次笔画聚合为一项 UndoEntry，保存前后差量和影响范围；失败不发布半个结果。

后台任务携带输入版本和依赖范围。主线程检测版本有效再发布；连续编辑造成旧结果过期时丢弃或重算受影响局部。不为了等音乐拍点堵塞建造。当前旧供音提交仍用音频绝对帧，未迁移代码前继续其旧行为；视觉/建造解耦是下一步功能，见 PROJECT。

#### 保存和恢复

临时文件写入 → 回读校验 → 替换正式档 → 保留上一份有效档。未知 schema 或损坏档不能清空后覆盖。稳定 ID 不来自数组位置；JSON 中超出安全整数的 ID 用字符串；派生缓存加载后重建。

恢复保存的玩家成员和局部拓扑，不按新 CID/同音自动扩张范围。已渲染 PCM 只能向前衔接，设备声音撤销与城市撤销分开承诺。跨版本声音重渲染与“可继续作品”分别验证。

#### 交通与自然

保留道路端点与节点一致、桥真实跨水、车辆沿路径弧长移动、改线在节点/边末接入的合同。公共建筑入口用真实步行图；轻量人物/车辆可提高活力，但不创建每辆车一个音轨，也不再通过客流自动繁殖建筑。完整经济/票制先不扩展。

性能依赖分层与局部更新，详见 [18](18_城市规模.md)。现有代码接口和已测范围见 [PROJECT](../PROJECT.md)。

#### 局部依赖与结果发布

| 玩家修改 | 必须更新 | 保持不变的来源 |
|---|---|---|
| 加/删房屋块 | 局部占用、邻面/屋顶/支撑、足迹、入口、命中、邻块阴影 | 无关房屋拓扑、道路大形、区域名字 |
| 改路/桥 | 相交段/路口/可达图、临街入口、附近植被与接头 | 玩家房屋位置和未确认改造 |
| 刷功能区 | 相交范围用途权重、未来点击候选、玩家选定的风格 | 既有房屋数量；不偷偷全区换材质 |
| 公共空间改造 | 目标及残余轮廓、入口、服务覆盖、附近自然和可选声场 | 留地来源链、设施稳定 ID |
| 改音乐连接 | 配器关系、来源资格、声音渐变与保存意图 | 几何、建设进度与生成随机流 |
| 移动镜头 | 可见块、LOD、命中投影、自动声场候选 | 全部世界与作者数据 |

结构生成、细节生成、表现发布分开预算。结构先给可读结果，细节可在随后几帧完成；同一 Intent 的细节不算额外建设动作。后台结果带世界/对象依赖版本，旧结果不能覆盖新操作或恢复后的作品。详细字段、公开空间布尔与存档路径统一见 [开发接口与迁移](20_开发接口与迁移.md)。

#### 2. 对象与版本

现有 schema 2 连续世界使用稳定对象 ID、连续位置/占地、时代、音级与作者来源。新增局部拓扑后提高对应对象/作品 schema，不能把结构不同的数据仍标成旧版本。

| 对象 | 新版目标的最小内容 | 来源与更新 |
|---|---|---|
| Building | ID、transform、footprint、era/style、作者来源、local_topology | 普通新房独立 ID；加层/露台引用宿主 |
| HouseTopology | schema、稳定 cell/face/module ID、占用/邻接、层高、模块类型、局部变换、生成版本 | 编辑单元，不保存派生三角形作为唯一真值 |
| RoadSegment | ID、端点节点、连续中心线、宽度、高程层、桥信息、revision | 端点/交点对齐；不量化到房屋格 |
| Lot/PublicSpace | ID、外环/孔洞/组件、实际临街边、入口、用途、设施 ID、来源链 | 多组件一致布尔，残余可继续编辑 |
| FunctionalArea | ID、轮廓/权重、用途倾向、style、revision、作者意图 | 生成标签和连续范围，不自动刷房 |
| VegetationIntent | ID、范围、密度/族、种子、排除区域、玩家修改 | 实例可重建；镜头不改种子 |
| MusicRegion/Connection | 稳定范围 ID、显式成员或明确空间范围、revision、风格、连接、控制 | 默认静态成员；动态范围须明确自动归属规则 |
| CityProfile | 地形族、中心层级、街块尺度、路断面、密度、混合用途、绿网、交通、建筑语法、历史倾向 | 生成倾向和样例参数，不替玩家决定放置 |

`Building ID`、局部单元 ID、内部 CID、作者街坊 ID、音乐区域 ID 与实例槽号互不替代。已有代码的建筑稳定键叫 `district_id`，迁移时映射到建筑实体含义，不能把它误当内部 Community 的 CID。几何连片后的单栋仍能选择、改造和追溯。

#### 3. 事务、撤销与后台

新版目标数据链：输入 → Preview → Intent → 几何/依赖校验 → WorldDelta → 一次发布 → UndoEntry → 派生画面/声音更新。

Intent 至少含 `operation_id/tool/source_ids/target/parameters/seed/base_version`；WorldDelta 记录 `created/modified/removed` 对象和影响范围；UndoEntry 保存前后状态、来源链及重新生成所需版本/种子。字段可沿现有类型实现，避免为同一真值再造平行容器。

预览读取不可变快照，拖动改变预览参数；确认才分配正式操作身份/随机计数。连续笔画是一项事务。取消没有世界写入，大型替换由本次预影确认，失败保持原版本。后台任务携带世界/对象依赖版本和选区修订；迟到任务丢弃或局部重算，不覆盖后续点击、载入或作者改名。

主线程提交世界和场景树；后台生成候选、几何与离线 PCM。结构、细节与动画可以分片完成，但世界不能发布半个失效事务。撤销还原几何与作者数据，已经输出的 PCM 无法倒放；在下一可写帧接回恢复声音。撤销不能被旧每乐句单槽或 −5V 成本拦住。

规划关系保留六类用途：reserve 保净空、connect 接真实入口、support 提供基础/公共服务、attract 选择模块倾向、focus 设置视觉/音乐关注、pressure 只描述空间拥挤或冲突。它们通过查询和候选权重工作，后两者不制造维护惩罚，任何关系都不自行增加建筑。

#### 4. 公共空间与留地几何

现有 `planning_reservations`、`target_polygons/footprint_components`、`hole_polygons/target_holes` 等字段保存完整范围；旧单 `polygon` 只作兼容读入，不截掉第二块或内院。目标组件不重叠，孔洞严格位于所属外环，拒绝自交；入口须能从真实道路接入。

部分兑现时进行同一布尔运算：原留地 = 本次目标 + 残余（扣除孔洞并在几何容差内比较面积）。残余组件保留 `root/parent/source` 链和独立 ID，可以再次规划；预览、提交、保存、JSON 与后台副本使用同一组范围。孔洞保留为空间，不能被植被/装饰画成已建公园。

设施搬迁保持设施 ID、用途、等级和历史来源；原位同用途不隐式升级，扩容是另一个动作。只取消关联待提交改造，不清空其他操作。服务容量是空间表现/工具配置，旧每级 18、三级等参数不成为所有新版功能的硬限制。当前服务与客流不能自动新增住宅。

#### 5. 玩家作者容器

现有容器：`authorship={schema:1,next_neighborhood_id,neighborhoods}`。单项包含 `id/name/revision/member_ids/selection_kind/created_audio_frame/modified_audio_frame`。当前 `selection_kind=explicit_buildings`；成员是实际存在且已出生的建筑稳定 `district_id`，去重并排序。名字去首尾空白后非空，编辑保留 ID/创建帧并增加 revision。

作者数据独立于 World 后台交换和内部 CID。作品二进制中的 `city.authorship`、可读 DNA 的 `runtime.authorship` 真值及顶层可读投影沿现有保存路径保持一致；加载使用权威真值，不分别造两份作者名单。未知作者 schema 明确拒绝，缺字段旧档为空，不从系统分桶名称补造玩家街坊。

历史成员暂时失效时保留原 ID，详情可说明对象已改造；改名不静默删除来源。新增成员由玩家明确操作；删除/改造的来源通过可撤销事务记录。未来空间范围选区另标 schema/selection_kind，与现有显式成员区分。默认扩展只有 Intent 明确归属时才加入街坊，不因为同音或共墙自动认领。

#### 6. 音频技术合同

世界建设时间、场景自然时间和设备音频时间有不同职责。新版建筑/道路立即提交；昼夜在关闭音频/暂停设备时照常工作。声音同步用实际 PCM 采样帧：不要用每帧 delta 累积音乐节拍，也不要回写预填缓冲。

现有基线为 120 BPM、22050 Hz、0.12 s 模型缓冲与 70 实际 RenderVoice；部分大城实际供音队列有 0.24 s 下限。边界由绝对拍序号乘采样率取整，避免半拍 5512/5513 的累积漂移。实际可听帧 = rendered − queued + 设备混音时间补偿，限范围并保持单调。新采样率/队列配置须和缓存、事件/存档版本一起迁移。

AudioPlan 至少记录计划/世界版本、提交帧、来源事件/对象、role/pitch/timbre、起止、增益/声像/包络/滤波和签名。排程按帧切块并稳定排序。可听活动行保存 `event_id/source_event_id/source_id/receiver_id/generation/source_onset/onset/end_frame/pitch/strength`；只查询实际渲染、当前可听的有界窗口，不能从未来资格画演奏标记。活动缓存是运行时数据，不进 DNA；静音/黑屏/停播按实际控制隐藏。

河岸 Reply 保存真实接收者与来源，延两拍、generation=1，不递归复制。来源进退有 `born_at/retired_at`，新入场不补播历史事件；改音的 A→B→A 是新生命周期，不复活旧 Reply。签名包含来源音级与接收身份，连续交接保留相位、当前淡化电平和已发生尾音。

精确共享波形只在音高、相位、包络、滤波、控制与来源签名一致时成立，逐声道累计原增益。`√k` 是改编归一化；不同控制状态不能合并。当前精确路径保留 PCM/功率相对误差 ≤2e-5 的旧测试，重新编曲另验响度。节点计数包括降电平背景、环境、装饰与交叉尾音，全城参与不等于解除预算。

现有初始完整混音校准约 −16 LUFS、公共增益固定、真峰值留 3 dB；mute/solo/镜头不重新校准。明确静音最高优先，独听/聚焦与自动视野调度其次，恢复时回到保存的显式控制。旧 25% Drone RMS 保护和“抖/刺”诊断 fixture 属旧合成器回归，新的音乐编制不强制每首曲保留同样 drone 比例，也不要求玩家辨别拍频才能操作。

#### 7. 同源试听

沿用现有私有 Model、连续相位和同一版本城市快照，比较不改造/留地/公园/文化馆或不同风格。副本保留待提交项、控制和来源；监听只输出一个比较分支，原城相位继续，不把新旧音轨叠加伪造差异。

世界版本、候选几何、目标/选区修订、来源、控制或排程边界变化使旧试听失效。取消恢复控制，不消耗正式 RNG。服务/空间有差异而主题尚未实际变化时 PCM 可以相同，面板按真实后果说明，不增造声部强行让分支不同。“后续机会”是条件描述，不是已经发生或保证得到的结果。

#### 8. 保存、种子与作品版本

现有 terrain/mode/boons/form/events 五条命名随机子流与计数器保留供旧作品复现；每日种子沿旧 UTC 日期 + 版本派生，自选根种子与生成器版本一起保存。新房屋/植被 Intent 派生局部子流，悬停、选房、镜头和装饰增减不重排整城。相同操作重做用同一种子和规则版本。

保存世界、作者真值、用户意图、拓扑/资产/生成版本、历史区、时代传播进度和必要音频状态；不保存线程、设备句柄、网格索引、临时焦点或可听标记缓存。旧档新字段为空/明确默认值，未知 schema 或损坏档不清空后覆盖。大整数 JSON ID/计数按现有安全精度路径或字符串编码处理。

临时写入、回读校验、替换正式文件并保留上一有效档；同时覆盖二进制作品、JSON DNA 与载入继续。可继续编辑、同版本确定回放、跨版本重新合成是三种验收，不能互相代替。日常/手选种子、具名快照、图鉴和来信使用实际事件来源；录音导出单独记录格式/采样率/素材权利，不把实时设备循环录下当作可重放作品格式。

#### 9. 交通和自然表现

路线、站点、路径 legs、步行接驳、换乘、需求分别保存身份。端点与图节点一致，不以最近距离把两岸无桥站点连上。改线时车辆完成旧路段或到下一合法节点再接新线，不跳过河面或瞬移到新站。时代Ⅰ–Ⅲ马车、Ⅳ电车、Ⅴ公交/汽车仍是表现素材，可在低画质按区域分频调度。

风、水、昼夜使用持久的场景自然时间，音符标记使用可听帧。既有昼夜从 audible_frame 派生，在迁移时用保存相位桥接到场景时间，避免设备停播冻结自然或载入跳天色；两个时钟不重复写同一真值。季节后置，不改地形拓扑或建设资格。

#### 10. 资产与派生缓存

现有 manifest schema 2 包含 `id/category/texture/era/origin/pixels_per_world/plot_span/image_bounds/model_bounds/source/license` 等，新增模块支持接口标签、层高、真实足迹、朝向、LOD 和命中代理。旧资产 metadata 与玩家历史分别保存；`voice_tag` 可以提示素材，不锁功能与乐器一一对应。

2.5D 真实四向对应世界北/东/南/西，不旋转 PNG 伪造门向；主图、阴影、窗光各带 origin 与尺度，并由真实几何烘焙。现有 2048 主图/512 检查图等是制作配置，新模板按显示尺寸调整。索引色纹理不直接线性混合槽号：先解析色板成 RGBA 再做过滤/mip，或使用明确的离散采样路径。

稳定地表、街面、屋顶、阴影/夜光按对象/几何版本和材质状态缓存。重绑作品即使几何相同也检查来源与夜光注册，避免复用缓存漏灯。实例槽回收和 dirty 上传按空间块/真实变化范围做，删除后的 GPU 数据及时失效。镜头移动只变换/裁剪，单栋编辑不全城重烘焙。原始模型/素材保持可恢复，源代码许可与纹理/音频许可分别登记。

#### 11. 验证与证据复用

#### 取用三库的具体机制

| 参考 | 已阅读的本地入口 | 本作采用 |

| Townscaper | `townscaper_state_save_history.md`、局部生成/拓扑报告 | 稳定局部占用、按动作分组撤销、重做同 ID；本作撤销会标 dirty，新分支不会复用已发布 ID |

#### 当前实现

城市地面使用连续 `(x,z)`，房屋使用宿主 origin + 局部 `(x,z,level)`，墙格 1.8、层高 1.7。房屋/模块/道路分别保留 ID，表现批次不认领身份。射线命中真实 cell 碰撞体，以稳定 ID 和面法线形成候选；预览不修改模型。

一次提交完成空间/支撑校验→真值变更→一项历史→局部重建。完整道路笔画即时落定，含完整两岸跨越的横向段生成桥；拒绝沿水、断桥和穿墙。道路图分割真实交点及相交路宽，包含自由笔画从已有路面内部起笔的共线情况，避免“桥可见但右岸不可达”。

每房和每条路有指纹、稳定 root 与材质合批。名字不触发几何重建，其他对象只在门前装饰净空真实改变时重建。地景一次生成并保留；音乐一次后台合成七条等长共享PCM，编辑只调层音量/乐句预设，不随区域数量增轨；城市建设不等待音频。

#### 水、路、植被与性能要求

美术以本地 Tiny Glade 参考库为基础，统一连续意图、自然边缘、门路/桥岸接头、暖软材料和植被层次，Foundation 补充地形、水岸、可达及生活目的地。工具和数据不读取房屋格，取消不写入，提交与撤销进入同一事务。植被画笔已实现橄榄/柏/灌木与擦除，按弧长采样消除鼠标事件密度差异；确定种子与实例进入作品及编辑历史。

工具7已实现连续池塘/引水渠、三档宽度、整笔撤销和Shift填回。主河与新笔画精确合并为圆润轮廓，孔洞保留为小岛；普通形状三角化，带孔组按边界事件做梯形并集，无叠面。水、浅边和岸石在独立缓存层；水变只重建实际高度改变的道路和可见性改变的植被块。房屋/道路冲突预览列出对象与位置，拒绝提交；树木只隐藏，意图保留。新水域支持多次横跨桥，路面与居民高度统一查询。

植物按8米空间块 MultiMesh 渲染，复用几何/材质；障碍签名未变时复用可见性，单株变化只重建所在块。房屋/道路覆盖植物只改变派生可见性，保留树木原始意图供撤销。河水与浅岸使用共享 TIME 着色器，静音时照常流动。固定背景树在编辑范围外，范围内所有树群由作品数据驱动。

累计采购和小聚通过实际驻留完成事件写入 `life_progress`；编辑撤销不回退已完成生活。居民以稳定 home ID 保留节点；植物/名字/上层变化不改变道路签名，真实可达或用途变化才重新寻路，断路暂停并取消未完成服务。行程与演出进度已保存；载入按实际路网/用途验证后继续。

扩城先做空间分块/局部 dirty、共享材质与实例、距离细节，再增加特效。完整场景测 CPU/GPU 帧时、输入提交延迟、内存和音频状态；第一次缓存建立与连续编辑分别记录。当前独立对象缓存增加绘制批次，后期按空间块合批稳定对象，不能回到每次编辑重建全城。

本机同场景实测从全街坊重建 48–53 ms 降到局部编辑约 11–12 ms，有声运行约 180 FPS。自制三角面采用 Godot 绕序，并统一索引后再与原生构件合批，面数守恒有实际检查。证据范围是 6 房/7 路的 RTX 5070 Ti Laptop 小场景；大城和最低配置没有测量结论。详细原件见 [验证](../验证记录/新共鸣之城_2026-10-14/README.md)。

#### 一次试玩

用工具 1 点中间长房的右墙扩出一个房间，点它的顶面再加一层；用工具 2 点相邻屋顶留下露台。按住右键转动镜头能看到不同墙面。工具 3 沿空地拉路到门前，横跨两岸会补桥。工具 5 选房，改名或安排面包坊/演奏庭；居民沿接通的小路去采购和小聚。

红色候选说明当前位置被道路、河水、别房或支撑规则占用。点其他墙面继续；所有实际建设立即发生，不等待乐句，也不检查协和资格。

| 操作 | 行为 |
|---|---|
| 1 / 房屋 | 点墙扩展、点顶加层、空地新房 |
| 2 / 露台 | 点墙延伸露台、点顶建屋顶花园 |
| 3 / 道路 | 选自由曲线或两点直拉；按住左键画，松开提交，Esc 取消；接头自动融合，整笔撤销 |

| 5 / 用途 | 逐栋选房、输入名字后 Enter；居所/面包坊/演奏庭；选演奏庭可邀请街坊演出或提前结束 |
| 6 / 植被 | 选橄榄/柏/灌木和笔刷大小，拖动左键画树群；Shift 擦除，Esc 取消；整笔撤销 |
| 7 / 水岸 | 选池塘或引水渠与宽度；池塘在空地起笔，引水从已有水域起笔拖向干地；Shift 点击填回自建水域，Esc 取消，整笔撤销 |
| 8 / 街坊 | 自由刷一片街坊，松开提交；点击已有区命名/选暖庭、深流、织机；Shift移除整区，Esc取消；面板显示真实成员与沿路服务可达 |

| 保存 / Ctrl+S | 保存新作品；原存档版本保留 |
| 滚轮 / 右键 / 中键 | 缩放 / 转动 / 平移镜头 |
| H / 全景 | 恢复河湾镜头 |
| F | 隐藏界面拍照 |
| 音乐 / 光线 | 静音与开启 / 白昼与暖夕光 |

新作品保存于 Godot 用户目录 `city_creation_v1.json`，不覆盖旧 City DNA。坏档保留原文件并禁止当前试玩自动覆盖；读取成功才替换城市。窗口关闭完成已有编辑保存，未确认道路草稿不写入。

植被自动避开完整房屋足迹、门前、道路与河岸；新建筑覆盖树木时保留植物真值并隐藏冲突实例，撤销建设后原树恢复。居民不会因为植树、改名或加层重新回家；正常继续入口自动保存累计采购/小聚，重新打开后累计次数继续。

选演奏庭，点“邀请街坊演出”。街坊沿路赶来，到齐后演出24秒；演奏庭与参与房屋轮流主奏/应答，亮窗和音符对应实际音乐。点“结束这场演出”可提前返回日常；断路或改掉演奏庭用途也会取消。静音不暂停居民，结束后普通配乐淡回。正常继续入口每15秒、手动保存与关闭时保存行程/驻留/演出进度，重新打开接着走。试听和截图见 [演出记录](../验证记录/街坊演出_2026-10-14/README.md)。

水岸可以合流、围出小岛，新增道路完整横跨后自动搭桥。红色水岸预影会列出冲突房屋/道路；调整路径后继续，当前工具不覆盖这些结构。水域覆盖树群只隐藏植物，撤销后恢复原树。基础主河暂不能填回。

用工具8沿几座房屋刷出街坊，选风格、为它起名；名称输入后Enter。房屋按最初落点归属，扩房不漂移，新房加入已有区，重叠范围归最后一笔。相同房屋用途也能选择不同声音；风格在下一个轮到该房屋的乐句进入，编辑和撤销立即发生。平移焦点改变近处房屋的轮换，听见后对应房屋亮窗；街坊没有自动扩房。面板的采购/演奏可达包含区外服务，沿路真能走到才计入；隔河声音照常参与。图与三种试听见 [街坊记录](../验证记录/街坊划区_2026-10-14/README.md)。

本轮已验证真实输入、删除/撤销、水岸/植被/音乐街坊笔画、保存与居民可达；美术统一以本地 Tiny Glade 参考库为基础。功能区生成倾向、完整经营进展、五时代与完整视野声场尚未完成。实现与证据见 [新城切片](21_新城创作切片.md)。旧 Demo 操作说明完整保留在 [旧入口说明](../废弃/文档/2026-10-14_新城入口前/Demo快速开始.md)。

### 待实验与实施依赖

已明确的最新需求直接实现，不重新询问“是否允许局部格、无格道路或声音退出循环”。下列是需要原型回答的问题。

| 问题 | 最小实验 | 决定什么 |
|---|---|---|
| 墙格点击和社区扩展是否自然 | 同一栋房的平墙、转角、上层、露台、移除 | 单元尺度/拓扑、命中和模块接口 |
| 2.5D 是否能承载动态接缝 | 同场景 2.5D、低多边形 3D/混合样例，至少一条动态路接门 | 渲染实现、镜头范围和资产成本 |
| 风格细节与性能 | 同镜头粗模/基础/完整细节与 p95 帧时 | 哪些细节保留、LOD/材质预算 |
| 视野声场是否舒服 | 近景→边缘→远景，静音/自动/连接 A/B | 淡化迟滞、并发密度、远处回应间隔 |
| 强力建筑是否改变操作 | 一座圆形剧场或批量布局能力前后同任务 | 首批能力与解锁节奏 |
| 时代如何保护玩家修改 | 高低混合屋顶、已命名街坊、正在编辑的房屋换代/撤销 | 资产版本迁移、演出优先级 |

先做房屋与道路的美术/交互切片，再接自然和声音，最后扩大时代与城市规模。模块尺度、区域边界和测量预算可由开发者按实验自主调整。

旧叛离、祝福权重、债务、R/V 崩盘、精确节拍解锁和容量经济不再是开工依赖。旧内容候选仍可在历史资料查到；重新采用时要证明对最新目标的价值。

#### 复核后明确的依赖

新增拓扑/工具需要作品 schema 迁移；建设即时提交需要和旧 pending/声音事件拆开；昼夜迁移需要从原可听帧保留相位，音乐连接需要稳定范围/修订和控制优先级。这些是工程工作，已给定 [开发接口](20_开发接口与迁移.md)，执行方自主实现，不列为再次审批。

后期120FPS和渐进换代一分多钟是修改前已记录的有效目标，本版保留。剩余的是如何达到性能、演出时编辑如何接续、用户是否满意风格/手感/听感；不能把没做原型改写成需求未授权。旧图鉴/来信、季节、27地标与14功能区按可选内容分期，不阻塞第一点击和道路接合。

## 施工文档规则

来源：[施工文档规则.md](施工文档规则.md)

### 文档维护

按最新用户需求更新所属正文和 spec；不要只在顶部加“新规则优先”而保留互相矛盾的现行条款。

正文写体验与系统关系，spec 写接口和验证，PROJECT 写当前目标/已实现/验证/下一步。数字只在一个位置维护；没实测的数字是调参起点，不能写成硬限制。

设计目标、已实现行为和测试证据分开陈述。常规架构、库、资产组织和验证顺序由开发者决定，不用待裁定表逐项申请许可。

重要旧稿先完整备份，再移入根 `废弃/文档/`；原文件名、来源、替代位置和未吸收内容可查。日志、失败夹具和大量截图留在验证/归档目录，开发正文只保留结论与入口。

只做能证明改动的最小检查：文档链接/合并稿同步，数据源变化时加参数不变校验；不因改文档重跑全游戏测试。合并稿由 `python tools/merge_docs_compact.py` 生成，用 `--check` 核对，源文档是编辑入口。

#### 兼容数据与覆盖维护

新玩法行为只在对应正文/spec定义；旧运行常量由 `数据/兼容规格/` 提供，不把R/V/额度再塞回新规则。共享对象、存档/音频来源和版本迁移细节统一在 `20_开发接口与迁移.md`。新的重要设计变更同步更新对应覆盖去向，不重新堆日期裁定或历史长日志。
