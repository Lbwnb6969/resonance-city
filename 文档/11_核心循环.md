# 02 · 核心循环

> 2026-10-09 重构版。本文定义玩家做什么、为什么想做、以及为什么在大城规模下仍然成立。
> 本文取代旧 `游戏策划案v3.1` 的 §4 循环部分，并给出问题单 Q01–Q13 的设计响应；实现差距与未验证体验仍见 [待裁定与依赖](待裁定与依赖.md)，不因已有方案而关闭。

---

## 0. 主要乐趣是什么（这是本文最重要的一段）

**玩家在塑造一座城市的性格，并听见自己塑造的结果。**

不是"发现失谐 → 从正确答案里选一个 → 提高数值 → 等下一个问题"。
而是：**"我要让这里成为一个低声部的地方"** —— 然后城市真的低下去，而且**你听得出那是你做的**。

| 旧循环的问题 | 新循环的回答 |
|---|---|
| 每个缺口都有"最安全 / 最和谐 / 收益最高"的唯一解 → 没有选择，只有执行 | **缺口是创造机会，不是待办事项**。玩家选择补什么、补在哪、补不补 |
| 候选音级只有数值高低不同 → "选 E 还是选 G"本质是同一件事 | **候选有真实的表达差异**（音域、角色、形态后果），不是数值差 |
| 提高 R 是覆盖一切的目标 | **R 只是布局和谐度**。张力、节奏、留白、历史都是正当目标（§8） |
| 创作感推迟到后期地标 | **前五分钟就有可理解、可记住的创作结果**（§3、§11） |
| 成功后只有"下一篇" | **作品留下**：城市曼陀罗、音频导出、继续经营（`15 §6`） |

## 1. 主身份裁定（回答 Q01）

**这是"配器驱动"的城市建造游戏。诊断是它的一个子动作，不是它的定位。**

三个动作的位置：

| 动作 | 位置 | 玩家感受 |
|---|---|---|
| **建造**（播种、划引力、踩路、引水） | **主循环** | "我在塑造这座城" |
| **配器**（判断缺口、选音、调音） | **主循环的核心判断** | "我知道这里**想成为**什么" |
| **诊断**（听出失谐、定位） | **子动作**，服务于配器 | "我听见这里不对，我知道该换成什么" |

**注意措辞的变化**：旧稿写"我知道这里**缺什么**"——那是填空。新稿写"我知道这里**想成为什么**"——那是塑造。
缺口系统保留，但定位从"任务清单"改为"提示这里有什么可能性"。

**旧反支柱的处理**：
- "玩家不自由输入音符、不直接作曲" → **保留**。音级来自系统给出的音阶集合，且必须与周围形成可听关系。
  玩家是**配器师**，不是作曲者。但要保证：**有限的选择必须产生真实的表达差异**（§5.2）。
- "核心时间用于听和判断，避免工具栏浏览吞掉注意力" → **保留并加强**（见 `16_界面与反馈.md`）。

## 2. 主循环

```
   ┌───────────────────────────────────────────────────────┐
   │                                                       │
   ▼                                                       │
 ① 听    城市在演奏。听它现在的样子，也听它"少了什么"        │
   │                                                       │
   ▼                                                       │
 ② 想    这里应该成为什么？低音区？节奏区？留白？            │
   │      ——缺口提示只是"这里有可能"，不是"这里必须"          │
   │                                                       │
   ▼                                                       │
 ③ 选音    3–5 个候选，每个有试听，且**表达不同**（§5.2）：   │
   │        低音候选 / 节奏候选 / 协和候选 / 张力候选         │
   ▼                                                       │
 ④ 放置    在连续地形上点一个位置。即时反馈：音高滑动、       │
   │        落点涟漪、预测和弦预览、社区形态预影              │
   ▼                                                       │
 ⑤ 落定    拍点改声（0.5 s）；乐句边界改城（16 s）           │
   │        城市长出新建筑，新声部进入，社区轮廓变化           │
   ▼                                                       │
 ⑥ 城市长大   社区更完整，新的可能性在别处出现               │
   │                                                       │
   └───────────────────────────────────────────────────────┘
```

**循环周期**：约 16–32 秒（1–2 乐句）。一章 12 乐句 = 约 6–12 次完整循环。
**手感周期**：0.5–1 秒（L2 拍点改声），这是玩家真正感到"跟手"的那一层（见 `10_世界模型.md` §5）。

## 3. 首五分钟（具体操作序列）

这是审查标准：**玩家必须在五分钟内感到"这段是我做的"。**

| 时间 | 发生什么 | 玩家做什么 | 听到/看到什么 |
|---|---|---|---|
| 0:00–0:20 | 序曲。镜头从海面缓推入一片空河谷。**没有 UI**，只有地形和一条河 | 无 | 环境声床：水声、风、远处鸟鸣；河水的波光流速 = 环境声床的节奏 |
| 0:20–0:40 | 系统播第一段空白城市的"气息"：只有 drone 底噪 | 无 | 一个长大的 C 长音，很轻。字幕（一行）："这是它的呼吸" |
| 0:40–1:20 | **第一次播种**。唯一的引导：3 个候选音，**每个的悬停预览音都不同**（见 §5.2） | 选 C，在河边点一下 | **点击瞬间**：地面荡开一圈涟漪；一个 C 音响起并与底噪融合；半透明"胚"出现 |
| 1:20–1:36 | 乐句边界。胚变成一栋房子 | 无 | 一栋小房子"弹"出来（squash & stretch，1 拍）；camera 轻推；一声调内木质轻击 |
| 1:36–2:40 | 城市自己长：每乐句长一栋，自动挑协和位置 | 观察 | 房子一栋栋出现，每栋一声轻响；两栋紧邻的房子开始产生和声，你**听得出**它们合得来 |
| **2:40–3:20** | **第一次"这是我能决定的"时刻**（关键节点，见下） | 听、判断、**做出一个表达选择** | 对岸听起来是空的；系统给 3 个候选，标明它们**各自会带来什么**（不是"哪个更好"） |
| 3:20–4:00 | 玩家在河对岸播下 G | 选 G，放置 | 落点预览显示"与对岸形成纯五度 · 预计形成对唱" + 立刻试听 |
| 4:00–4:16 | 落定 | 无 | G 出现，**两岸第一次合上**；河面泛起一次明显波光；声音明显变"满" |
| 4:16–5:00 | 系统识别"两岸对唱"雏形 | 无 | 柔和提示滑入（可悬停看详情，6 秒自动收） |

### 3.1 第一次"表达选择"（2:40 那一刻必须做到的事）

**它不是**："这里缺一个五度，建议放 G，点击接受。" —— 那是执行，不是创作。

**它必须是**：系统给出 3 个候选，**每一个都能听出不同的未来**，而且**没有哪个是唯一正确的**。

| 候选 | 悬停时玩家听到的 | 文字提示 | 落定后果 |
|---|---|---|---|
| **G（五度）** | 空、开、稳 —— 与 C 合成一个开阔的和声 | "形成对唱 · 两岸呼应" | 两岸合上；触发"双子港"雏形 |
| **C（八度）** | 厚、实 —— 声音更沉，空间更满 | "加强地基 · 但两岸同音" | 更"厚"，但**不会触发**对唱（同音不产生应答） |
| **E（三度）** | 亮、暖 —— 声音变明亮 | "加入色彩 · 和声更复杂" | 三个音构成 C 大三和弦，最"完整"，但**没有对唱** |

**三者的收益量级相当**（没有哪个是明显的最优解）；差别在**城市性格**：
- 选 G → 这座城偏向"两岸对唱、呼应"的性格
- 选 C → 偏向"厚重、单中心"
- 选 E → 偏向"明亮、和声丰富"

**这就是"玩家在决定城市将成为一个怎样的地方"。** 三个选项都能通关，都会让声音变好，
但五年后玩家回想这一局，他会记得自己选了什么。**这一条做到，主要乐趣成立；做不到，整个设计不成立。**

**关键设计**：
- **第一分钟没有 UI 面板**。只有城市、地形、和一行字幕。
- **第一次点击的反馈必须极强**：涟漪 + 声音 + 预影 + 预测文案。
- **缺口必须声音先行、视觉随后**。玩家先"听出空"，再看到提示。
- **第一次成功的和声必须可辨认**：两岸合上时要有明确的听觉 + 视觉双重奖励。

## 4. 两条都值得选的路线（回答 Q09 / Q29）

审查标准：**玩家为什么不会总是选系统算出来最安全、最和谐、收益最高的方案？**

**场景**：中局（约 15 分钟），你在两条河之间有一片可建地，面积够开三个社区。
系统同时提示两个可能性：这里可以成为低音区，也可以成为节奏区。

**两条路线的收益量级相同，差异在"这座城市会变成什么"。**

### 路线 A · 深流（低音路线）

| 项 | 内容 |
|---|---|
| **追求什么** | 一座有"底"的城。声音沉稳、宽厚，上面可以飘旋律而不塌 |
| **具体做什么** | 在河谷低洼处播低八度共鸣点（如 C2），用引力带让它沿等高线铺开成整片低音社区；把附近的高音建筑往上坡方向调 |
| **立即看到/听到** | 落点预览音**明显比周围低一个八度**，低音沉下去；低音社区建成后，全城的 drone 底噪变厚，原本"飘"的旋律突然有了依靠 |
| **城市正式变化后** | 形态：河谷底部出现一条**深色调的低音带**，房屋沿等高线排列，与其他社区色彩分明。音乐：低音槽锁定在这个社区，全城的地基音变成它的音级 |
| **优势** | 全城获得地基；高音社区变得更"能立住"；深流形态允许在上方叠更多旋律社区而不会听起来乱 |
| **代价** | 低音社区**占地大、成熟慢**（低音建筑需要更大空间才升级）；**它不提供节奏**——城市依然"没有推进力" |
| **适用情境** | 你已经有几个旋律社区但听起来发飘；你打算长期经营；你偏爱舒缓的音乐 |
| **为什么不是另一条的劣化版** | 织机路线**无法替代它**：节奏再密，也不能产生低频支撑。把全城调成低音也不行——那样就没有旋律可听了 |

### 路线 B · 织机（节奏路线）

| 项 | 内容 |
|---|---|
| **追求什么** | 一座"活"的城。有推进力、有律动，长音不再拖沓 |
| **具体做什么** | 在平原播商业共鸣点群，让它们密集生长；用踩路切出小广场控制密度 |
| **立即看到/听到** | 落点预览音**带一个短促的律动尾音**（不是长音）；商业社区成型后，全城的节拍感立刻出现，"散"变成"有拍子" |
| **城市正式变化后** | 形态：**密集的、屋顶节奏一致的商业街区**，中间夹小广场，与低音河谷的疏朗形成对比。音乐：节奏槽锁定，全城的律动由它驱动 |
| **优势** | 全城获得推进力；织机形态的律动可与任意社区形成应答；商业区的密集带来更多声部组，声音层次丰富 |
| **代价** | 商业律动会与相邻 drone 抢注意力（ducking 反复触发，**听感变忙**）；密集区留白下降，**触发"缺留白"可能**；商业建筑与住宅的换色会让画面更花 |
| **适用情境** | 你觉得城市太长、太慢、听不出时间感；你偏好有力的音乐；你打算快速扩张 |
| **为什么不是另一条的劣化版** | 深流路线**无法替代它**：再多低音也不能产生节奏。把低音区调成商业只会同时失去低频和节奏 |

### 4.1 为什么这两条不是"最优解 vs 次优解"

旧设计的问题不是"选项太少"，而是**有一个选项在数值上全面优于其他**（同度 +8 最划算），
所以玩家没有真正的选择——只有一次计算。

现在两条路线**在目标函数上等价**：
- 它们**都满足全部三条跨越路径**（都能赢）
- 它们**对同一个指标（R）的影响大致相同**（都产生协和关系）
- 差别在**声音性格与城市形态**，而这两者**没有优劣，只有偏好**

**制度保证**（不是靠文案说服）：
1. **音乐性权重（`spec.space` 表 SP4）**：单一路线撑满全城时，同音占据率上升，收益自动减半；
   两条路线都自然被推着走向多样，**不偏向任何一条**。
2. **R 不是唯一判据**：除崩盘阈值外，没有任何跨越条件、缺口奖励以 R 为唯一判据（`spec.space` 表 SP3）。
3. **两条路线的收益都是"全城性的"**：一条给地基，一条给推进力，互不覆盖。

**验收要求**：
- 两条路线的**城貌截图必须明显不同**
- **30 秒音频必须盲听可辨**（HUMAN-DIFF）
- **两者的收益数字必须量级相当**（执行 AI 需构造两局并给出对比表，不得出现"一条明显更强"）

**做不到的话**：说明设计没成立，需要回头改，不是改文案。

---

### 4.2 路线成立的证据边界

两条路线收益相当、没有唯一最优解是待实玩的设计目标。比较同种子、相近操作额度下的城貌、音乐、成长和玩家偏好；核查“全城同音”的安全走法为何仍有吸引力，以及多音、张力或不同布局带来的独立回报。M 只缩放规定的局部项，不能据此证明全局同音优势已消失，也不应靠强制投放故障让其他路线成立。

全局 R 是关系评分，不是音乐审美或社区健康的替代品。大城全局 R 高时，仍检查社区局部 R、成员 V 和可听状态；小城少数坏边也需核查反馈与恢复机会。沿用现行危机阈值，不另加社区失败条件，不把关注机会做成逐栋维修清单。

## 5. 玩家动词（完整清单）

### 5.1 城市动词

| 动词 | 操作 | 落定效果 | 代价 | 频率 |
|---|---|---|---|---|
| **播种**（释放共鸣点） | 在任意合法位置点一下（选好音级） | 新建共鸣点，下一乐句边界长成胚 | 无 | 受每乐句介入槽限制 |
| **调音** | 悬停建筑 → 点音级 | 改 current_midi | −10 活力 | 每乐句 1 次 |
| **迁移** | 拖动建筑到新位置 | 位置改变，耦合关系重算 | 静音 1 乐句 | 每乐句 1 次 |
| **划引力** | 拖出一条方向线 | 生长候选偏向该方向（只排序，不改数值） | 重划暂停扩张 1 乐句 | 同时 1 条 |
| **踩路** | 在两点之间划一下，重复 3 次 | 形成街道，阻断该处声学耦合 | 不可撤销 | 每乐句 1 次 |
| **引水**（新） | 从水源拖出一条河道 | 水域生成，隔声 + 对唱加成 | 不可撤销，占地 | 每乐章 1 次 |
| **植树**（新） | 在陆地点一下 | 林地生成，吸高频 | 占地，降低密度 | 每乐句 1 次（可与调音竞争） |
| **选址**（新，无独立按钮） | 播种时选择落点：沿街 / 内院 / 空地 | **决定这栋会长成什么**（见下 §5.1.1） | 无 | 随播种 |

#### 5.1.1 落点就是选择（回答"我能不能随便造房子"）

**任意合法陆地都能点。没有"此处不可建"的拒绝。**

但**位置决定未来**，这就是玩家的真实选择：

| 落点 | 玩家看到/读到 | 会长成什么 |
|---|---|---|
| **临街地块**（临街面 ≥2 向） | 预览卡："沿街 · 可成长" | 全阶段可达（胚→群→央→腔→地标），参与命名形态 |
| **内地块**（临街面 =1 且有邻居） | "内院 · 需先有邻" | 可升级，但首栋要等 2 乐句 |
| **空地**（无临街面） | "孤屋 · 不会长大" | 速率减半，**停在群**，耦合略弱 |

**为什么不是"拒绝"**：拒绝会在玩家最想试的那一瞬间关掉输入。
**点三次空地看到三次"孤屋"，玩家自己就懂了**——这比弹提示好。

**空地的正当用途**：独奏岛、瞭望点、故意留白的**前兆**。它是表达，不是错误。
**验收**：若玩家从不主动选空地，**改空地的收益，不是删空地**（`spec.fabric` 表 FB1 §1.3）。

#### 5.1.2 连片是玩家造出来的，不是系统撒的（新）

**房子会长到一起**，而且**怎么长是玩家的选择**：

| 玩家怎么做 | 城市变成什么 |
|---|---|
| 沿同一条街连续播种 | 共享山墙 + 屋顶连成一片 → 读作**一条街** |
| 在街区内部围合 | 形成**庭院**（算留白，可作内陆地块） |
| 把房子散着放 | 各自孤立 → 读作**村落** |

**这不是一个新的建造模式**——它就是"你把共鸣点放在哪"的自然结果。
玩家不需要学新按钮，只需要**看懂沿街与散落的差别**。

**关键约束（必须写进 UI 与实现）**：连片**只发生在视觉层**。
共享山墙**不合并音级、不合并 ID、不给 R/V 加成**。
**每一栋永远唱自己的音**——连片让城市好看，不让人少一个音（`spec.fabric` §0）。

**这是"好看"的主要引擎**：留白来自地形与不建的地方，层次与城市感来自连片。
第 5–15 分钟玩家应当能说出："**我把它盖成了一条街，不是一堆房子。**"

### 5.2 候选音：必须表达不同（回答"有限选择是否等于没有选择"）

**这是"玩家不自由输入音符"这条反支柱能否成立的关键。**

如果候选只有数值高低（"E 更协和，G 次之"），那么玩家面对的不是选择，是一道有唯一答案的题。
**有限的选择必须有真实的表达差异**，否则它不构成创作。

**裁定：候选按"表达类型"分组给出，而不是按"得分"排序给出。**

| 候选类型 | 音程关系 | 玩家听到的 | 表达含义 |
|---|---|---|---|
| **地基** | 与主音的八度 / 同度 | 沉、厚、稳 | "让这里更结实" |
| **协和** | 与最近邻居的三度 / 六度 | 亮、暖、满 | "让这里更和谐" |
| **框架** | 四度 / 五度 | 空、开、稳 | "让这里更开阔、更容易呼应" |
| **张力** | 大二 / 小七 | 不稳、待解决 | "让这里留一个悬念" |
| **节奏** | 商业类型（律动层） | 短促、有拍子 | "让这里动起来" |

**规则**：

1. **每次给出 3–5 个候选，跨至少 3 个不同类型的候选**。不得给出"五个都是协和、只是得分不同"的列表。
2. **候选按类型分组显示**，每组标注它"会带来什么性格"，**不标注"推荐指数"**。
3. **每个候选的悬停预览音必须真的不同**——不是同一段音高不同，而是**音域、时值、层次都不同**
   （低音候选是长音，节奏候选带律动尾音，张力候选有明显的不稳定感）。
4. **不得存在"系统推荐的那个"**：可以高亮 1 个与当前缺口匹配的候选（单推荐焦点），
   但**不得暗示其他候选是错的**——它们只是不同。
5. **张力候选（大二/小七）是正当选项**，不是"等待解决的错误"。选它会让这一区域暂时不稳，
   但它是"留悬念"这个表达的一部分。

**验收**：给出 3 个候选，**盲听三段预览音，必须能分辨出哪个是低音、哪个是节奏、哪个是张力**。
如果听不出，候选系统没成立，改为重新设计候选，**不是改文案**。

### 5.3 聆听动词（不改城市）

| 动词 | 作用 |
|---|---|
| **试听** | 长按 3 秒，听这个选择落定后的未来（独立渲染，不改真实城） |
| **单独聆听** | Solo 一个社区（不是单栋），听清它 |
| **静音** | Mute 一个社区 |
| **聚焦** | 点一栋建筑，镜头推进，界面显示它的完整信息 |
| **全城/社区切换** | 两种聆听尺度之间切换（见 `12_声音架构.md` §5） |

### 5.4 单推荐焦点原则

**任意时刻，界面只突出 1 个推荐动作。** 其余动词**可用但不显眼**（在悬停菜单或快捷键里）。

这来自旧 v3.1 原则"玩家任意时刻能做什么，答案不少于 3 个，但界面同时只突出 1 个推荐焦点"——**保留，并升级为 UI 的核心约束**。

## 6. 缺口系统（回答 Q08 / Q09）

**先读这一条，它决定缺口的性质**：

> **缺口是一个创造机会，不是一个必须清除的任务。**
>
> 玩家可以选择补低音、补节奏、补和声关系、补空间应答，**也可以选择留白**，或者完全不理它去做别的。
> 没有任何机制要求"每个缺口都必须被填上"。缺口不是待办清单，是**系统在说"这里还有个可能"**。

### 6.1 缺口的产生

**缺口来自城市自己的演奏，不是随机投放。**

每乐句边界，系统按**社区**为单位计算配器完整度，找出缺失的角色（5 类）：

| 缺口类型 | 判定 | 注意 |
|---|---|---|
| **缺低音** | 全城无人机最近 4 秒的 20–130 Hz 功率 / 总功率 < 15% | 用**参考配器状态**的 PCM 计算，不受玩家 Solo/Mute/悬停影响 |
| **缺节奏** | 某社区半径 6 内无商业律动建筑 | 区域级 |
| **缺协和** | 某社区邻近集合内存在 `s ≤ 0.30` 的配对，且无解法音 | **只在 `N₁₂` 内判定**（`spec.space` 表 SP5），否则密集区处处是缺口 |
| **缺留白** | 某区域建筑密度超阈值且无公园/水面间隔 | 区域级 |
| **缺应答** | 存在两片分离社区（距离 5–10），音程协和但未形成呼应 | 区域级 |

**每条缺口有稳定 ID**，被填上后记录 ID，**不得因为玩家来回调音而反复计入跨章计数**（防刷）。
缺口依据**参考配器状态**，**不因玩家 Solo / Mute / 悬停而改变**——否则玩家一 Solo 就凭空造出缺口。

### 6.2 缺口的呈现

**声音先行**：缺口区域的可听特征先出现（空、干、闷、挤），**然后**才是视觉柔光。

视觉表达（**不扭曲几何**，沿用美学红线）：

| 缺口 | 视觉 |
|---|---|
| 缺低音 | 该区域色温偏冷、对比略降，像"没被照亮" |
| 缺节奏 | 该区域微动效变慢 |
| 缺协和 | 失谐配对之间极轻的"弦驰"（地面纹理相位微错位） |
| 缺留白 | 该区域空气感变闷（雾感微增） |
| 缺应答 | 两片社区之间一条极淡的虚线，像"未接上的线" |

**呈现纪律**：缺口**绝不弹窗、绝不出卡、绝不显示数字进度**。它的视觉是"柔光"，听觉是"这里听起来空"。
**玩家可以完全不知道缺口系统的存在而正常游玩**——这是"极简 UI"与"不把创作变成维护"的共同要求。

### 6.3 不填会怎样（回答 Q08）

**答案是：几乎什么都不会发生，这是设计意图。**

| 情形 | 后果 |
|---|---|
| 不填某个缺口 | **没有后果**。缺口会随城市变化自然消失或变形 |
| 长期不填同一区域 | 该区域**缓慢锈蚀**：每乐句 V −1，耦合 σ 略降（声音变干、变闷） |
| 锈蚀积累 | 形成**锈蚀簇**（局部，不是全城），视觉上是**一小片灰化街区** |
| 想恢复 | **可逆**：填上缺口后逐步恢复；也可以用别的动作（植树、引水、调整音级）改善 |

**关键约束**：

- **锈蚀是局部可见的，不是全城一起变**（回答 Q10：大城不再稀释局部问题）。
- **锈蚀不阻塞、不扣分、不导致失败**（唯一的失败仍是 `R < 40` 连续 3 乐句崩盘）。
- **锈蚀的速度必须慢到"可以放着不管很久"**——V −1/乐句意味着 50 个乐句（13 分钟）才掉到 0；
  而 V 不影响 R，只影响视觉密度与微动效。**它是"声音变干"的隐喻，不是惩罚。**
- **缺口按社区聚合，不按栋**——所以一片锈蚀簇需要一个社区级的动作，**不需要逐栋维护**。

**为什么这样设计**：压力应当来自**审美的自我要求**（我想让这段更好听），而不是系统的惩罚。
这正是"好玩易玩"的基础。**如果实测发现玩家感到被逼迫，就继续降低锈蚀速度，而不是加提示。**

## 7. 跨章条件（回答 Q09）

**旧条件**：本乐章 ≥3 次"协和解决"（把大二/小三提升到协和）+ 末乐句 R ≥ 70。

**问题**：一直和谐建城的玩家没有可计数的"解决"，反而拿不到晋升。**"把城建好"不算数。**

**新条件（三选一，任一满足即可跨越）**：

| 路径 | 条件 | 适合 |
|---|---|---|
| **修复者** | 本乐章 ≥3 次协和解决，且末乐句 R ≥70 | 处理了失谐的玩家 |
| **建造者** | 本乐章新增建筑数 ≥ **`max(6, ceil(0.04 × N))`**（N = 当前全城建筑数），且末乐句 R ≥ 70 | 一直在和谐扩张的玩家 |
| **配器师** | 本乐章填上 ≥2 个**不同 ID** 的声景缺口，且末乐句 R ≥ 70 | 在做配器的玩家 |

**"建造者"的阈值为什么随规模变化**：旧稿写死"≥6 栋"。在 9 栋的小城里，6 栋是 67% 的增长；
在 600 栋的大城里，6 栋是 1%——**大城里这条路径变成白送**。改为 `ceil(4% × N)` 后：

| N | 阈值 |
|---|---|
| 9–150 | 6 |
| 200 | 8 |
| 300 | 12 |
| 400 | 16 |
| 600 | 24 |

**三条路径必须分别独立判定**，任一满足即跨越；**不得要求三条全满足**。
**三全音的修复不得默认计入"修复者"**（三全音只在特定时代由工业产生，见 `spec.harmony` 时代段）。

**为什么三条并存**：三种玩法风格都有明确计数，都能拿到跨越。
**"把城建好"第一次成为赢得跨越的正当方式**（回答 Q09）——这是重构最核心的一处修正。

## 8. 张力与保留失谐（回答 Q07 / Q11）

**问题**：同音最优（`s = 1.0`，`ΔV +8`），所以最优解是全城调成 C。为什么玩家不总是这样选？

**旧答案不够**：旧稿说"全城同音听起来是平的"——这是**审美判断**，不是机制。
它无法阻止一个追求效率的玩家全城调 C，而那样的城市在数值上确实不差。

**新答案分两层，一层是机制，一层是表达**：

### 8.1 机制层：音乐性权重（`spec.space` 表 SP4）

**直接、可计算、不惩罚、不记账。**

- 当一栋建筑的音级在其**近邻集合**中的耦合占比 `occ > 0.40` 时，它参与的**所有边 `c` 乘 0.7**，`ΔV` 减半。
- 混入不同音级后 `occ` 回落至 **≤0.40** 才恢复，不累积、不停留；一栋不同音级不保证足够。
- **它按邻近度计算，不是全城统计**——全城有 5 个 C 社区但各自混居时，无影响。

**这降低了全同音的邻接活力收益**：全城调 C 时 `occ` 接近1，邻接 ΔV 减半；R 仍100，不能声称所有数值目标都已消除同音最优。
均衡分布时（五声音阶下每个音级约 20%），`occ` 都低，无人受损。

### 8.2 表达层：张力、节奏、留白都是正当目标

**明确允许、并明确设计为"有收益"的创作选择**：

| 结构 | 收益 | 为什么正当 |
|---|---|---|
| 三个以上音级构成的社区 | 装饰层更丰富（每音级一个装饰音型） | 音级多 = 音色层次多 |
| 五度/八度对唱 | 双方每乐句 **+2 活力** | 应答是音乐结构，不是"协和" |
| **有意保留一处未解决的张力**，在后续乐句解决 | 爆发加成 = E × 落点精度 | **紧张—解决是音乐的基本手段**，不是错误 |
| **纯节奏驱动**（低音区不发展，靠商业律动撑起全城） | 节奏槽锁定；织机形态解锁 | 鼓乐、电子乐都是这样成立的 |
| **大面积留白**（不建，只保水面与林地） | 留白缺口不触发；该区域声部全部退场，全城对比更强 | 留白是配器手段，不是"没建完" |
| **历史街区**（保留旧时代音色） | 不随跨越换装；形成时代对比 | 混音是风格，不是"没升级" |
| 全城 ≥4 个不同音级 | 解锁"排钟"式全城音阶报时 | 多样性直接产生新效果 |

### 8.3 明确的制度约束

1. **R 不是唯一判据**：除崩盘阈值（`R < 40` 连续 3 乐句）外，
   **没有任何跨越条件、缺口奖励、形态解锁以 R 为唯一判据**（`spec.space` 表 SP3）。
2. **不设"越高越好"的单一分数**。玩家看不到总分，也**不显示推荐的 R 目标**。
3. **三全音不是"必须消除的错误"**：它是工业身份的固有特征（表 B 保留），
   一个工业带城市可以理直气壮地带着它。
4. **N 条路线的收益必须量级相当**：执行 AI 需构造对比局验证，**不得出现一条明显更强**。

**关键**：多样性奖励**同时来自音乐本身（更好听、更多层）与机制（`occ` 权重）**，
但**机制只做"去掉唯一最优"，不做"奖励多样性分数"**——否则只是换了一个唯一最优。

## 9. 时间尺度

| 单位 | 长度 |
|---|---|
| 拍 | 0.5 s（120 BPM） |
| 小节 | 2 s |
| **乐句** | **8 小节 = 16 s** |
| 乐章 | 12 乐句 ≈ **3.2 min** |
| 一局（交响曲模式） | 7 乐章 ≈ 22 min（实际 25–35 min） |
| **自由共鸣模式（大城）** | **无固定长度，目标 40–90 分钟达到 400–600 栋** |

**大城的模式裁定**（回答 Q02 / Q19 / Q26）：

- **交响曲**（7 乐章）：终局目标120–180栋（spec.run 表 R8）；80–150栋是中型验证阶段。这是"一局"的标准体验。
- **自由共鸣**（无终点）：大城目标，400–600 栋、36–48 规划社区。可以随时保存、继续、聆听成品。
- **聆听模式**：把一座大城当壁纸，纯听不操作。

**为什么分两个模式**：22 分钟的 Roguelite 结构适合"再来一局"，但不可能长出大城。大城需要连续经营，所以给它独立的模式。**两模式共用同一套世界模型与声音架构，只是节奏与目标不同。**

## 10. 失败与压力（回答 Q08）

**唯一的全城级失败**：R < 40 连续 3 乐句 → **仅在交响曲模式下**结束本乐章进程（保留旧 HARM-003）；作品保留，可转继续经营。
**自由共鸣模式没有失败**：R < 40 只触发可逆的灰噪化（R > 48 退出），不结束、不计数（`spec.run.md` 表 R8-a）。
交响曲保留这层压力，是为了让"这一章收得好不好"有分量，服务于七乐章的叙事弧；它不用来惩罚失误。

**局部压力**：锈蚀簇（§6.3）。它不会结束游戏，但会让城市听起来越来越干、越来越闷，画面越来越灰。**玩家会自己想处理它**，因为本作的乐趣就是听好听的声音。

**没有倒计时，没有资源枯竭，没有强制的负面事件。**

**为什么**：这是"创作型"游戏，压力应当来自**审美的自我要求**（我想让这段更好听），而不是系统的惩罚。这正是"好玩易玩"的基础。

## 11. 作者感（回答 Q13）

**玩家在什么时刻感到"这是我的作品"？**

**旧稿的缺陷**：作者感的节点全部出现在**中后期**（命名形态、地标、环形合唱）。
玩家要玩 20 分钟才感到"这是我的"，前 20 分钟只是在执行任务。

**裁定：作者感必须在最早的可玩阶段出现，而且必须是"能记住的"结果。**

### 11.1 作者感的七个时刻（按出现顺序，前三个在 5 分钟内）

| 时刻 | 时间 | 机制 | 为什么玩家会记住 |
|---|---|---|---|
| **1. 第一次表达选择** | 2:40 | §3.1 的三个候选各有不同未来 | 他**选了**，而且听得出区别 |
| **2. 第一次听见自己的选择生效** | 4:00 | 两岸合上，声音明显变满 | 因果链闭环：我做的 → 声音变了 |
| **3. 第一次听见"我的社区"** | 5–8 min | **社区主题**（见 11.2） | 一段**用他自己调的音**奏出的旋律 |
| 4. 第一次命名形态 | 8–15 min | 环形合唱 / 深流 / 织机 | 形态用玩家的实际音级演奏 |
| 5. 第一次调音改旋律 | 10–20 min | 环形合唱的 n 拍序列**就是玩家调出来的** | 音序是他排的 |
| 6. 第一座地标唱的歌 | 20–40 min | 地标动机用落成时城市的实际音级写成 | 每座城的同一地标唱法不同 |
| 7. 终局聆听整城 | 40–90 min | 城市曼陀罗 + 音频导出 | 作品可保存、可带走 |

### 11.2 社区主题：作者感的核心机制（必须在 P1 就有）

**规则**：任何 ≥6 栋的成熟规划社区，自动生成一段**社区主题**——

- 取该社区建筑的**实际音级**（不是系统预设的音阶）
- 按**稳定几何序**排列（如沿社区主轴的投影序，或按社区内建筑的稳定 ID 序）
- 生成一段 4–8 音的**短动机**，在该社区获得焦点或单独聆听时播放
- **玩家改变其中任何一栋的音级，主题就变了**——这是"我编的"的直接证据

**为什么这是核心**：

- **它在 5–8 分钟就出现**，不需要地标、不需要后期时代。
- 它是**可记忆的**：玩家能哼出自己社区的动机。
- 它把"调音"从一个数值操作变成"改一个乐句"。
- 它是后续一切创作机制（环形合唱、地标动机）的**同一套逻辑的最小版本**。

**尺度分工**：社区尺度下主题用于局部聆听；全城演出中主题若作为可辨的前景旋律，必须占用唯一 Lead 槽（`spec.audio` 表 A20），其余社区以和声垫/代表承载。第63轮 `theme_slot_limit=1` 是合奏切片，不能据此宣称 ≥6 栋成熟社区的完整主题验收已完成。

### 11.3 "我的城市在唱我编的曲子"必须在中期成立

**验收**：玩家在第 8–15 分钟时应当能说出类似的话：
"我把我东边那片社区调成了 C–E–G，现在它唱的是这个。"

**做不到的话**，说明社区主题机制没成立，**需要重做社区主题，而不是把作者感节点提前写进文案**。
