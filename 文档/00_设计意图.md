# 共鸣之城：设计意图

> 2026-10-08。本文解释体验目标；实现细节只取自 `01_执行规格/`，判定只取自 `02_验收/`。先读根目录 `PROJECT.md` 与 `执行交接-P0.md`，确认当前状态。

1. 数值只能来自 `01_执行规格` 的表格，不得在代码中硬编码；规格没有的值 → 停下提问，不要自创。可将表格生成数据文件；不得另建私有默认值。
2. 每个任务必须附一条可运行的验收命令；没有验收的任务视为未定义，不得开工。未来测试入口必须先随任务实现，缺失或待裁定不能记为 PASS。
3. 不得引入规格未列出的新机制，即使它看起来显然更好。
4. 任何文档的大改：先复制为带日期的新工作稿，原件只读。
5. `manifest.json` 是程序选件的唯一事实源；不得通过扫描图片目录推断选件。
6. 一次只实现一个规格 ID；执行日志记录“规格 ID + 验收命令 + 输出路径”。

**定位：城市先响着，你负责听出哪里不对，然后作一次介入。失谐不是坏，未解决的失谐才是。** 玩家是调音师，循环是聆听 → solo/mute 定位 → 判断张力 → 试听代价 → 介入 → 再聆听。

城市与音乐结合已有先例，不能宣传为空白市场。Circuit City、Sound of Cities 偏建造与创作；Harmoni-us 已涉及冲突音景。我们要验证的差异是诊断、有限介入、延迟解决与明确取舍，尚未证明独占。竞品证据见 `事实核查-2026-10-08.md`。

- A 声音即信息：持续 drone 承载和声诊断，律动承载街区身份；视觉优先模式提供完整等价信息。
- B 规划即和声：失谐不是坏，未解决的失谐才是。选择何时解决与承担哪一处新张力。
- C 生长即作品：城市与音乐来自相同事件；City DNA 可复现形态和声音。
- D 每一局都未知：短局、祝福与图鉴驱动发现；不靠永久数值碾压。

反支柱：玩家不自由输入音符、不直接作曲；只能在系统允许的提案内诊断与介入。核心时间用于听和判断，避免工具栏浏览吞掉注意力。

画面采用固定视角的 2.5D 表达：平面城市、离线烘焙低模、全局换色、Y 排序。少量天空、云雾、粒子、光效与后处理可作为表现层，不能反过来决定城市运行时全 3D；具体表现预算未裁定。本轮只修文档，不生成游戏脚本或场景。
