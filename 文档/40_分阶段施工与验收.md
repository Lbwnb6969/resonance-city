## 5. M78：一个主题的完整音乐垂直样板

**目的：** 用一个原创主题证明“乐句、伴奏、连续基础层、安全切换、正式播放”成立，之后才复制到多风格。

**拟新增：** 乐谱事件/预设解析模块、音域规划模块、过渡渲染模块。保留原公开入口适配。

**施工子步：**

1. 定义score事件契约及语义role，保留layer1～4。建立一个8小节原创主题与A/B变体，含至少一个有依据的经过音和自然终止。
2. `note()`不再无条件对已规划音高fold；老调用可走兼容分支，新score需验证后保留MIDI。测试覆盖音域边缘、五声音阶、低音领唱和非法音。
3. 伴奏使用真实分解/转位和留白；允许刻意重复，不强制随机化。
4. 利用现有wrap渲染连续基础层，同时实现安全切换。先确定同一player过渡缓冲/复合流方案，测试相位、尾音、loop_begin/end和回到稳定目标的状态转换。
5. 移除“小节前0.12秒必然静音”的切换假设；一个样板贯通主声部、夜景候选及旧模式回退。不允许只在离线WAV里正确。
6. 新生成依赖纳入音库签名。烘焙默认样板和轻量库，确认实际播放器加载新stream，不被旧预编译资源覆盖。

**不在此步做：** 六风格、所有调式变体、全城市自动选曲、动态BPM或全音色重做。

**关键测试：**

- 3秒小节、24秒环和首播处分别检查分轨/混音包络；不是要求永远非零，而是区分编写休止与工程断缝。
- 当前调式、跨调式和同主题变体切换均无明显瞬态爆音/拍钟漂移；旧尾音不污染下一和声。
- 高旋律候选不会经旧fold掉八度；深音域profile不会被折回高音。
- `lead_count`与实际可听归属一致，4短槽/12长轨不增加，唯一领唱有效。
- 缓存失效和缺preset时安全使用默认；不会把null stream交给player。

**复用测试：** `test_city_creation_transparent_chamber.gd`、`test_city_creation_theme_pcm.gd`、`test_city_creation_smooth_variation.gd`、`test_city_creation_chamber_routing.gd`、`test_city_creation_portable_bank.gd`。旧固定拍点/固定音域断言要分类改成新契约，不降低正确性约束。

**验收：** 正常五屋城市实际播放；切换前后WAV、事件计划与签名一致；有效试听确认主要机械感减少；第一圈与后续两圈均无异常。没有实际听音能力时只报技术验收，听感项继续待验。

**回退：** 用开发配置切回旧事件生成器/匹配音库；保留新preset与缓存版本隔离，不在旧key下覆盖新资源。

## 13. M86：整合终验与交付

**必做旅程：**

## 15. 命令与证据模板

以下是已存在入口的命令示例，需在项目根目录执行。Godot命令名按本机实际可执行路径替换。新功能专用测试在对应里程碑创建，不假装当前已存在。

```text
python tools/check_ai_harness.py
python tools/check_doc_links.py
python -B tests/test_ai_harness.py

Godot --headless --path . --audio-driver Dummy --script tests/test_city_creation_legacy_roundtrip.gd -- --isolated-session
Godot --headless --path . --audio-driver Dummy --script tests/test_city_creation_transparent_chamber.gd -- --isolated-session

Godot --path . --rendering-method gl_compatibility --audio-driver Dummy --script tools/check_creation_reference_music_live.gd -- --isolated-session --out-dir=res://验证记录/整合音乐
```

Dummy驱动的实际PCM时长必须读取WAV确认，不能把墙钟请求150秒写成已经录到150秒。技术采集使用Dummy不代替人实际试听。

音库生成工具会修改资源与stamp，只在音频变更任务内运行，先读当时脚本参数与输出路径：

```text
Godot --headless --path . --script tools/bake_creation_music_bank.gd
Godot --headless --path . --script tools/bake_creation_portable_bank.gd
```

对照分析需本机原分析环境和真实reference summary；先运行已有analyze.py，再按实际目录传入：

```text
python tools/compare_creation_reference_music.py --reference-summary <真实summary.json> --evidence <真实证据目录> --profile-output <新的分析profile.json>
```

首轮不得覆盖仓库已有参考profile；使用新输出名比较前后。M80扩展多风格后，同步升级工具的数据契约和测试。

建议每任务记录：基线提交、当前提交、场景/种子、存档版本、viewport、渲染模式、采样率、音库签名、测试命令和退出码、原图/录音/报告路径、P1/P2/P3缺陷。运行成功不等于报告内容正确，实际错误日志和原图/WAV必须核对。
