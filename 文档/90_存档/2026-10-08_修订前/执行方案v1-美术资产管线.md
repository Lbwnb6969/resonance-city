# 《共鸣之城》执行方案 v1 — 美术资产管线与落地细节

> 工作稿 · 2026-10-08 · v0.1
> 配套主策划案 v3（游戏策划案v3-共鸣之城.md）。本稿回答：资产从哪来、AI 怎么加工、细节怎么做好。
> 本稿同时**修订 v3 的一个决定**：渲染路线由"真 3D 低模"改为"2D 矢量 + 2.5D 分层渲染"，理由见第 1 章。

---

## 1. 渲染路线定案：2D 扁平矢量 + 2.5D 分层（修订 v3）

### 1.1 为什么改

v3 写"真 3D 低多边形"时还不知道一个关键事实：**用户已购的三套素材全部是 EPS 矢量插画**（744 个 EPS + 预览 JPG，含散件单体）。这改变了成本方程：

| 考量 | 真 3D 低模 | 2D 矢量（选定） |
|---|---|---|
| 已购素材能否用 | 不能（需另购/另做） | **直接可用** |
| AI 自动加工深度 | 需 Blender 脚本，门槛高 | **SVG 就是 XML，AI 直接读写改色拆件** |
| 昼夜/季节/谐振度变色 | 要打光系统 | **换色板即可（扁平纯色天生适配）** |
| 与"动画电影感"的契合 | 需精细 shader | 扁平插画本身就是这个味 |
| 90° 旋转 | 免费 | 做不了（需 4 套图）→ **放弃旋转** |
| 单件成本 | 高 | 极低 |

### 1.2 定案规格

- **视角**：固定等距（2:1 或真等距，以素材视角为准，见第 4 章盘点），可平移/缩放，**不可旋转**。v3 中"90° 步进旋转吸附节拍"的设定作废；镜头表现欲改由"缩放推近 + 贴地聆听镜头（后期）"承担。
- **渲染**：Godot 2D，`Sprite2D` + `YSort` 节点树分层；地面 → 道路 → 建筑 → 植被 → 车辆/行人 → 天气/粒子。
- **伪立体**：建筑拆"立面/侧面/屋顶"三层绘制，按 Y 排序自然遮挡；投影用统一规则的软阴影贴层，不打真光。
- **昼夜**：不做光照，做**调色板切换**——所有入库颜色登记在全局色板表，昼夜/季节 = 换一张色板 + 窗户自发光层点亮。这套系统同时服务"谐振度驱动饱和度"（支柱 C 的联觉一致性），一次投入三处复用。

### 1.3 对参考对话（AI 建议）的采信与修正

| AI 建议 | 处理 | 理由 |
|---|---|---|
| 2D sprite + YSort + 模块化零件 | **采信** | 与本定案一致，且符合已购素材形态 |
| 不让 AI 生成整张城市，只生产"词汇" | **采信** | 正确，这是程序生成的基本法 |
| Scenario 训练风格模型批量产图 | **暂缓** | 先榨干 744 个已购件 + CC0；真的出现风格缺口再订阅，不先花钱 |
| Meshy（Text→3D） | **不采用** | 路线已定为 2D，3D 生成用不上 |
| Blender | **不采用** | 无 3D 资产即无 Blender 需求；矢量加工用 Inkscape CLI |
| Krita + AI Diffusion | **降级为可选** | 人工修图场景才用；AI 自动化主力是 Inkscape CLI + ImageMagick + 直接改 SVG 源码 |

**三个前置动作（第一批任务）：**
1. **授权核对**：查购买平台的商用授权条款（能否用于游戏成品、能否修改后商用、是否需署名）。结果记入 `资产/授权登记.md`。**这是红线，不确定的素材不进库。**
2. **全量盘点**：744 个 EPS 全部批量转 PNG 预览图（见第 3 章管线），生成索引表（文件名/分类/视角/主色/可用性评级）。
3. **风格筛选**：三套素材画风必有差异，按第 5 章美术圣经打分，**不合风格的不要硬用**——改色能救的改色，救不了的淘汰或只作参考。

## 3. AI 可自动执行的矢量加工管线（核心交付物）

这是给执行 AI 的标准作业流程（SOP），全部可脚本化，无人工美术依赖。

### 3.1 工具链

| 工具 | 用途 | 调用方式 |
|---|---|---|
| **Inkscape**（免费开源） | EPS→SVG→PNG 转换、矢量编辑 | 命令行批处理：`inkscape input.eps --export-type=svg` / `--export-type=png --export-width=2048` |
| **SVG 源码直改** | 换色/删件/重组 | SVG 即 XML，AI 用文本工具直接改 `<path fill="#...">`，无需打开任何 GUI |
| **ImageMagick** | PNG 裁切、拼合、加阴影、生成预览 | 命令行批处理 |
| Krita（可选） | 极少数需要手绘修补的场合 | 人工 |

### 3.2 五步加工法

```
① 转换    EPS → SVG（Inkscape CLI 批量）
② 体检    AI 读 SVG：提取全部颜色值、元素数量、包围盒
          → 产出"体检报告"（主色列表/复杂度/是否含栅格图）
③ 收编    按色板映射表批量替换颜色（见第 5 章）
          不在色板上的颜色一律映射到最近色板色 → 风格统一的根
④ 拆解    按模块标准切成零件层（底座/墙身/屋顶/门窗/装饰）
          输出：每层一个 PNG + 一份 manifest.json
⑤ 入库    按命名规范放入资产库，登记索引
```

### 3.3 模块拆解标准（程序组合的"词汇表"）

每栋建筑入库形态：

```
building_res_01/
├── base.png          # 底座/首层（原点：底部中心）
├── body.png          # 墙身
├── roof.png          # 屋顶
├── windows.png       # 窗（夜间自发光层共用此 alpha）
├── door.png
├── deco.png          # 阳台/招牌/空调等（可空）
├── shadow.png        # 软阴影（统一规则生成，不手画）
└── manifest.json     # {类别, 占地tile, 层高, 声部标签, 色板槽位, 来源, 许可}
```

- **拼接基准**：地面 tile = 256×128px（2:1 等距），1 层高 = 64px，所有零件原点 = 底部中心。
- **manifest.json 是灵魂**：程序生成器只读 manifest 选件拼楼；`声部标签` 直接挂接主策划案的声部签名系统（工业件打 industrial 标签，生成器按街区声部选件——**美术词汇与音乐规则在同一张表上**）。

### 3.4 质量红线

- 入库 PNG 分辨率 ≥ 2048px 长边（高清屏缩放余量），Godot 内按需 mipmaps。
- 透明度边缘无白边（导出后 ImageMagick 检查 1px 晕边）。
- 每件入库必须过"三格测试"：与任意两件同库资产并排放置，观感像同一个游戏。

## 4. 细节打磨清单（"要做好"的部分）

### 4.1 昼夜系统（2D 方案）

- 全局色板 ×4 时段（晨/昼/昏/夜）×4 季节，共 16 张色板表，驱动所有 `CanvasItem.modulate` 分组。
- 夜间氛围三件套：窗户层自发光（用 windows.png 的 alpha 叠 additive）、路灯锥形光斑贴图、整体色板转冷。
- 切换不做渐变动画跳变，**在小节边界随音乐一起呼吸式过渡**（呼应主案铁律）。

### 4.2 生长动画（城市"长出来"的瞬间是核心爽点）

- 建筑生成 = 底部向上 mask 揭示 + 轻微 squash & stretch（1.05→0.95→1.0），时长精确 = 1 拍。
- 生长瞬间触发对应声部的入场音——**视听在节拍上同时落位**，这是"长出来很爽"的物理原因。
- 街区升级 = 旧件下沉淡出、新件升起，禁止瞬移替换。

### 4.3 生命感（低成本高回报）

- 行人/车辆：单方向循环小动画（4-8 帧即可），沿道路 spline 移动；密度绑定街区活力 V。
- 微动效：旗帜飘、烟囱冒烟（工业声部的视觉节拍器）、树摆——全部循环节奏锁 BPM 的整数分频，**让整座城市在视觉上也在打拍子**。
- 天气：雨=全屏粒子+高频声部加"沙沙"噪声层；雪=色板高明度化+高频低通。

### 4.4 听诊视图（标志性奇观）

- 一键切换：建筑 sprite 淡出，替换为按街区声部实时起伏的波形/频谱柱体（Line2D/Polygon2D 程序化绘制，数据源 `AudioEffectSpectrumAnalyzer`）。
- 等距 2D 下做"波形天际线"：沿每排建筑的 Y 序绘制发光波形脊线，错位叠加即成山脉感——比 3D 方案实现更简单，效果不打折。

### 4.5 稀有形态演出

- 命名形态触发：镜头缓推 + 四周暗角 + 全城窗户层按和弦顺序逐片点亮 + 形态名手写体浮现。全部用现有 2D 系统可实现，无需特殊资产。

## 5. 美术圣经（给所有资产加工的硬约束）

> 初版参数，P0 盘点已购素材后按主力素材微调数值。

- **色板**：全局 ≤ 24 色。基调：暖灰白墙体（#F2EDE4 级）、陶土屋顶（#D96B4F 级）、灰蓝工业（#6B7B8C 级）、叶绿（#7FB069 级）、暖黄窗光（#FFD98A 级）。色板表是唯一色彩事实源。
- **描边**：不用黑描边；用同色系深 20% 的色线，1.5px @1024 基准。
- **阴影**：单方向（右上光源）、纯色 25% 透明、无渐变、无多层。
- **比例**：夸张化——门/窗比真实大 15%，树高度 ≤ 2 层，车辆圆胖化。
- **禁止**：照片纹理、复杂渐变、写实高光、黑纯 #000 与纯白 #FFF 直接出现在资产上。
- **AI 加工时**：凡不在色板上的颜色 → 映射最近色板色；凡违反阴影规则的 → 删原阴影重生成标准阴影层。
