# 音乐与成长系统施工手册

本手册将[54产品规格](54_V7_最终施工改造总案.md)与[69采用取舍](69_成长动力与开放音源制作路线.md)转成工作单和交付规则，不新增平行总纲。当前做到哪里、下一步做什么，唯一查[PROJECT](../PROJECT.md)与backlog；本页的阶段名称不是额外里程碑，不改变M75～M86编号与验收状态。

## 1. 开工与交付的顺序

先读根入口、PROJECT、AGENTS；再读本次任务对应的本手册章节与69。按需查源码/专题，禁止把全部历史原稿当本轮任务。先核Git状态及当前文件：其他会话的修改不覆盖、不混入提交；原件与失败版本留档。当前暂停上传，仍本地提交备份。

选择当前未完成的一项可验证产物，完成后记录命令、结果、时间和剩余问题。资料足够时自主完成制作，不以“需要听评”为由停在计划或工具安装；先导出可听版本供用户评价。等待听评期间继续整理来源、检查组合与技术问题，但不将听评状态改为通过。

| 状态 | 必须已经存在的证据 | 不代表什么 |
| --- | --- | --- |
| 材料可用 | 原件、许可、hash、样本映射、实际工具加载 | 音色适合、本作原创音乐已完成 |
| 技术可播 | 指定输入成功渲染、可解码、时长/声道/峰值实测 | 编曲好听、所有音高/演奏法都正常 |
| 作品待评 | 完整可听音频、原谱/工程、制作说明与对照 | 用户已经认可 |
| 作品认可 | 绑定音频hash的实际用户听评，问题已回应 | 游戏内混音/循环/交互也已认可 |
| 场景可用 | 真实隔离场景、输入与混音录音、切换/循环/回退证据 | 整体M84/M85/M86已通过 |

## 2. 第一首音乐：实际工作单

### 2.1 定义一首作品，而不是先定义全组合系统

用途是自由造城时可长听的温暖室内乐/新古典背景。按专题B的2.3，空地、孤屋和简单城以少量稀疏织体、和声呼吸与留白为默认，大多数普通营造时段不突出主旋律；完整作品不要求独奏主题，声部容量不是同时发声目标。现有core内含主奏时不能靠降低颜色层去除，不自动选作简单城默认；旧尖薄合成曲退出正式默认和自动回退。用户只生成完整新曲，不能上传旧曲修改；以下MIDI/采样/分轨操作由工程端承担，不要求用户提供可编辑工程。近距离有真实乐器触感，远景能退到背景；主奏退出时伴奏仍成立，展开时不靠整体增响制造情绪。先选一首用户参考中最接近目标的作品作为主要对照，说明取其何种质感/句法/空间，不能泛称“像Tiny Glade”。没有可访问录音就写缺少听觉证据，先基于已收到反馈制作独立候选，不假称听过。

制作前在[音乐交付单](施工模板/音乐制作交付单.md)填：场景、核心感受、主参考路径/hash及选定片段、主要动机、曲式草图、角色与乐器、一次重点验证的问题。基准曲应有完整呈示、发展/呼吸和收束；长度按完整表达决定，首轮可从约2～3分钟工作规模起步，不强制旧144秒/80BPM/四轨模板。

首轮可以用钢琴、疏朗拨弦和一层弦乐支撑起步，不因下载了35个SFZ就全用。每加一件乐器，说明它填补什么音乐作用、何时退出；每段保留清楚的主次与安静窗口，不将每拍填满。复用动机时改变句法、音区、和声背景或配器要有听觉目的；复制八小节不等于发展，随机改音也不等于变奏。

### 2.2 真实音源选择与表达

外置库根目录以[开放音源目录](../数据/音乐制作/开放音源目录.json)的`local_root`为准，文件不存在先修路径或材料，不悄悄退回正弦音色冒充采样。目录中的以下路径相对该根目录：

| 角色候选 | 已实际渲染的SFZ | 本轮仍要检查 |
| --- | --- | --- |
| 钢琴主体 | `音源/SalamanderGrandPiano/Salamander Grand Piano V3.sfz` | 作品实际音区、软/中力度层、踏板/释放及高音穿透；不是毛毡琴 |
| 弦乐支撑 | `音源/VSCO-2-CE/CelloEnsSusVib.sfz` | 弓头、长音接续、重复触发和真实呼吸；这是大提琴组，不是独奏连奏库 |
| 木管候选 | `音源/VSCO-2-CE/FluteSusNV.sfz` | 起音、句尾、实际音区及与钢琴争抢，不能用低通替代配器判断 |
| 拨弦/交互音 | `音源/VCSL/Chordophones/Composite Chordophones/Folk Harp.sfz` | 音高范围、攻击瞬态、连弹密度、尾音叠积 |
| 轻打击点缀 | `音源/VCSL/Idiophones/Struck Idiophones/Marimba.sfz` | 中低音木质感与高音突出度，不默认所有力度都柔和 |

其他已下载SFZ可以选，但先做相应短句验证。新增FreePats钢琴/吉他等候选先看目录状态，未下载不写已可用。源库不可直接改写，修改SFZ或切片另建派生批次并保留来源/差异。

MIDI保留可编辑音符、速度图、力度与控制器。力度用于音色与句法，不只是最终音量；CC1/CC11/踏板只有在该SFZ实际支持并受测时才使用。长音按乐器设计连断，不把多次重触发假装连奏；微时值依据重拍、呼吸和声部关系，不在全谱撒均匀随机抖动。滤波、混响、压缩按问题使用，不规定“2.8kHz一刀切”或全乐器共用一条修复曲线。

### 2.3 制作目录与可复现命令

在外置资产`音乐/制作批次/<唯一曲目ID>/<版本>/`新建批次，不覆盖任何已有目录。建议职责布局（工程格式自主）：

```text
brief.md                 复制并填写音乐交付单
source/                  MIDI、速度图、DAW工程或可重跑脚本
renders/                 每声部原始渲染、日志与报告
mix/                     完整曲母版、受控对照、处理参数
stems/                   完整作品认可后才制作的同源分轨
evidence/                技术测量、实际听评与问题修改记录
asset_manifest.json      来源/许可/输入输出hash与真实格式
```

从项目根目录执行（PowerShell，变量路径换成本批实际路径）：

```powershell
$musicBank = 'C:/Users/Administrator/Desktop/mIDDLEFILE/资产/音乐/开放音源_20261101'
$musicMidi = '本批source目录中的原创MIDI绝对路径'
$musicRender = '本批renders下尚不存在的输出目录'
python -X utf8 tools/render_open_sample_midi.py --renderer "$musicBank/制作工具/sfizz-1.2.3-win64/bin/Release/sfizz_render.exe" --sfz "$musicBank/音源/SalamanderGrandPiano/Salamander Grand Piano V3.sfz" --midi "$musicMidi" --out-dir "$musicRender"
```

该命令已实际跑通sfizz1.2.3，输出`render.wav`、`report.json`、`renderer.log`；默认48kHz、PCM16立体声。`--use-eot`是截尾短探针选项，不用来制作正式尾音。工具报告只检查本次输出，不核完整SFZ支持、混音或艺术质量。更高位深工作母版另核导出工具；后续处理用足够精度避免反复量化，不能给PCM16转成float就宣称恢复了录音精度。

sfizz这一调用只装载一个SFZ。多乐器作品分别导出对应MIDI/声部，保留共同起点与速度图，再统一混合；不要把完整多乐器MIDI灌进一个钢琴SFZ就称完整配器。脚本可补齐同步尾部静音，但不能裁断乐器释放。原始探针文件不是可直接挪作本作原创音乐的完成稿。

### 2.4 混音与故障定位

先在没有旧游戏增益补偿/短音干扰的离线环境听完整曲，再进入场景。出现问题时保存对照，优先定位最小原因：

| 听到的问题 | 首先比较 | 不作为自动答案 |
| --- | --- | --- |
| 尖、抢耳 | 独奏与混合、实际音区/力度、瞬态、主伴关系、场景整体音量 | 一律切高频、所有轨一起变小 |
| 薄、空 | 去主奏后的伴奏、音区覆盖、持续/释放、配器空缺 | 无限加长音、加厚混响 |
| 机械、重复疲劳 | 句子方向、强弱拍、动机发展、呼吸/速度图、重复触发 | 全谱随机微时值或更换调式 |
| 混浊/抽吸 | 低频与尾音叠积、压缩、整曲/分轨响度与运行增益 | 把每轨归一化到同峰值 |
| 切换破坏乐句 | 速度图、样本起点、相位/尾音、入口/出口和调度 | 只找零交叉点或加长淡化 |

一次比较只改变能解释结果的少量因素。统一增益会改变整体响度，不能凭公式直接归因“主奏相对越压越响”；要记录实际前后混音。烧录混响与运行总线混响只选有明确分工的方案。主奏休止保留安静，不按声部减少自动把剩余部分顶满响度。

### 2.5 听评是作品验收，不是最后补一句“待评”

交付实际可播放完整曲，另提供有定位作用的片段：代表主题、主奏离场、展开、收尾/循环。时长按乐句选，不把三份60秒片段当完整长听的替代。对照版本匹配感知响度，记录采用的测量方法与增益，保留原始母版；同峰值不等于等响度，不把某个LUFS数当艺术标准。

用户听评记录必须绑定文件hash、时间、具体片段和原话：是否愿意继续听、哪里抢注意力、伴奏是否自足、循环是否疲劳、是否符合城市场景。AI可以记录自己的分析，但不能代替用户认可或伪造盲听。持续修改后hash已变，旧认可不能自动继承；局部改动可只复核受影响部分及必要整曲关系。

不满意时优先修改作品/表达/音源，再做受控比较；不要用增加玩法或换十个调式掩盖作品问题。完成的定义是有可播放、可复现、实际评价过的作品，而非一份宣称“商业级”的设计文字。

## 3. 从完整曲到城市音乐系统

只在完整曲达到目标后增加自适应。先导出固定混音作为回退，然后从相同制作工程导出少量同源分轨，明确每轨角色、允许的最少/最多组合、乐句边界与共同速度图。禁止独立归一化；分轨相加应与认可的参考混音对照，无法一致须解释总线处理或母带差异。

Lyria 3.5 候选使用独立 `lyria_stem_bundle_v1` 容器；字段、帧对齐、分轨拒收和运行时首批范围按[Lyria35 同源分轨施工方案](音乐制作批次/Lyria35_同源分轨与Godot接入施工方案_v1.md)和[首批候选](../数据/音乐制作/Lyria35_首批同源分轨候选_v1.json)执行。用户已确认输入全部为纯音乐并授权目录内整批自动器乐分轨：直接用六轨／木管专门模型及剩余器乐细分，不运行人声筛查前置，先逐轨比较再分配 `lead/bed`。命令及完整记录见[整批分轨交付](音乐制作批次/Lyria35_纯音乐整批分轨交付_20261102.md)；保留 `full_mix`，听评通过后再做运行时接入。

第一次空间样板只选一个有实际来源的连续变化，如围合暖度控制支撑声部；参数由听感决定，不机械沿用4～6秒或-6dB。曲尾/乐句切换与分层混音分别验，不能混为一条“淡入淡出”规则。使用真实空间变化而非经营等级解锁基础音乐。

接入前明确新资源容器、真实声道/采样率、帧数/loop点、轨道起点、缓存签名与内存、同步运输、失效任务丢弃和缺失文件回退。不能把旧单声道`bytes/2`假设套到立体声，不能将旧8小节校验器放宽成任意媒体接口。旧M80/schema1与v2/v3开发接口保持各自含义。

最低场景覆盖：静置与连续编辑、镜头进出、暂停/静听/静音、主奏休止、整曲循环、来源删除/Undo、换城与在途渲染作废。记录真正Master录音和实际时长；CPU/Dummy输出不能替代实窗混音。自然Foley与音乐短音做同场景对照后取舍，源码有触发模块不证明实际每拍都发声。

如果有限分轨比固定混音更差，保留固定混音并回到配器/同步/参数修复；不用删全部历史能力来证明新路线。整曲与系统分别验收后才允许切默认，M84整体仍按原范围验。

## 4. 成长与生活系统：先交一个完整样板

### 4.1 玩家价值与内容盘点

先用[成长交付单](施工模板/成长样板交付单.md)描述玩家的具体念头、操作和获得后的新玩法；不能只写“增加留存”“获得成就感”。区分题签（灵感）、奖励（新增能力/表达）、生活事件（变化）和收藏（作品接续）。一项样板不必同时新增四套系统。

首项新奖励优先适用面广、正常视角可辨、可用于继续创作的美学变体；具体题材由施工盘点现有内容后选。先做可观看的小样与真实支撑位置，证明它不是已免费内容改名、不是只在极窄几何里出现的一个开关。未有可用内容就先生产内容，不先画Lv.3～Lv.20奖励表。

先展示奖励与适用条件，再让玩家自选追求；题签能忽略、更换，不偷偷改建筑用途/道路/颜色。无水山城、稀疏小院等应能沿自身创作方向成长；不把某种店铺/顾客作为唯一入口。现有成长点值与阈值先沿用，真实样板节奏完成后再调，避免同时改变内容与计分而无法判断原因。

### 4.2 实现前明确四种状态

| 状态 | 权威来源 | 展示/编辑语义 |
| --- | --- | --- |
| 已得资格 | 版本化真实账期/已领取记录 | 不随拆屋、切显示开关或暂停经济丢失 |
| 作者选择 | 独立可撤销偏好/明确选项 | 玩家决定是否启用，Undo按编辑事务处理 |
| 当前可表现 | 实际几何、道路/水岸/净空及支持范围 | 无支撑时待用，不补假建筑/库存；恢复支撑后确定性重建 |
| 临时表演 | 独立运行状态或显式持久事件记录 | 不能冒充获得资格，不回写永久数据来伪造完成 |

已有等级2桥灯/紫藤是资格和表现分离的例子，不等于新题签、全局收藏或筹备系统已存在。新的领取名额如果可累计/花费，就必须定义账本；不能借“不是货币”逃避幂等、保存与跨城语义。

### 4.3 最低充分系统验证

先定一次真实事件的身份与消费位置，再接UI。对样板逐项选择相关用例：

- 新账期正常获得一次；重复轮询/保存/冷读不重发；撤销与重新创建新ID不能混淆为同一事件。
- 暂停不累计，恢复同账期，已得内容可用；旧账、旧邀请、credits及growth_cutoff不混入新账。
- 作者关闭、全局装饰关闭、无适用几何/净空不足的实际效果；新资格不偷偷覆盖旧作者意图。
- 保存/发布失败原状态和原件保持；预览/打开历史作品不写新权益；跨城只按明确范围生效。
- 一次真实原生UI流程，观察奖励是否可发现、看得见、想继续使用，附画面与事实记录；API通过不能冒充玩家完成体验。

三项及最终按工程约定做独立Critic；审阅不能代替引擎输入或玩家体验。沿小模块实现，只在所需职责处分派；本手册不强制库、架构和测试顺序。

### 4.4 经济循环与长期目标

满仓休息先作为实际状态观察，不自动新增资源销毁器。节庆试作先证明玩家愿意布置/观看/拍照，以及与普通日常有明确差异。决定消耗后，必须有真实库存来源、预留/送达/完成/取消语义；不得凭库存数直接补造送装/茶聚receipt。取消/断路/暂停不罚玩家，具体恢复策略和物资去向仍须明确。

记录体验中的建造、观察和等待；不以产量最大化作为目标。发现刷屋/挂产/点按钮收菜更有效时，先检查奖励吸引力、目标条件和事件来源，再校准数值。有限奖励耗尽后的继续创作/收藏必须有真实内容承接，不能用无限重复题签声称无限可玩。

## 5. 批次收尾与交接

复制模板到本批真实目录并填完；不存在的产物写未完成，不创建空文件伪装完成。将产物路径、hash、实际验证、用户反馈和最小下一步写入PROJECT/backlog；日志每轮≤6行。文档轮只跑链接/Harness及本次资料一致性检查，不重跑游戏或全部历史候选脚本。

失败版本保留，原件及旧存档不删除。大型音频/采样留外置资产，仓库保存元数据、制作脚本、许可和经审定的发行资源。当前只本地Git备份；恢复上传时才执行37。检查完成不自动改runtime_ready/pass，只有其对应范围真实完成才更新。
