# 生成管线与数据

## 1. 统一流程

```text
玩家意图
  → 连续空间命中 / 房屋局部格命中
  → 合法性与连接候选
  → 可撤销预览
  → 玩家确认
  → 稳定操作记录
  → 分层程序生成
  → 分片提交几何、材质、声音反馈
```

## 2. 分层职责

| 层 | 读取 | 写入 |
|---|---|---|
| Intent | 鼠标/手柄、选中的房屋或区域 | `intent_id`、类型、路径/轮廓、参数 |
| Space | 地形、道路、房屋占地、局部网格 | 连接候选、冲突、预览几何 |
| Generator | 固定种子、模块库、邻接标签 | 墙/路/植被/公共建筑实例 |
| Presentation | 已提交实例、可听区域 | 网格、LOD、阴影、音频事件 |
| Save | Intent、稳定 ID、种子、版本 | 城市作品文件 |

渲染缓存、后台线程句柄、临时预览和音频播放器都不进入存档。局部格子坐标只写入房屋生成结果的版本化参数，不写成全局占用表。

## 3. 房屋局部生成器

使用带旋转和轻微扰动的不规则四边形格。每个格边带有 `wall/door/terrace/roof/open` 标签；相邻标签不兼容时拒绝该候选或回退为空边。生成顺序固定为：边界 → 结构 → 开口 → 屋顶/露台 → 装饰。随机只用于同权重候选，种子来自 `intent_id`，撤销和重做得到同一结果。

## 4. 连续城市生成器

道路使用样条采样和连接图；功能区使用距离场/权重场；植被使用分块 Poisson 或蓝噪声散布；特殊建筑使用占地轮廓和入口约束。所有系统共享一套空间查询，避免道路、植被和建筑各自维护冲突真值。

## 5. 版本与失败处理

每次确认递增城市版本。后台结果必须携带输入版本，版本过期就丢弃并重新预览；不能把迟到结果覆盖新操作。写档采用临时文件、校验、替换和保留上一份有效档。旧版本缺字段时使用空默认值，未知版本拒绝覆盖原档。
